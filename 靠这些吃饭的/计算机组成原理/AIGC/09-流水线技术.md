# 09-流水线技术

```知识地图
为什么需要流水线？→ 指令的串行执行 vs 并行执行
    ↓
五级流水线：IF → ID → EX → MEM → WB
    ↓
流水线冒险（三类）
    ├── 结构冒险：硬件资源冲突
    ├── 数据冒险：指令间数据依赖 → 旁路技术(Forwarding)
    └── 控制冒险：分支跳转 → 分支预测
    ↓
性能分析：吞吐率、加速比、流水线深度
    ↓
现代流水线技术：超标量、乱序执行
```

**本讲回答的核心问题**：流水线如何让CPU同时执行多条指令？流水线中会遇到哪些"冒险"问题？如何解决这些问题让流水线顺畅运行？

## 1. 从串行到流水线

### 1.1. 串行执行的问题

如果不采用流水线，每条指令必须完全执行完后才能开始下一条：

```
指令1:  ┌────取指────┬──译码──┬──执行──┬──访存──┬──写回──┐
指令2:                                          ┌────取指────┬──译码──┬── ...
```

> **问题**：取指时ALU闲着，执行时存储器闲着——每个时钟周期只有1/5的硬件在工作，利用率极低。

### 1.2. 流水线的思想

流水线（pipelining）的核心思想：**将一条指令的执行过程分成若干个阶段，每个阶段由独立的硬件完成。当一条指令完成一个阶段后，下一个阶段硬件立刻开始处理下一条指令。**

> **通俗理解**：就像汽车装配线。如果一辆车完全造好才开始下一辆——效率极低。流水线上，每个工位只做一件事（装轮胎、装车门……），不同工位同时处理不同的车。虽然一辆车的制造时间没有缩短，但**每秒钟产出的车辆数（吞吐量）大幅提高了**。

### 1.3. 流水线 vs 串行对比

```
串行（无流水线）：
指令1:  │取指│译码│执行│访存│写回│
指令2:                         │取指│译码│执行│访存│写回│
                                   ↑ 每5个时钟周期完成1条指令

流水线（5级理想状态）：
         时钟:  1  2  3  4  5  6  7  8  9
指令1:        │取指│译码│执行│访存│写回│
指令2:             │取指│译码│执行│访存│写回│
指令3:                  │取指│译码│执行│访存│写回│
指令4:                       │取指│译码│执行│访存│写回│
                                   ↑ 每1个时钟周期完成1条指令！
```

**关键结论**：
- 一条指令的**延迟**（latency）没有减少（仍是5个时钟周期）
- 但**吞吐量**（throughput）提高了5倍（从5周期/条→1周期/条）
- 流水线的本质是**用硬件资源换吞吐率**

## 2. 五级流水线的每个阶段

### 2.1. 各阶段功能

| 阶段 | 英文 | 缩写 | 功能 | 使用的硬件 |
|:----|:-----|:---:|:-----|:----------|
| **取指** | Instruction Fetch | IF | 从指令Cache/主存中取出指令，PC值自增 | PC、指令Cache、IMEM |
| **译码** | Instruction Decode | ID | 对指令译码，读取寄存器中的操作数 | 译码器、寄存器组 |
| **执行** | Execute | EX | ALU执行运算或计算地址 | ALU、加法器 |
| **访存** | Memory Access | MEM | 读写数据Cache/主存（仅LOAD/STORE指令） | 数据Cache、DMEM |
| **写回** | Write Back | WB | 将运算结果写回到寄存器 | 寄存器组 |

### 2.2. 每条指令经过的流水线阶段

不同指令不一定会使用所有阶段（例如寄存器操作指令不需要访存，但为保持流水线节奏仍需经过该阶段——该阶段为空操作）：

| 指令类型 | 例子 | IF | ID | EX | MEM | WB |
|:--------|:----|:--:|:--:|:--:|:---:|:--:|
| **ALU寄存器指令** | ADD R1, R2, R3 | ✓ | ✓ | ✓ | 空 | ✓ |
| **LOAD指令** | LW R1, 0(R2) | ✓ | ✓ | ✓ | ✓ | ✓ |
| **STORE指令** | SW R1, 0(R2) | ✓ | ✓ | ✓ | ✓ | 空 |
| **分支指令** | BEQZ R1, label | ✓ | ✓ | ✓ | — | — |

## 3. 流水线冒险

流水线在理想情况下每周期完成一条指令，但实际中会遇到三类"冒险"（hazard）——即阻碍下一条指令在预定时钟周期内执行的情况。

### 3.1. 结构冒险（Structural Hazard）

**定义**：多条指令在同一时钟周期争用同一个硬件资源。

**例子**：如果指令Cache和数据Cache是同一个存储器，LOAD指令在MEM阶段访问存储器时，下一条指令的IF阶段也要访问存储器——冲突了。

**解决方式**：

| 方式 | 说明 |
|:----|:------|
| **分离Cache** | 将指令Cache和数据Cache分开（哈佛结构）——**最常用** |
| **插入气泡**（stall） | 让流水线暂停一个时钟周期 |
| **增加资源** | 如多端口寄存器组解决寄存器读写冲突 |

> 现代处理器内部将L1 Cache分为L1i（指令）和L1d（数据），从硬件上解决了取指和访存的结构冲突。

### 3.2. 数据冒险（Data Hazard）

**定义**：指令之间存在数据依赖关系——下一条指令需要使用上一条指令的计算结果，但结果还没有写回寄存器。

**经典例子**：
```
ADD R1, R2, R3    ; R1 = R2 + R3（结果要在WB阶段才写入R1）
SUB R4, R1, R5    ; R4 = R1 - R5（ID阶段要读R1，但此时R1还没更新）
```

**三种数据相关**：

| 类型 | 含义 | 例子 |
|:----|:-----|:-----|
| **RAW**（Read After Write） | 先写后读——**真正的数据依赖** | ADD R1→SUB R1 |
| **WAR**（Write After Read） | 先读后写——**反依赖** | SUB R1→ADD R1（通常不出现于顺序流水线） |
| **WAW**（Write After Write） | 先写后写——**输出依赖** | ADD R1→ADD R1（目标寄存器相同） |

**解决方法**：

#### (1). 插入气泡（软件方式——由编译器插入NOP指令）

在ADD和SUB之间插入NOP（空操作）指令，等待ADD的结果写回：

```
ADD R1, R2, R3
NOP                   ; 等待1个时钟周期
NOP                   ; 再等1个时钟周期
SUB R4, R1, R5        ; 此时R1已经更新
```

**缺点**：浪费了2个时钟周期，降低性能。

#### (2). 旁路技术（Forwarding/Bypassing，硬件方式）

**核心思想**：结果一旦在EX阶段计算出来，不等到WB阶段写回寄存器，而是直接通过一条"旁路"送到下一条指令的EX阶段输入。

**工作原理**：
```
ADD R1, R2, R3    ; EX阶段结束时R1的结果已经算好了
    ↓（旁路：结果直接送到EX阶段的输入）
SUB R4, R1, R5    ; EX阶段直接使用旁路过来的R1值
```

> **通俗理解**：旁路技术就像在厨房和餐桌之间开了一个"快速通道"——菜（计算结果）刚做好（EX阶段完成），不等端到餐厅（写回寄存器），直接通过快速通道送到下一个需要它的厨师手上。

#### (3). 流水线互锁（Pipeline Interlock）

当旁路无法完全消除数据冒险时（如LOAD指令的MEM阶段才得到数据，紧邻的下一条指令在EX阶段就需要该数据），硬件自动插入气泡：

```
LW R1, 0(R2)      ; R1在MEM阶段才得到数据
NOP               ; 硬件自动插入1个气泡（stall）
ADD R4, R1, R5    ; 通过旁路从MEM→EX直接取R1
```

**三种方法对比**：

| 方法 | 实现方式 | 性能影响 | 复杂度 |
|:----|:--------|:--------|:------|
| 插入气泡（软件） | 编译器插入NOP | 最大 | 最低 |
| **旁路技术** | 硬件增加转发路径 | **最小（可消除大部分冒险）** | 中等 |
| 流水线互锁 | 硬件检测+自动插入 | 仅LOAD-USE需要 | 较高 |

### 3.3. 控制冒险（Control Hazard）

**定义**：分支指令（如BEQ、JMP）改变了指令的执行顺序，而流水线在取指阶段还不知道是否要跳转——取出的下一条指令可能是错的。

**问题本质**：分支指令需要到EX（甚至MEM）阶段才能知道跳转是否发生、目标地址是什么，但下一条指令在IF阶段已经取进来了。

**解决方法**：

#### (1). 分支预测（Branch Prediction）

**静态预测**：
- **永远预测不跳转**：最简单，取PC+4顺序执行。预测错了再清空流水线。
- **预测跳转**：假设分支总是跳转

**动态预测**：根据历史执行情况来预测

| 预测方式 | 说明 | 正确率 |
|:--------|:-----|:------|
| **1位预测器** | 上次跳转→预测跳转；上次不跳→预测不跳 | ~80% |
| **2位饱和计数器** | 需连续错2次才改变预测方向 | ~93% |
| **BTB**（分支目标缓冲器） | 缓存分支指令地址和跳转目标，提前预测 | ~95%+ |
| **混合预测器** | 结合多种预测器，选择最可信的 | ~97%+ |

> **通俗理解**：1位预测器像"上次裁了跟头就换条路"——容易反复无常。2位饱和计数器像"要连续吃两次亏才换路"——更稳定。BTB则像"记住每个路口的标志"——看到熟悉的路口直接知道往哪转。

#### (2). 分支延迟槽（Branch Delay Slot）

在分支指令后插入一条**一定会执行**的指令（无论跳转与否都先执行它），让流水线在等待分支结果期间不至于空闲。

#### (3). 清空流水线（Flush）

预测错误时，将流水线中已经取出的错误指令作废（清除），从正确的目标地址重新开始取指。典型损失：2~3个时钟周期。

> **控制冒险的代价**：在五级流水线上，每次分支预测错误需要清空流水线，损失约2~3个周期。如果预测正确率95%，平均每20条分支指令才错1次，损失不大。但如果没有分支预测（每次分支都等结果才取下一指令），每条分支指令都要损失2~3个周期，性能大幅下降。

## 4. 流水线性能分析

### 4.1. 基本公式

流水线的**吞吐率**（throughput）是衡量流水线性能的指标：

$$
\text{IPC} = \frac{\text{指令总数}}{\text{总时钟周期数}}
$$

**理想吞吐率**：每条指令1个时钟周期，即 $\text{IPC} = 1$

**实际吞吐率**会受到冒险的影响而降低。

### 4.2. 流水线深度

**优点**：更深的流水线可以让每个阶段的逻辑更简单，主频可以更高。

**缺点**：
- 冒险的惩罚更大（清空流水线损失更多周期）
- 流水线寄存器开销增大
- 功耗增加

> 历史上，Intel Pentium 4达到了31级流水线深度（主频冲到3.8GHz），但效率并不高——分支预测错误时损失31个周期。后来的Core架构回归到14~20级流水线，更注重每时钟周期的指令数（IPC）。

## 5. 现代流水线技术

### 5.1. 超标量（Superscalar）

**定义**：每个时钟周期能发射**多条指令**到执行单元。

```
标量流水线（每周期1条）：
周期:   1    2    3    4    5
        指令1 指令2 指令3 指令4 指令5

超标量（每周期2条，双发射）：
周期:   1       2       3
        指令1   指令3   指令5
        指令2   指令4   指令6
```

**实现条件**：
- 取指阶段必须能同时取出多条指令
- 译码阶段必须有多套译码器
- ALU等执行单元必须有多份

**发射宽度**：Intel Core i系列通常4~6发射，Apple M1 FireStorm核可达**8发射**。

### 5.2. 乱序执行（Out-of-Order Execution）

**核心思想**：不按程序中的指令顺序执行，而是**哪个指令的操作数先准备好，就先执行哪个**。

**工作原理**：
1. **取指译码**：正常取指、译码
2. **分发到保留站**：指令被分发到功能单元的保留站中，等待操作数
3. **数据准备好就执行**：每个功能单元监控保留站——哪个指令的操作数全部准备好，就开始执行
4. **重排序缓冲**（ROB，Reorder Buffer）：乱序执行的结果先存入ROB，等前面的指令都执行完后，再从ROB中按程序顺序提交（commit）结果

> **通俗理解**：乱序执行就像厨房里的大厨做菜——菜谱上说"先切菜A，再煮汤B，再煎牛排C"。大厨发现汤需要煮很久，就先让助手开始煎牛排（C先做顺手的事），然后自己切菜（A），等汤煮好了再盛出来（B）。但上菜（提交）时，还是按照A→B→C的顺序——顾客（程序）完全察觉不到执行顺序的变化。

### 5.3. 多发射与乱序执行的关系

| 技术 | 解决的问题 | 本质 |
|:----|:---------|:-----|
| **超标量** | 每周期执行多条 | 增加执行宽度 |
| **乱序执行** | 克服数据依赖导致的等待 | 提高执行单元利用率 |

两者通常结合使用：超标量提供宽度，乱序执行填充效率。

## 习题9：流水线技术

### 9.1 概念题

1. **什么是流水线冒险？有哪几种类型？**

> **答**：流水线冒险是阻碍下一条指令在预定时钟周期开始执行的因素。三类：结构冒险（资源冲突）、数据冒险（数据依赖）、控制冒险（分支跳转）。

2. **什么是数据冒险中的RAW、WAR、WAW？**

> **答**：RAW（先写后读）——真正的数据依赖；WAR（先读后写）——反依赖；WAW（先写后写）——输出依赖。五级流水线中最常见的是RAW。

3. **旁路技术（Forwarding）的原理是什么？**

> **答**：旁路技术将ALU的计算结果直接从EX阶段的输出转发到下一个指令的EX输入，而不必等到WB阶段写回寄存器后再读取。这消除了大多数RAW数据冒险。

4. **分支预测错误会带来什么代价？**

> **答**：预测错误后，流水线中已取出的指令需要清空（flush），从正确目标地址重新取指。五级流水线中损失约2~3个时钟周期。

### 9.2 计算题

5. **某五级流水线CPU，每周期完成一级。理想情况下，执行200条指令需要多少周期？如果其中有20条LOAD指令（每条需要插入1个气泡），10条分支指令（预测正确率80%，错误需清空2个周期），实际需要多少周期？**

> **解**：理想：200 + 5 - 1 = 204周期。LOAD气泡：20×1=20。分支预测错误：10×(1-80%)×2=4。实际：204+20+4=228周期。IPC=200/228≈0.877。

## 本讲核心要点

1. **流水线的本质**：将指令执行分为多个阶段，不同阶段并行处理不同指令——**延迟不变，吞吐率提高**
2. **五级流水线**：IF（取指）→ ID（译码）→ EX（执行）→ MEM（访存）→ WB（写回）
3. **结构冒险**：多指令争用同一硬件资源，通过**分离指令/数据Cache**解决
4. **数据冒险**：指令间存在数据依赖，**旁路技术**从根本上解决了大部分RAW冒险
5. **旁路技术的核心**：ALU计算结果在EX阶段完成后直接转发到下一条指令的输入，不等写回寄存器
6. **控制冒险**：分支指令改变指令流向，通过**分支预测**解决——动态预测正确率可达95%+
7. **分支预测方法演进**：1位→2位饱和计数器→BTB→混合预测器，预测精度从80%提升到97%+
8. **流水线深度权衡**：深度越大主频越高，但冒险惩罚越大——Pentium 4走到31级后回头
9. **超标量**：每周期发射多条指令，增加执行宽度；**乱序执行**：准备好就执行，提高执行单元利用率
10. **现代CPU＝流水线 + 超标量 + 乱序执行 + 分支预测**——这四项技术共同决定了处理器的单核性能
