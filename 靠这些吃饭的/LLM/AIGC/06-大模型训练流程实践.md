## 1. 为什么需要 Transformers 框架

第五章手写的 LLaMA2 代码帮你理解了模型原理，但在实际项目中它有三个问题：

- 每次新模型出来都要从头写——工作量大
- 手写训练循环不支持多卡分布式——训练慢
- 用不了 HuggingFace 上已有的预训练权重——重复造轮子

**Transformers**（HuggingFace）解决了这些问题：`AutoModelForCausalLM.from_pretrained()` 一行代码加载任意开源 LLM，`Trainer` 封装了分布式训练逻辑，配合 `DeepSpeed` 实现多卡混合并行。

---

## 2. 模型初始化

```python
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer

# 方式一：从配置文件初始化（从头训练）
config = AutoConfig.from_pretrained("qwen-1.5b/config.json")
model = AutoModelForCausalLM.from_config(config)

# 方式二：加载预训练权重（微调）
model = AutoModelForCausalLM.from_pretrained("qwen-1.5b")

# 加载配套的 tokenizer
tokenizer = AutoTokenizer.from_pretrained("qwen-1.5b")
```

> **通俗理解**：`from_config` 是"拿图纸造新车"（参数随机初始化），`from_pretrained` 是"开别人已经造好的车"（加载已有权重）。SFT 一般用后者，因为已经有预训练知识了。

## 3. Pretrain——预训练实践

### 3.1. 数据处理

与第五章不同，这里用 HuggingFace 的 `datasets` 库处理数据。

**Step 1**：加载原始数据

```python
from datasets import load_dataset
ds = load_dataset('json', data_files='dataset.jsonl')
# ds["train"][0] 的内容: {"text": "今天天气真好……"}
```

**Step 2**：Tokenize（文本 → 数字）

```python
def tokenize_function(examples):
    return tokenizer([item for item in examples["text"]])

tokenized_datasets = ds.map(tokenize_function, batched=True, num_proc=10,
    remove_columns=["text"])  # 处理完移除原始文本
```

**Step 3**：拼接成固定长度块（2048 tokens）

预训练一般把多个短文本拼接成一个长样本，提高训练效率：

```python
block_size = 2048

def group_texts(examples):
    # 把所有样本的 tokens 拼成一个长序列
    concatenated = {k: list(chain(*examples[k])) for k in examples.keys()}
    # 按 block_size 切分成块
    result = {
        k: [t[i:i+block_size] for i in range(0, total_length, block_size)]
        for k, t in concatenated.items()
    }
    result["labels"] = result["input_ids"].copy()  # CLM 任务 labels = input_ids
    return result
```

```
原始数据： [text1, text2, text3, ...]  （长度不等的文本）
    │
    ▼
tokenize： [[1,5,23,...], [2,8,14,...], ...]  （每个文本变成数字序列）
    │
    ▼
拼接： [1,5,23,...,2,8,14,...,3,9,25,...]  （所有序列拼成一条长河）
    │
    ▼
切块： chunk1:[1,5,...,2048], chunk2:[...], ...  （每 2048 个 token 一块）
```

**关键区别**：Pretrain 时 `labels = input_ids.copy()`，即每个 token 都要参与 loss 计算。后面会看到 SFT 不一样。

### 3.2. 使用 Trainer 训练

```python
from transformers import Trainer, TrainingArguments

training_args = TrainingArguments(
    output_dir="output",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,    # 实际 batch_size = 4 × 4 = 16
    num_train_epochs=1,
    learning_rate=1e-4,
    logging_steps=10,
    save_steps=100,
    gradient_checkpointing=True,       # 省显存：不存中间激活值
    bf16=True,                         # bfloat16 混合精度
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    tokenizer=tokenizer,
    data_collator=default_data_collator,  # CLM 任务用默认 collator
)

trainer.train()
```

**gradient_accumulation_steps 的意义**：显卡一次只能装 batch_size=4，但总 batch_size=16 效果更好。于是每 4 次前向传播才更新一次参数——相当于用时间换空间。

### 3.3. DeepSpeed 分布式训练

单卡太慢，要用多卡。用 DeepSpeed 启动：

```
deepspeed pretrain.py \
    --per_device_train_batch_size 16 \
    --gradient_accumulation_steps 4 \
    --bf16 \
    --deepspeed ./ds_config_zero2.json \
    --report_to swanlab
```

`ds_config_zero2.json` 的核心是 ZeRO-2：

```
{
    "zero_optimization": {
        "stage": 2,           # ZeRO-2：分片梯度 + Adam 状态
        "offload_optimizer": {
            "device": "none"  # 不卸载到 CPU（更快）
        }
    }
}
```

> **通俗理解**：ZeRO-2 像"大家凑钱买书"——每个人都出部分钱（存部分梯度和优化器状态），需要时再从别人那复制过来。第 4 章我们讲过 ZeRO-1/2/3，这里 ZeRO-2 就够了。

## 4. SFT——有监督微调实践

### 4.1. Pretrain vs SFT 的核心区别

| | Pretrain | SFT |
|:---|:---------|:-----|
| **数据** | 无监督纯文本 | 指令-回复对 |
| **loss 计算** | 整个序列所有 token | **只算 assistant 回复部分的 loss** |
| **目的** | 学习语言规律和知识 | 学习遵循指令的能力 |
| **数据量** | 数百 B ~ T 级别 | 数 k ~ 数 M 级别 |

### 4.2. SFT 数据处理——Chat Template

SFT 需要把对话数据按特定"模板"拼接成一个文本序列：

```
原始对话：
  system: "You are a helpful assistant."
  human: "将下列文本翻译成英文：今天天气真好"
  assistant: "Today is a nice day!"

按 Chat Template 拼接后：
  <|im_start|>system\nYou are a helpful assistant.<|im_end|>\n
  <|im_start|>human\n将下列文本翻译成英文：今天天气真好<|im_end|>\n
  <|im_start|>assistant\nToday is a nice day!<|im_end|>\n
                                        ^^^^^^^^^^^^^^^^^^^^^^^^^
                                        只有这部分计算 loss！
```

**关键实现**——对 user 部分用 `IGNORE_TOKEN_ID`（通常是 -100）遮蔽，对 assistant 部分保留真实文本：

```python
IGNORE_TOKEN_ID = -100

def preprocess(sources, tokenizer, max_len):
    input_ids, targets = [], []
    for source in sources:
        input_id, target = [], []
        # system 部分 → 不需要拟合
        system = im_start + _system + tokenizer(system_message).input_ids + im_end
        input_id += system
        target += [IGNORE_TOKEN_ID] * len(system)

        for sentence in source:
            role = sentence["from"]  # "human" 或 "assistant"
            _input_id = tokenizer(role + "\n" + sentence["value"] + "<|im_end|>")
            input_id += _input_id
            if role == "human":
                target += [IGNORE_TOKEN_ID] * len(_input_id)  # 不参与 loss
            else:  # assistant
                target += _input_id  # 参与 loss

        # padding 到固定长度
        input_id += [pad_token_id] * (max_len - len(input_id))
        target += [IGNORE_TOKEN_ID] * (max_len - len(target))
        input_ids.append(input_id[:max_len])
        targets.append(target[:max_len])
```

```
最终训练样本：
  input_ids:  [3, 905, ..., 4, 3, 905, ..., 4, 3, 912, ..., 4, 0, 0]  ← 全部 token
  labels:     [-100,-100,..., -100,-100,..., 3, 912, ..., 4, -100,-100]
                ↑ system 不参与    ↑ human 不参与    ↑ assistant 参与   ↑ padding 不参与
```

**注意**：`loss` 只计算 assistant 回复部分的交叉熵——这是 SFT 与 Pretrain 最本质的区别。

## 5. PEFT——高效微调（LoRA）

当资源有限时，全量微调 7B 模型需要约 60GB 显存。LoRA 可以降到 10GB 以下。

### 5.1. LoRA 的原理

```
全量微调：更新所有参数    W_new = W_old + ΔW     ΔW 大小= d×k （巨大）
LoRA 微调：  W_new = W_old + B×A    B: d×r, A: r×k （r=8, r≪d）
                                   比较 d×k 和 d×r + r×k，后者小得多
```

假设 `d=4096, k=4096, r=8`：
- 全量 ΔW：4096 × 4096 = **16.8M** 参数
- LoRA B+A：4096×8 + 8×4096 = **65K** 参数 → 节省 **256 倍**

**LoRA 的前向计算**：

$$\boxed{h = W_0 x + \Delta W x = W_0 x + BA x}$$

```
输入 x
    │
    ├─→ W_0（冻结）────→ W_0 x  ──┐
    │                              ├──→ h = W_0 x + BA x
    └─→ A（可训练）→ B（可训练）→ BA x ──┘
```

### 5.2. 使用 peft 库实现

```python
from peft import LoraConfig, get_peft_model

# 配置 LoRA 参数
peft_config = LoraConfig(
    task_type="CAUSAL_LM",
    r=8,               # 秩——越小参数越少，但表达能力越弱
    lora_alpha=32,     # 归一化系数，用于控制 LoRA 更新的幅度
    lora_dropout=0.1,  # dropout 比例
    target_modules=["q_proj", "v_proj"],  # 只对 attention 的 Q 和 V 做 LoRA
)

# 用 LoRA 包装原模型（原参数冻结，只新增 A,B 可训练）
model = get_peft_model(model, peft_config)
```

然后把 `model` 传入 Trainer——训练代码和全量 SFT 完全一样。

**训练前后参数对比**：
- 原模型参数：1.5B（全部冻结）
- LoRA 新增参数：约 4.2M（仅 0.28%）
- 显存占用：全量微调 ~60GB → LoRA ~8GB

**推理时将 LoRA 合并回原权重**：`model = model.merge_and_unload()`，推理计算无额外开销。

> **通俗理解**：LoRA 像给模型穿上了一件"特制马甲"——马甲上的小口袋（A/B 矩阵）存着针对某个任务的调整方案。训练时只修改口袋里的东西，原衣服（大模型参数）不动。切换不同任务时，换件马甲就行了，不用换全身衣服。

**习题**：对一个 dim=4096 的线性层做 LoRA（r=8），可训练参数占原参数的比例是多少？

**解**：
- 原参数：$d \times k = 4096 \times 4096 = 16,777,216$
- LoRA 参数：$d \times r + r \times k = 4096 \times 8 + 8 \times 4096 = 65,536$
- 比例：$65,536 / 16,777,216 \approx 0.39\%$——仅千分之四的参数参与训练

## 6. 偏好对齐（进阶路线）

SFT 之后，模型能遵循指令了，但还需要让回答更"符合人类口味"——这叫**偏好对齐**。

### 三条路线对比

| 方法 | 核心思路 | 是否需要 RM | 资源需求 | 学习难度 |
|:----|:--------|:-----------|:--------|:--------|
| **RLHF** | 训练奖励模型 → PPO 强化学习 | 是 | 最高（4 个模型） | 难 |
| **DPO** | 直接优化偏好损失 | 否 | 低（1 个模型） | 中等 |
| **KTO** | 区分好/坏回答 | 否 | 低 | 中等 |

**学习建议**：先掌握本章 Pretrain + SFT + LoRA，再入手 DPO（资源需求低、工程复杂度低），最后深入 RLHF。

## 本讲核心要点

1. **Transformers 框架** 是 LLM 训练的事实标准——`AutoModel` 一行加载模型，`Trainer` 封装训练循环
2. **Pretrain 数据处理** 核心是拼接短文本为固定长度块（如 2048），每个 token 参与 loss 计算
3. **SFT 数据处理** 核心是 Chat Template：user/system 部分用 `IGNORE_TOKEN_ID` 遮蔽，assistant 部分计算 loss
4. **Pretrain 和 SFT 本质都是 CLM**，唯一区别是 loss 的 mask 范围不同
5. **gradient_accumulation_steps** 用时间换空间——小 batch 多次累积达到大 batch 效果
6. **DeepSpeed ZeRO-2** 分片梯度和 Adam 状态，是多卡分布式训练的基础设施
7. **LoRA** 冻结原权重，只训练低秩矩阵 A(r×k) 和 B(d×r)，参数量仅为原参数的 0.1%~1%
8. **LoRA 的 r 值**控制表达能力——r 越大可训练参数越多效果越好，但显存也越高，常用 r=8/16
9. **LoRA 推理无延迟**——训练完可以 `merge_and_unload()` 将权重合并回原矩阵
10. **偏好对齐**（RLHF/DPO/KTO）是 SFT 之后的进阶步骤，让模型回答更符合人类期望
