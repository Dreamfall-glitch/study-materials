
## 第一部分：FPGA 硬件架构

### 1.1. FPGA 基本单元

FPGA（Field-Programmable Gate Array）是一种可以通过编程重新配置其内部互联和逻辑功能的芯片。与 CPU 顺序执行指令不同，FPGA 在空间上并行实现硬件电路。

**核心硬件资源**：

| 资源类型 | 结构 | 功能 | 典型数量(XC7A35T) |
|:--------|:-----|:-----|:-----------------|
| **LUT** (查找表) | 多输入SRAM存储真值表 + MUX | 实现任意组合逻辑函数 | ~20K 个 6输入LUT |
| **FF** (触发器) | D触发器 + 时钟使能 + 复位 | 时序逻辑的存储单元 | ~41K 个 |
| **Block RAM** | 双端口 SRAM 阵列(18Kb/36Kb) | 片上大容量存储/FIFO | ~100个 BRAM36 |
| **DSP Slices** | 专用乘加器(25x18 + 48位累加) | 高速乘累加运算 | ~90个 |
| **IOB** (IO块) | 输入缓冲 + 输出驱动 + DDR | 芯片与外部接口 | 按封装管脚数 |
| **时钟资源** | MMCM/PLL + 全局时钟网络 | 时钟分频/倍频/相位调节 | 5~6个 CM/M |

> **LUT 的工作原理**：一个 6 输入 LUT 本质上是一个 64x1 的 SRAM + 一个 6 选 1 多路选择器。任意 6 输入布尔函数的真值表直接烧录进 SRAM 的 64 个比特位中，"计算"这个函数实质上就是一次存储器查表——这也是"查找表"名称的来源。

**FPGA 内部结构层次**：
```
Configurable Logic Block (CLB) = 多个 Slice
    └── Slice = 若干 LUT + FF + 多路选择器 + 进位链
         └── 每个 LUT 可配置为 6输入单输出 或 5输入双输出
```

### 1.2. FPGA 厂商与器件

| 厂商 | 系列 | EDA 工具 | 特点 |
|:-----|:-----|:--------|:-----|
| Xilinx(AMD) | Artix/Kintex/Virtex/Zynq | Vivado | 市场占有率最高 |
| Intel(Altera) | Cyclone/Arria/Stratix | Quartus Prime | 性价比、Intel代工优势 |
| 国产 | 紫光同创/安路/高云 | PDS/TD/Gowin | 国产替代、高校教学 |

> Zynq 系列是 SoC FPGA——在单一芯片上集成了 ARM Cortex-A 处理器(PS) + FPGA 可编程逻辑(PL)，适用于嵌入式 + 硬件加速的混合场景。PS 和 PL 之间通过 AXI 总线高速互联。

### 1.3. CPLD vs FPGA

| 特性 | CPLD | FPGA |
|:-----|:-----|:-----|
| 基本逻辑单元 | 乘积项 + 宏单元 | LUT + FF |
| 存储结构 | 非易失(Flash) | 易失(SRAM，需外部配置芯片) |
| 规模 | 数百到数千逻辑门 | 数十万到数百万逻辑门 |
| 上电启动 | 即时工作 | 需从外部 Flash 加载配置 |
| 典型应用 | 胶合逻辑、简单状态机 | 复杂数字系统、信号处理 |

## 第二部分：EDA 工具与开发流程

### 2.1. 完整设计流程

```
1. 设计输入（RTL Design）
   Verilog/VHDL 代码编写 + IP 核集成
         ↓
2. RTL 功能仿真（Behavioral Simulation）
   Modelsim / Vivado Simulator — 不涉及时序, 纯功能验证
         ↓
3. 逻辑综合（Synthesis）
   RTL → 门级网表(gate-level netlist) — 映射到 LUT/FF/BRAM/DSP
         ↓
4. 综合后仿真（Post-Synthesis Simulation）
   带门延迟的功能验证(可选，多数项目跳过)
         ↓
5. 布局布线（Place & Route / Implementation）
   将网表中的逻辑单元分配到FPGA物理位置 + 连接布线资源
         ↓
6. 静态时序分析（Static Timing Analysis, STA）
   检查所有时序路径是否满足 Setup/Hold 约束
         ↓
7. 生成比特流（Bitstream Generation）
   生成 .bit 文件，下载到 FPGA 配置芯片
         ↓
8. 上板调试（On-chip Debug）
   使用 ILA(Vivado) 或 SignalTap(Quartus) 抓取内部信号
```

### 2.2. 综合过程详解

综合（synthesis）是 EDA 流程中最关键的一步——将行为级 RTL 转化为与具体硬件对应的门级网表。

**综合器的工作**：
1. **语法分析**：解析 Verilog 并建立抽象语法树
2. **逻辑优化**：消去冗余逻辑、常数传播、资源共享
3. **技术映射**：将通用门级逻辑映射到特定 FPGA 的 LUT/FF/DSP 硬件原语

**综合可推断的硬件**：

| RTL 写法 | 综合结果 |
|:---------|:---------|
| 计数器（if-else 模式 + 复位） | FF + 加法器 |
| 二维数组 reg + 单时钟读/写 | Block RAM |
| `a * b` 乘法运算 | DSP Slice（位数匹配时） |
| case 语句（状态机模式） | LUT + FF (二进制/独热编码) |
| `assign out = a & b` | LUT 中的与门 |

**综合推断的限制**：
- `initial` 语句：仿真有效，综合时忽略
- `#delay` 延时：综合时忽略（仅仿真用）
- `@(posedge something)` 中的 something 必须为时钟信号

### 2.3. 布局布线

综合后的网表是逻辑层面上的连接关系——还没指定每个门放在芯片上的哪个位置。布局布线将逻辑网表物理映射到 FPGA 的硅片上：

- **布局（Placement）**：分配 LUT/FF/BRAM/DSP 到具体的 Slice 位置，目标是优化时序和功耗
- **布线（Routing）**：通过开关矩阵和互连线连接各 Slice 的输入输出，解决信号冲突和拥塞问题

> 布局布线的质量直接决定设计能跑多快。两个 FF 之间连线如果绕了半个芯片，延迟可能比局部路径大 10 倍以上。工具通常需要多次迭代才能找到最优解。

**布局布线挑战**：
- **拥塞（Congestion）**：某区域布线资源不足
- **时序收敛（Timing Closure）**：多次布局布线才能满足时序要求
- **确定性（Determinism）**：同一设计两次布局布线可能得到不同结果

### 2.4. 时序约束与 STA

综合和布局布线工具需要知道设计者对时钟频率的期望——这就是时序约束的作用。

**基本约束语句**（SDC/XDC 格式）：

```tcl
# 定义时钟
create_clock -period 10.000 -name clk [get_ports clk]  # 100MHz

# 输入/输出延迟约束
set_input_delay  -clock clk -max 2.0 [get_ports data_in]
set_output_delay -clock clk -max 2.0 [get_ports data_out]

# 伪路径（跨时钟域，不需要分析）
set_false_path -from [get_clocks clk_a] -to [get_clocks clk_b]

# 多周期路径
set_multicycle_path -setup 2 -from [get_clocks clk] -to [get_clocks clk]
```

> **Setup time**：数据必须在时钟沿之前稳定到达 FF 输入端的最小时间。不满足就导致逻辑错误。**Hold time**：数据在时钟沿之后必须保持的最短时间。Setup 与时钟频率相关，Hold 与频率无关。

**亚稳态**（Metastability）：当时钟沿恰好在数据变化过程中到达，FF 的输出可能进入一种不稳定的中间态（非 0 非 1），经过不确定的恢复时间后可能翻转到错误状态。跨时钟域信号必须打至少两级同步器来降低亚稳态传播概率。

**两级同步器标准写法**：
```verilog
reg sync1, sync2;
always @(posedge clk_dst or negedge rst_n) begin
    if (!rst_n) {sync2, sync1} <= 2'b00;
    else        {sync2, sync1} <= {sync1, signal_src};
end
assign signal_sync = sync2;
```

## 第三部分：Verilog 核心语法

### 3.1. 模块与实例化

```verilog
module top_level (
    input  wire        clk_50m,
    input  wire        btn_reset,
    output wire [3:0]  led
);
    // 子模块实例化（按名称关联，推荐）
    counter #(
        .MAX_COUNT(50_000_000)
    ) u_counter (
        .clk    (clk_50m),
        .rst_n  (!btn_reset),
        .out    (led)
    );
endmodule
```

模块参数化通过 `#(.PARAM(value))` 传递，`parameter` 使设计可复用。

**wire 与 reg 的区别**：

| 类型 | 用途 | 赋值方式 | 存储特性 |
|:-----|:-----|:---------|:---------|
| wire | 组合逻辑连线 | `assign` 或模块端口连接 | 无存储，值由驱动源决定 |
| reg | 过程块中的变量 | `always` 或 `initial` 块内 | 可综合为 FF 或 latch |

> **重要**：`reg` 不一定会综合成寄存器。在 `always @(*)` 中赋值的 reg 综合为组合逻辑，在 `always @(posedge clk)` 中赋值的 reg 才综合为触发器。

### 3.2. 运算符详解

```verilog
// 位拼接与复制
assign out = {a[3:0], b[3:0]};  // 拼接: {4'b1100, 4'b0011} = 8'b1100_0011
assign out = {4{a[0]}};         // 复制: {4{1'b1}} = 4'b1111

// 归约运算符
wire all_one  = &data;   // AND 归约：data所有位相与
wire odd_ones = ^data;   // XOR 归约：奇偶校验

// 算术运算符
assign prod = a * b;      // 综合器会用 DSP 或 LUT 实现, 小心大位宽
assign divide = a / b;    // 除法不可综合（除非是除以 2 的幂）
```

**运算符优先级**（从高到低）：
1. `! ~ & | ^` (取反、归约)
2. `* / %`
3. `+ -`
4. `<< >>` (移位)
5. `< <= > >=` (关系)
6. `== != === !==` (相等)
7. `& ^ ^~` (位运算)
8. `&&` (逻辑与)
9. `||` (逻辑或)
10. `?:` (条件)

### 3.3. 阻塞 vs 非阻塞的仿真行为

```verilog
// 阻塞赋值：顺序执行
always @(posedge clk) begin
    a = b;          // a 在这一拍立即变为 b 的值
    c = a;          // c = 新a = b
    // 上面两条语句综合结果：a 和 c 得到相同的值 b，等同于 c = b
end

// 非阻塞赋值：并行更新
always @(posedge clk) begin
    a <= b;         // 调度：a 在本时钟沿结束后更新为 b
    c <= a;         // 调度：c 在本时钟沿结束后更新为 a（旧值）
    // 综合结果：a 和 c 分别得到 b 和 a_old → 一个两级移位寄存器
end
```

**黄金法则**：
- 组合逻辑（`always @(*)`）→ 用阻塞赋值 `=`
- 时序逻辑（`always @(posedge clk)`）→ 用非阻塞赋值 `<=`
- 同一个 always 块中不要混用两种赋值

## 第四部分：常用电路模板

### 4.1. 流水线乘法器

```verilog
// 流水线乘法器(打破长组合路径,提高Fmax)
reg [15:0] a_d1, b_d1;
reg [31:0] mul_d1, mul_d2;

always @(posedge clk) begin
    a_d1   <= a;              // Stage 0: 输入寄存
    b_d1   <= b;
    mul_d1 <= a_d1 * b_d1;    // Stage 1: 乘法(可能用DSP)
    mul_d2 <= mul_d1;         // Stage 2: 输出寄存
end
assign mul_out = mul_d2;
```

> **流水线原理**：如果乘法延迟为 4ns，时钟周期为 5ns——直接连可以跑。如果乘法延迟为 12ns，时钟周期为 5ns——综合工具报不满足时序。插入寄存器将乘法拆成多拍（流水线），每拍只要完成一部分组合逻辑，Fmax 大幅提升，代价是结果延迟 2-3 拍出来。

**流水线深度与 Fmax 的关系**：
```
无流水线: Tclk > Tcomb (组合逻辑延迟)
1级流水线: Tclk > max(Tcomb1, Tcomb2)
N级流水线: 频率受最慢一级限制，总延迟为 N 个时钟周期
```

### 4.2. 格雷码计数器

```verilog
// 格雷码计数器(跨时钟域FIFO专用的二进制→格雷码转换)
reg [3:0] gray_cnt;
always @(posedge clk) begin
    gray_cnt <= (gray_cnt >> 1) ^ (gray_cnt + 1);
end
```

> 格雷码相邻值之间只有 1 bit 变化——跨时钟域传输时可避免多比特同时翻转引发的采样错误。

**二进制转格雷码公式**：`gray = (binary >> 1) ^ binary`

### 4.3. 同步 FIFO

```verilog
reg [7:0] fifo_mem [0:15];  // 16深 x 8宽
reg [3:0] wr_ptr, rd_ptr;
reg [4:0] count;             // FIFO内数据个数

wire empty = (count == 0);
wire full  = (count == 16);

always @(posedge clk) begin
    if (wr_en && !full) begin
        fifo_mem[wr_ptr] <= wr_data;
        wr_ptr <= wr_ptr + 1;
        count  <= count + 1;
    end
    if (rd_en && !empty) begin
        rd_data <= fifo_mem[rd_ptr];
        rd_ptr <= rd_ptr + 1;
        count  <= count - 1;
    end
end
```

**FIFO 的关键参数**：
- 深度（Depth）：最多能存多少个数据
- 宽度（Width）：每个数据多少位
- 空标志（empty）：读指针追上写指针
- 满标志（full）：写指针追上读指针

## 第五部分：状态机设计

### 5.1. 三段式状态机模板

```verilog
// 一段式（不推荐）：所有逻辑在一个 always 块中，可读性差
// 二段式（可用）：状态跳转 + 输出逻辑分开，但输出逻辑是组合的
// 三段式（推荐）：状态寄存器 + 次态逻辑 + 输出逻辑完全分离

module fsm_example (
    input clk, rst_n,
    input din,
    output reg dout
);
    // 状态编码
    localparam IDLE = 3'b001, RUN = 3'b010, DONE = 3'b100;
    reg [2:0] state, next_state;

    // 1. 状态寄存器（时序逻辑）
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) state <= IDLE;
        else        state <= next_state;
    end

    // 2. 次态逻辑（组合逻辑）
    always @(*) begin
        next_state = state;
        case (state)
            IDLE: if (din) next_state = RUN;
            RUN:  if (done_signal) next_state = DONE;
            DONE: next_state = IDLE;
        endcase
    end

    // 3. 输出逻辑（时序逻辑，避免毛刺）
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) dout <= 1'b0;
        else begin
            case (state)
                DONE: dout <= 1'b1;
                default: dout <= 1'b0;
            endcase
        end
    end
endmodule
```

### 5.2. 状态编码方式

| 编码方式 | 特点 | 适用场景 |
|:---------|:-----|:---------|
| 二进制编码 | 状态少，节省 FF | 小状态机（<8 状态） |
| 独热编码（One-hot） | 每个状态一个 FF，组合逻辑简单 | 高速设计、大状态机 |
| 格雷码 | 相邻状态只变 1 bit | 跨时钟域传输 |

```verilog
// 独热编码示例
localparam IDLE = 4'b0001, RUN = 4'b0010, DONE = 4'b0100, ERROR = 4'b1000;
// 次态逻辑更简单：只需判断单个 bit
if (state[0] && din) next_state = RUN;  // 从 IDLE 跳转
```

## 第六部分：IP 核与复用

在实际工程中，不鼓励从零手写所有模块——厂商和第三方提供了大量可复用的 IP 核（Intellectual Property cores）。

| IP 核类型 | 实例 | 使用方式 |
|:---------|:-----|:--------|
| **硬核**（固化在硅上） | Zynq 的 ARM 核、MGT(GTP/GTX)收发器 | 不可修改，例化即可 |
| **软核**（RTL 级，可修改） | MicroBlaze 软核处理器、AXI Interconnect | 可查看源代码，可修改参数 |
| **加密 IP**（需要 License） | DDR4 控制器、PCIe 接口 | XCI 文件集成，黑盒使用 |
| **开源 IP** | PicoRV32、UART、SPI Master | 自由使用和修改 |

**Vivado IP 集成流程**：
1. IP Catalog → 选择 IP（如 Clocking Wizard、FIFO Generator）
2. 配置参数（输入频率、输出频率、相位等）
3. Generate → 生成 .xci 文件和例化模板
4. 在 BD(Block Design)或 RTL 中例化
5. 综合时 IP 的网表自动合并

**使用 IP 的优势**：
- 经过厂商充分验证，可靠性高
- 针对特定器件优化（时序、面积）
- 减少开发和验证时间

## 第七部分：调试与上板

### 7.1. 在线逻辑分析仪

FPGA 内部信号不能像软件那样 `printf` 输出——必须使用片上调试工具。

| 平台 | 工具 | 原理 |
|:-----|:-----|:-----|
| Xilinx | ILA (Integrated Logic Analyzer) | 用 BRAM 存储采样的内部信号，通过 JTAG 回读到 PC |
| Intel | SignalTap II | 同上原理 |

```tcl
# Vivado 中标记要观察的信号
(* mark_debug = "true" *) wire [7:0] debug_signal;
```

### 7.2. 片上调试流程

1. 在 RTL 中标记 `mark_debug` 信号
2. 综合后打开综合设计，`Set Up Debug` 向导
3. 选择采样时钟、触发条件、采样深度
4. 重新实现(Implementation) → 生成比特流
5. 下载后打开 Hardware Manager → 配置触发 → 抓取波形

**调试技巧**：
- 采样深度受 BRAM 容量限制，深度越深消耗 BRAM 越多
- 触发条件支持：边沿触发、电平触发、数据匹配、复杂序列
- 优先调试接口信号（握手、状态机），再调试数据通路

### 7.3. 常见上板问题排查

| 现象 | 可能原因 | 排查方法 |
|:-----|:---------|:---------|
| 无输出 | 时钟未工作 / 复位拉死 | ILA 抓时钟和复位信号 |
| 输出偶尔错误 | 跨时钟域问题 / 时序违例 | 检查时序报告，添加同步器 |
| 下载后不工作 | 配置模式错误 / 电源问题 | 检查 Mode 引脚，测量电压 |
| 功能时对时错 | 亚稳态 / 毛刺 | 降低频率测试，添加寄存输出 |

## 第八部分：条件语句与分支

### 8.1. case / casex / casez

```verilog
// case: 精确匹配（x 和 z 也作为确定值比较）
case (state)
    2'b00: next = S0;
    2'b01: next = S1;
    2'b10: next = S2;
    default: next = S0;    // 必须有 default，避免综合出 latch
endcase

// casez: z(高阻)在比较中被视为"不关心"位（dont-care）
casez (opcode)
    4'b10??: add_flag = 1;     // 匹配 1000~1011 的任意值
    default: add_flag = 0;
endcase

// casex: x 和 z 都视为 dont-care（仿真中常用，综合需谨慎）
```

> `casez` 在实际 RTL 中比 `casex` 更常用，因为 `z` 通常代表真实的"不关心"状态，而 `x` 在硬件中不存在。综合器对待 `casez` 更明确。

**case 与 if-else 的选择**：
- `case`：适用于多路分支（如状态机、解码器）
- `if-else`：适用于优先级编码（如中断仲裁）
- `case` 综合出并行 MUX，`if-else` 综合出串行优先级链

### 8.2. generate 语句

`generate` 用于在编译时批量生成硬件实例——等效于硬件循环展开，不是运行时行为：

```verilog
// 生成 8 个相同的 D 触发器（并行）
genvar i;
generate
    for (i = 0; i < 8; i = i + 1) begin : dff_chain
        reg dff;
        always @(posedge clk or negedge rst_n) begin
            if (!rst_n)
                dff <= 0;
            else if (i == 0)
                dff <= data_in;
            else
                dff <= dff_chain[i-1].dff;  // 引用前一级（层次化名）
        end
    end
endgenerate
```

`generate` 也可用于 `if/case` 条件编译：

```verilog
generate
    if (DATA_WIDTH == 8) begin : gen_8bit
        // 8位数据通路
    end else begin : gen_other
        // 其他位宽的数据通路
    end
endgenerate
```

### 8.3. 函数（function）与任务（task）

| 特性 | function | task |
|:-----|:--------|:-----|
| 返回值 | 有，函数名即返回变量 | 无返回值（通过 output/inout 参数输出） |
| 参数方向 | 默认 input | input/output/inout |
| 时序控制 | 不可用 `#/@/wait` | 可以包含延时 |
| 调用 | 表达式内调用 `x = func(a,b)` | 过程语句调用 `task_name(a,b,c)` |
| 可综合性 | 可综合（无时序控制时） | 通常不可综合 |
| 典型用途 | 组合逻辑计算（如优先级编码器） | testbench 激励生成 |

```verilog
// function: 组合逻辑（可综合）
function [3:0] priority_encoder;
    input [7:0] din;
    integer i;
    begin
        priority_encoder = 0;
        for (i = 0; i < 8; i = i + 1)
            if (din[i]) priority_encoder = i;
    end
endfunction

// task: 测试激励（仿真专用）
task send_byte;
    input [7:0] data;
    integer i;
    begin
        for (i = 0; i < 8; i = i + 1) begin
            @(posedge clk);
            txd <= data[i];
        end
    end
endtask
```

## 第十部分：更多常用电路模板

### 10.1. 基本加法器

```verilog
// 带进位链的加法器
assign {cout, sum} = a + b + cin;

// 参数化超前进位加法器（减少进位传播延迟）
module carry_lookahead_adder #(parameter W = 16) (
    input [W-1:0] a, b,
    input cin,
    output [W-1:0] sum,
    output cout
);
    wire [W:0] carry;
    assign carry[0] = cin;
    genvar i;
    generate
        for (i = 0; i < W; i = i + 1) begin
            wire g = a[i] & b[i];   // 进位生成
            wire p = a[i] ^ b[i];   // 进位传播
            assign sum[i]   = p ^ carry[i];
            assign carry[i+1] = g | (p & carry[i]);
        end
    endgenerate
    assign cout = carry[W];
endmodule
```

### 10.2. 桶形移位器（Barrel Shifter）

```verilog
// 经典 8-bit 全桶形移位器（左移/右移/循环）
module barrel_shifter (
    input [7:0] din,
    input [2:0] shamt,    // 移位量
    input [1:0] mode,     // 00=左移, 01=右移逻辑, 10=右移算术, 11=循环
    output reg [7:0] dout
);
    always @(*) begin
        case (mode)
            2'b00: dout = din << shamt;
            2'b01: dout = din >> shamt;
            2'b10: dout = $signed(din) >>> shamt;  // 算术右移，符号位扩展
            2'b11: dout = {din, din} >> (8 - shamt);  // 循环移位
        endcase
    end
endmodule
```

### 10.3. UART 发送模块

```verilog
module uart_tx #(
    parameter CLK_FREQ = 50_000_000,
    parameter BAUD     = 115200
) (
    input  wire       clk, rst_n,
    input  wire       send,            // 发送触发脉冲
    input  wire [7:0] data,
    output reg        txd,             // 串行输出线
    output reg        busy
);
    localparam BIT_PERIOD = CLK_FREQ / BAUD;
    reg [15:0] bit_cnt;
    reg [3:0]  bit_idx;   // 0=start, 1-8=data, 9=stop
    reg [7:0]  tx_data;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            txd <= 1'b1; busy <= 0;
            bit_cnt <= 0; bit_idx <= 0;
        end else if (busy) begin
            if (bit_cnt == BIT_PERIOD - 1) begin
                bit_cnt <= 0;
                bit_idx <= bit_idx + 1;
                case (bit_idx)
                    0:  txd <= 1'b0;              // 起始位
                    1:  txd <= tx_data[0];
                    2:  txd <= tx_data[1];
                    3:  txd <= tx_data[2];
                    4:  txd <= tx_data[3];
                    5:  txd <= tx_data[4];
                    6:  txd <= tx_data[5];
                    7:  txd <= tx_data[6];
                    8:  txd <= tx_data[7];
                    9:  txd <= 1'b1;              // 停止位
                    10: begin busy <= 0; txd <= 1'b1; end
                endcase
            end else
                bit_cnt <= bit_cnt + 1;
        end else if (send) begin
            busy <= 1; tx_data <= data; bit_idx <= 0;
        end
    end
endmodule
```

### 10.4. ALU 算术逻辑单元

```verilog
module alu #(parameter W = 8) (
    input  [W-1:0] a, b,
    input  [2:0]   op,
    output reg [W-1:0] result,
    output reg         zero, carry, overflow
);
    parameter ADD = 3'd0, SUB = 3'd1, AND = 3'd2,
              OR  = 3'd3, XOR = 3'd4, SLT = 3'd5;  // set less than

    always @(*) begin
        {carry, overflow} = 0;
        case (op)
            ADD: {carry, result} = a + b;
            SUB: {carry, result} = a - b;
            AND: result = a & b;
            OR:  result = a | b;
            XOR: result = a ^ b;
            SLT: result = ($signed(a) < $signed(b)) ? 1 : 0;  // 有符号比较
            default: result = 0;
        endcase
        zero = (result == 0);
    end
endmodule
```

### 10.5. CRC-8 校验模块

```verilog
module crc8 (
    input  wire       clk, rst_n,
    input  wire       valid,
    input  wire [7:0] data,
    output reg  [7:0] crc_out
);
    // CRC-8-ATM: x^8 + x^2 + x + 1, 初始值 0xFF
    wire [7:0] crc_next;
    wire       feedback = data[7] ^ crc_out[7];
    assign crc_next = {
        data[6] ^ crc_out[6],
        data[5] ^ crc_out[5],
        data[4] ^ crc_out[4],
        data[3] ^ crc_out[3] ^ feedback,
        data[2] ^ crc_out[2] ^ feedback,
        data[1] ^ crc_out[1],
        data[0] ^ crc_out[0] ^ feedback,
        feedback
    };
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) crc_out <= 8'hFF;
        else if (valid) crc_out <= crc_next;
    end
endmodule
```

## 第十一部分：时序分析深入

### 11.1. 时序路径类型

STA 工具分析四种时序路径：

| 路径类型 | 起点 | 终点 | 约束类型 |
|:--------|:-----|:-----|:--------|
| 输入到寄存器(in2reg) | 芯片输入管脚 | 内部 FF 的 D 端 | `set_input_delay` |
| 寄存器到寄存器(reg2reg) | 内部 FF 的 Q 端 | 内部 FF 的 D 端 | `create_clock`（自动推导） |
| 寄存器到输出(reg2out) | 内部 FF 的 Q 端 | 芯片输出管脚 | `set_output_delay` |
| 输入到输出(in2out) | 芯片输入管脚 | 芯片输出管脚 | 组合逻辑延迟约束 |

**时序路径示意图**：
```
输入 → [组合逻辑] → 寄存器 → [组合逻辑] → 寄存器 → [组合逻辑] → 输出
        ↑                  ↑                  ↑
      in2reg            reg2reg            reg2out
```

### 11.2. Setup/Hold Slack

综合后的时序报告给出每条关键路径的 slack 值：

```
Setup Slack = Data Required Time - Data Arrival Time
Hold Slack  = Data Arrival Time - Data Required Time
```

Slack 为负表示时序违例；为正则表示设计满足约束且有裕量。

| Slack 类型 | 负值含义 | 解决方法 |
|:-----------|:---------|:---------|
| Setup slack 为负 | 时钟频率太高，数据来得太慢 | 插入流水线、逻辑优化、降低频率 |
| Hold slack 为负 | 数据路径太短，时钟歪斜导致 | 添加 buffer、调整时钟树 |

### 11.3. 时序优化方法

**Setup 违例解决方法**：
- **插入流水线寄存器**：打破长组合逻辑路径
- **逻辑复制**：减少高扇出信号的负载
- **优先级重排**：将关键路径上的逻辑移到靠近输出端
- **重定时（Retiming）**：工具自动移动寄存器位置平衡路径延迟

```verilog
// 逻辑复制：减少高扇出信号
// 原来：一个驱动控制8个逻辑块（扇出=8，负载大）
// 优化：复制3份，每份驱动2~3个
reg en_copy1, en_copy2, en_copy3;
always @(posedge clk) {en_copy1, en_copy2, en_copy3} <= {3{en_orig}};
```

**Hold 违例解决方法**：
- 在数据路径上插入 buffer/LUT 增加延迟
- 调小时钟树偏斜（Clock Skew）
- 在布局布线阶段设置优先级

## 本讲核心要点

1. **FPGA 硬件基础**：FPGA 通过 LUT(查找表)实现组合逻辑，通过 FF(触发器)实现时序逻辑——所有硬件电路由这两类基本单元构成，加上 BlockRAM、DSP、时钟网络提供片上存储和计算加速。
2. **EDA 设计流程**：依次为 RTL设计 → 功能仿真 → 逻辑综合(网表映射) → 布局布线(物理映射) → 静态时序分析(Setup/Hold检查) → 比特流生成。时序约束是综合和布局布线的指导文件。
3. **Verilog 本质**：Verilog 是硬件描述语言而非编程语言——每一行代码在脑中必须先有对应的电路图。阻塞 `=` 描述组合逻辑(顺序执行)，非阻塞 `<=` 描述时序逻辑(并行更新)。
4. **状态机设计**：三段式状态机(状态寄存器 + 次态逻辑 + 输出逻辑)是最佳实践。独热编码减小组合逻辑复杂度，提升高速设计的时序收敛能力。
5. **流水线与跨时钟域**：流水线通过在组合逻辑中插入寄存器来分割长路径——以延迟为代价换吞吐率。跨时钟域信号必须经过至少两级同步器避免亚稳态。
6. **调试与验证**：片上调试用 ILA/SignalTap 抓取内部信号波形——无法用 `printf` 调 FPGA，JTAG 回读 BRAM 是唯一的实时调试手段。仿真阶段应使用自检查 testbench 和覆盖率分析保证验证充分性。
