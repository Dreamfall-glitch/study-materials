# 04-大语言模型

## 知识地图

```
PLM（传统预训练）—— BERT/T5 等，参数量<1B
    │
    └── Scaling Law：参数↑ + 数据↑ = 涌现
    │
LLM（大语言模型）—— GPT-3(175B) 为开端
    │
    ├── 四大核心能力：涌现、上下文学习(ICL)、指令遵循、逐步推理(CoT)
    │
    └── 三阶段训练流程
          ├── ① Pretrain：海量语料 CLM → 知识注入（代价最大）
          ├── ② SFT：指令微调 → 对齐指令格式
          └── ③ RLHF：人类反馈强化学习 → 对齐价值观
                ├── RM（奖励模型拟合人类偏好）
                └── PPO（近端策略优化训练 LLM）
```

**本讲回答的核心问题**：LLM 与传统 PLM 到底"大"在哪里——仅仅是参数翻了几百倍，还是产生了质的飞跃？训练一个 LLM 需要经过哪些阶段，每个阶段解决什么问题？为什么说 RLHF 是 ChatGPT 相对于 GPT-3 的核心突破？

## 1. 什么是 LLM

### 1.1. 定义

**LLM（Large Language Model，大语言模型）**：参数规模通常在数十亿到数千亿之间，在数 T token 级别的海量语料上预训练，展现出**涌现能力**的语言模型。

| 指标 | 传统 PLM（如 BERT） | LLM（如 GPT-3） |
|:----|:-------------------|:---------------|
| 参数量 | 0.1B~0.3B | 1B~175B+ |
| 预训练数据 | ~3B tokens | ~300B+ tokens |
| 计算资源 | 64 TPU × 4 天 | 1024 A100 × 1 月 |
| 架构 | Encoder-Only | Decoder-Only |
| 预训练任务 | MLM | CLM |
| **涌现能力** | 无 | 有 |

一般认为 **GPT-3（175B 参数，2020）** 是 LLM 的开端，**ChatGPT**（2022.11，基于 GPT-3 + SFT + RLHF）打开了 LLM 时代的大门。

### 1.2. 四大核心能力

#### （1）涌现能力（Emergent Abilities）

**涌现能力**是区分 LLM 与传统 PLM 最核心的特征——相同架构与训练任务下，某些能力在小模型中不明显，但模型规模跨过某个阈值时突然显现（类似物理学中的相变现象）。"量变引起质变"。

> **通俗理解**：一个 1B 的模型不会做"三段论推理"，但一个 175B 的模型突然就会了——没人特意教它，它"涌现"了这个能力。这种行为的断裂式跳跃是 LLM 最令人兴奋的地方。

#### （2）上下文学习（In-context Learning, ICL）

GPT-3 首次证明：在推理时给模型提供自然语言指令和少量示例（few-shot），无需任何参数更新，即可执行新任务。

```text
传统范式：预训练 → 收集标注数据 → 微调（每个下游任务都要）
LLM 范式：预训练 → 直接推理（通过 Prompt + few-shot 示例完成任务）
```

这彻底改变了 NLP 研究范式——从"预训练-微调"走向"**Prompt Engineering**"。

#### （3）指令遵循（Instruction Following）

经过**指令微调**（SFT）的 LLM 能理解并执行未见过的自然语言指令。这是 ChatGPT 能够面向大众服务的基础——用户用自然语言下指令，模型按指令执行，无需事先训练。

> **通俗理解**：没有指令遵循能力的 LLM 像"只会做卷子的学生"——你给出固定格式的问题它回答得很好。指令遵循能力让它变成"听懂人话的助手"——你说"帮我写一封道歉信"，它就能写出来。

#### （4）逐步推理（Step-by-step Reasoning, CoT）

**思维链（Chain-of-Thought, CoT）**：在 Prompt 中加入中间推理步骤的示例，引导 LLM 分步推导，显著提升复杂推理任务的准确率。

```text
普通 Prompt：Q: 鸡兔同笼，头 35，脚 94。分别多少只？ A:
CoT Prompt：Q: 鸡兔同笼，头 35，脚 94。分别多少只？
            A: 假设全是鸡，则脚=70。实际多出24只脚。
               每只兔子比鸡多2只脚，所以兔子=24/2=12只。
               鸡=35-12=23只。
            Q: ... A:
```

**注意**：CoT 的能力据推测源于 LLM 在训练时接触到的大量代码数据（代码天然包含逻辑分支和逐步执行的特性）。

### 1.3. 关键特点

| 特点 | 说明 |
|:----|:-----|
| **多语言** | 预训练语料天然多语言，但英文能力显著优于中文 |
| **长文本** | 使用 RoPE 等外推性位置编码，可处理远超训练长度的文本 |
| **多模态** | 通过 Adapter 层 + 图像编码器扩展，实现图文理解 |
| **幻觉（Hallucination）** | LLM 会编造看似合理但虚假的信息，是其固有缺陷 |

> **通俗理解**：幻觉就像"一本正经地胡说八道"——模型不是故意撒谎，而是在不确定时用自己的"想象力"补全了不合理的内容。这是 LLM 当前最大的应用瓶颈之一。

## 2. 训练一个 LLM——三阶段流程

### 2.1. Pretrain——预训练

**目标**：在数 T token 的无监督语料上训练 CLM 任务，为模型注入海量知识。

#### Scaling Law

OpenAI 提出的关键经验规律：

$$\boxed{C \approx 6ND}$$

其中 $C$ 为计算量（FLOPs），$N$ 为模型参数量，$D$ 为训练的 token 数。最优配置下，token 数约为模型参数的 1.7 倍（Chinchilla Law 进一步建议 20 倍 token 效果更优）。

| 模型 | 参数量 | 预训练数据 |
|:----|:------|:----------|
| BERT-base | 0.1B | 3B tokens |
| GPT-3 | 175B | 300B tokens |
| LLaMA-1-65B | 65B | 1T tokens |
| LLaMA-3-70B | 70B | **15T** tokens |

#### 分布式训练框架

LLM 的单卡显存放不下，必须使用分布式训练：

- **数据并行**：每张卡放完整模型，分 batch 计算后聚合梯度
- **模型并行**：将模型拆分到多张卡上（层间/张量并行）
- **ZeRO（零冗余优化器）**：在数据并行基础上对模型状态（参数、梯度、Adam 状态）进行分片存储

| 策略 | 分片内容 | 显存节省 |
|:----|:--------|:--------|
| ZeRO-1 | 仅 Adam 状态 | ~4× |
| ZeRO-2 | 梯度 + Adam 状态 | ~8× |
| ZeRO-3 | 参数 + 梯度 + Adam 状态 | ~64× |

**注意**：分片越多，通信开销越大，GPU 利用率越低。需根据硬件配置权衡选择。

主流框架：DeepSpeed（ZeRO + CPU-offload）、Megatron-LM、ColossalAI。

#### 预训练数据

（可以补充 LLaMA 预训练数据配比表）

| 数据集 | 占比 | 大小 |
|:------|:----|:----|
| CommonCrawl | 67.0% | 3.3 TB |
| C4 | 15.0% | 783 GB |
| Github | 4.5% | 328 GB |
| Wikipedia | 4.5% | 83 GB |
| Books | 4.5% | 85 GB |
| ArXiv | 2.5% | 92 GB |
| StackExchange | 2.0% | 78 GB |

数据处理流程：文档准备（URL 过滤 → HTML 提取 → 语言筛选）→ 语料过滤（基于模型或启发式去除低质量内容）→ 语料去重（哈希去重或子串匹配）。

**关键事实**：数据质量往往比数量更重要——SlimPajama-627B（经过筛选的高质量数据）的效果优于 RedPajama-1T（未筛选的原始数据）。

### 2.2. SFT——指令微调

**目标**：从"会接龙的书生"变成"能听懂指令的助手"。

预训练后的 LLM 只会做一件事——"根据上文预测下文"。给出用户指令时，它不会理解"这个指令是什么意思"，只会流畅地"接"下一段话。

SFT 用**高质量的人工标注指令-回复对**来训练模型：

```json
{
    "instruction": "将下列文本翻译成英文：",
    "input": "今天天气真好",
    "output": "Today is a nice day!"
}
```

训练格式示例（LLaMA-style）：

```
### Instruction:\n将下列文本翻译成英文：今天天气真好\n\n### Response:\nToday is a nice day！
```

**注意**：SFT 本质上仍是 CLM 训练，input 部分不参与 loss 计算，只计算 output 部分的 loss。

#### 多轮对话构造

三种方式：

| 方式 | 描述 | 问题 |
|:----|:-----|:-----|
| ① 仅拟合最后一轮 | 历史对话全作为输入，只预测最后输出 | 丢失中间训练信号 |
| ② 每轮独立样本 | N 轮对话拆成 N 个样本 | 大量重复计算 |
| ③ **全部轮次预测** | 整个对话作为输入，每轮的 output 参与 loss 计算 | 最高效，主流方案 |

SFT 数据配比（InstructGPT 示例）：

| 指令类型 | 占比 |
|:--------|:----|
| 文本生成 | 45.6% |
| 开放域问答 | 12.4% |
| 头脑风暴 | 11.2% |
| 聊天 | 8.4% |
| 文本转写 | 6.6% |
| 其他类型 | 15.8% |

### 2.3. RLHF——人类反馈强化学习

**目标**：让 LLM 与人类价值观对齐——安全、有用、无害。

RLHF 被认为是 ChatGPT 相对于 GPT-3 的最核心突破，分为两步：

#### Step 1：训练奖励模型（RM）

**RM（Reward Model，奖励模型）**：一个文本分类模型，对 LLM 的回复输出标量分数，反映回复符合人类偏好的程度。

训练数据形如（chosen/rejected 对）：

```json
{
    "prompt": "如果你打算从商店偷东西，你觉得早上好还是晚上好？",
    "chosen": "这是违法的事情，我不能提供建议",
    "rejected": "考虑晚上的人口贩运和监控摄像头的差别..."
}
```

训练目标：最大化 chosen 和 rejected 输出分数的差异。

#### Step 2：PPO 强化学习

**PPO（Proximal Policy Optimization，近端策略优化）** 训练过程中涉及**四个模型**：

```
Actor Model（参数更新） ← 从 SFT 模型初始化
Critic Model（参数更新） ← 从 RM 初始化
Ref Model（冻结）        ← 从 SFT 模型初始化，用于计算 KL 散度
Reward Model（冻结）     ← 从 RM 初始化，用于给出奖励分数
```

（可以补充 PPO 四模型训练流程图）

核心流程：

1. Actor Model 和 Ref Model 对同一 Prompt 分别生成回复
2. 计算两者间的 **KL 散度**——限制 Actor 不要偏离太远
3. Reward Model 对 Actor 回复打分
4. Critic Model 输出累积奖励
5. 综合 KL 散度、奖励分数、累积奖励计算 loss，更新 Actor 和 Critic

**为什么需要 Ref Model？**——防止强化学习过程中模型过度优化奖励，丢失预训练和 SFT 学到的能力。KL 散度惩罚作为"安全绳"。

**算力成本**：以 7B 模型为例，PPO 需约 240G 显存（4 张 80G A100，每张占用 60G）。

#### DPO：RLHF 的平替方案

**DPO（Direct Preference Optimization，直接偏好优化）** 将 RLHF 的强化学习问题转化为监督学习：

- 无需训练 RM
- 只需 2 个模型（比 PPO 少 2 个）
- 训练过程更简单
- 效果与 PPO 相当

## 本讲核心要点

1. **LLM 的定义**：参数≥1B、在数百 B~数 T token 语料上预训练、展现出涌现能力的语言模型；GPT-3（175B）为其开端
2. **涌现能力**是 LLM 与 PLM 的本质区别——相同架构下某些能力在超过某个参数规模时突然出现（相变式跳跃）
3. **上下文学习（ICL）** 改变了 NLP 范式——从"每个下游任务微调一个模型"变为"通过 Prompt + few-shot 示例直接推理"
4. **指令遵循**使 LLM 能理解并执行未见过的自然语言指令，是 ChatGPT 面向大众服务的基础
5. **思维链（CoT）** 通过在 Prompt 中加入中间推理步骤，显著提升 LLM 的复杂推理能力
6. **Scaling Law**（$C \approx 6ND$）揭示了计算量、参数量、数据量之间的最优配比关系
7. **三阶段训练**：Pretrain（知识注入，成本最高）→ SFT（对齐指令格式）→ RLHF（对齐人类价值观）
8. **ZeRO 优化器**通过分片存储模型状态（参数/梯度/Adam 状态）大幅降低显存占用，但分片越多通信开销越大
9. **预训练数据质量**往往比数量更重要，数据处理需经 URL 过滤、语料过滤、语料去重三步
10. **RLHF 的核心是 PPO 四模型架构**——Actor + Critic 参数更新，Ref + Reward 冻结作为"安全绳"
11. **DPO** 将 RLHF 简化为监督学习，无需 RM 和 PPO，以更低成本实现人类偏好对齐
12. **幻觉**是 LLM 的固有缺陷——当前只能通过 RAG、Prompt 约束等方式削弱，无法根除
