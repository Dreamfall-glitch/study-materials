## 1. LLaMA2 模型实现

### 1.1. 超参数配置

搭模型的第一步：确定"房子有多大"——层数多少、每层多宽、词表多大。

```
ModelConfig 好比"施工图纸"：
  dim=768       → 每个词向量 768 维（信息密度）
  n_layers=12   → 堆叠 12 层 Decoder（层层加工）
  n_heads=16    → 注意力分成 16 个头（多角度理解）
  n_kv_heads=8  → 但只有 8 个键值头（GQA 省显存）
  vocab_size=6144 → 词表大小（认识 6144 种 token）
  max_seq_len=512 → 最长理解 512 个词
```

> **通俗理解**：dim 是"信息容器的大小"（每个词用一个 768 维的向量表示），n_layers 是"加工流水线的层数"（数据每过一层就被更深入地理解一次），n_heads 是"同时派出多少个检查员"（每个检查员关注不同的关系）。

### 1.2. RMSNorm——给数据"做标准化"

**为什么要归一化？** 深层网络中，每层的输出分布会随着参数更新不断变化（内部协变量偏移），使得后续层难以学习。归一化把每层输入"拉回"标准范围。

**RMSNorm vs LayerNorm**：可以把两者想象成"温度校准"——

```
LayerNorm：先减均值（校准零点），再除标准差（校准刻度），再加缩放平移
RMSNorm：  只除 RMS（校准刻度），不加零点校准——简化了，但够用
```

$$\boxed{\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{n}\sum_{i=1}^{n}x_i^2 + \epsilon}} \cdot \gamma}$$

```python
class RMSNorm(nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))  # γ，可学习的缩放参数

    def forward(self, x):
        # x.pow(2).mean(-1) → 计算每个样本所有特征维度的平方均值
        # rsqrt → 平方根的倒数，相当于 1/sqrt(...)
        rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return self.weight * (x * rms)
```

**数据形状**：输入 (B, S, dim) → 输出 (B, S, dim)，形状不变，只是每个特征维度的值被重新缩放。

### 1.3. 分组查询注意力（GQA）

#### 从 MHA 到 GQA——为什么需要？

想象你在开会，有 16 个记录员（查询头）在记录会议内容。每个记录员都需要一份会议纪要来参考（KV 缓存）。

```
MHA（原始 Transformer）：16 个记录员 → 16 份纪要 → 占 16 份内存
MQA（多查询注意力）：   16 个记录员 → 共用 1 份纪要 → 省内存但可能漏记
GQA（LLaMA2 的做法）： 16 个记录员 → 分 8 组，每组 2 人共享 1 份纪要 → 内存减半，效果接近 MHA
```

| 方案 | 查询头数 | 键值头数 | 推理内存 | 效果 |
|:----|:--------|:--------|:--------|:----|
| **MHA**（原始 Transformer） | 16 | 16 | 大（16份） | 最好（但最贵） |
| **MQA**（多查询注意力） | 16 | 1 | 最小（1份） | 略差 |
| **GQA**（LLaMA2） | 16 | 8 | 适中（8份） | 接近 MHA |

**GQA 的核心操作：repeat_kv**。键值头只有 8 个，查询头有 16 个，计算注意力时要把 8 个 KV 复制成 16 个，跟查询头对齐。

```python
def repeat_kv(x: torch.Tensor, n_rep: int) -> torch.Tensor:
    # 输入 x: (B, S, 8, 64)   → 8 个键值头，每个 64 维
    # n_rep=2                  → 每个 KV 头需要匹配 2 个 Query 头
    # 输出:   (B, S, 16, 64)   → 复制后变成 16 个，与查询头数对齐
    return (x[:, :, :, None, :]        # 在头维度后插入一维: (B,S,8,1,64)
            .expand(bs, slen, n_kv_heads, n_rep, head_dim)  # 扩展: (B,S,8,2,64)
            .reshape(bs, slen, n_kv_heads * n_rep, head_dim))  # 合并: (B,S,16,64)
```

#### RoPE（旋转位置编码）——给向量"转个角度"

**为什么需要位置编码？** 注意力机制本身对位置不敏感——"我喜欢你"和"你喜欢我"的计算结果一样。位置编码让模型知道"谁在前谁在后"。

>**RoPE 的直观理解**：想象每个词向量是一把"指南针"，位置编码给这把指南针施加了一个"旋转角度"。位置 0 的向量指向正北，位置 1 的向量转了 10 度，位置 2 的转了 20 度……这样两个向量的夹角就自然包含了它们的相对位置。

```
位置 0："我" → 方向↑
位置 1："喜" → 方向↗
位置 2："欢" → 方向→

"我"和"欢"的夹角 = 方向差 = 2步 = 20度
```

**预计算频率**（只算一次，推理时直接查表）：

```python
def precompute_freqs_cis(dim: int, end: int, theta: float = 10000.0):
    # dim=128，end=512（最大序列长度）
    # 生成 64 种不同的旋转频率（dim/2 种），从快到慢
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
    # 对每个位置（0~511），计算角度 = 位置 × 频率
    t = torch.arange(end)
    freqs = torch.outer(t, freqs).float()
    return torch.cos(freqs), torch.sin(freqs)  # (512, 64) cos 和 sin
```

**应用旋转**：

```python
def apply_rotary_emb(xq, xk, freqs_cos, freqs_sin):
    # 把 Q 的最后一维拆成两半：实部(偶数下标)和虚部(奇数下标)
    xq_r, xq_i = xq.float().reshape(*xq.shape[:-1], -1, 2).unbind(-1)
    # 旋转公式（和复数乘法一模一样）：
    # 新实部 = 旧实部 × cos - 旧虚部 × sin
    # 新虚部 = 旧实部 × sin + 旧虚部 × cos
    xq_out = torch.stack([
        xq_r * freqs_cos - xq_i * freqs_sin,   # 旋转后的实部
        xq_r * freqs_sin + xq_i * freqs_cos    # 旋转后的虚部
    ], dim=-1).flatten(3)  # 合并回原始形状
    return xq_out.type_as(xq), xk_out.type_as(xk)
```

> **通俗理解**：RoPE 相当于给每个位置的 Q 和 K 向量装了一个"角度编码器"——位置越近的向量旋转角度越小，位置越远的旋转角度越大。这样注意力计算时，位置相近的词天然获得更高的注意力分数。

#### 完整的 Attention 模块

```python
class Attention(nn.Module):
    def forward(self, x, freqs_cos, freqs_sin):
        # x: (B, S, 768) 
        # → wq/wk/wv 线性投影 → (B, S, 16×64) 共 16 头，每头 64 维
        xq, xk, xv = self.wq(x), self.wk(x), self.wv(x)
        
        # → reshape → (B, S, 16, 64) 拆分成多头
        # → RoPE 旋转位置编码
        xq, xk = apply_rotary_emb(xq, xk, freqs_cos, freqs_sin)
        
        # → repeat_kv（GQA）→ (B, S, 16, 64) Q/K/V 头数对齐
        # → transpose → (B, 16, S, 64) 把"头"维度放到第 1 维
        # → Flash Attention 计算
        output = F.scaled_dot_product_attention(xq, xk, xv, is_causal=True)
        
        # → transpose → (B, S, 16, 64) → view → (B, S, 768) 合并多头
        # → wo 线性投影 → (B, S, 768)
        return self.wo(output)
```

**数据形状变化一览**：

```
输入 x:     (B, S, 768)
  → wq:    (B, S, 768) × (768, 1024) → (B, S, 1024)  [16头×64维]
  → view:  (B, S, 16, 64)
  → RoPE:  (B, S, 16, 64)  [值变了，形状不变]
  → transpose: (B, 16, S, 64)
  → attn:   (B, 16, S, 64)  [注意力加权后的结果]
  → transpose+view: (B, S, 1024)
  → wo:     (B, S, 768)  [恢复原始维度]
```

### 1.4. MLP 模块（SwiGLU）——每个位置的"独立思考"

注意力层让 token 之间"交流信息"，MLP 层让每个 token 在交流完的信息上"独立加工"。

**SwiGLU 的"门控"思想**：

```
传统 MLP（ReLU）： x → W1 → ReLU → W2  （单路径）
SwiGLU（LLaMA2）： x → W1 → SiLU ──┐      （双路径，一条"门"控制另一条）
                    x → W3 ─────────→ × → W2
```

这里的 W3 起到"门"的作用——它决定 W1 的输出有多大比例可以通过。如果门输出接近 0，这条信息就被挡住了；如果门输出接近 1，信息几乎无损通过。

```python
class MLP(nn.Module):
    def forward(self, x):
        # self.w1(x) → (B, S, 2048)  第一个路径，被 SiLU 激活
        # self.w3(x) → (B, S, 2048)  门控路径，没有激活
        # 两者逐元素相乘 → 门控机制
        # self.w2(相乘结果) → (B, S, 768) 投影回原始维度
        return self.dropout(self.w2(F.silu(self.w1(x)) * self.w3(x)))
```

> **通俗理解**：Transformer 的节奏是"交流—思考"交替——注意力层是"开会"（大家互相看对方在说什么），MLP 层是"散会后的个人思考"（每个人自己想想刚才的信息）。SwiGLU 的改进在于给思考过程加了一道"闸门"，能自主决定哪些信息更重要。

### 1.5. Decoder Layer——一次"交流+思考"的完整操作

```python
class DecoderLayer(nn.Module):
    def forward(self, x, freqs_cos, freqs_sin):
        # 第一步：注意力（交流）
        # Pre-Norm：先归一化再进注意力层
        # 残差连接：h = x + attention_output
        h = x + self.attention(self.attention_norm(x), freqs_cos, freqs_sin)
        
        # 第二步：MLP（思考）
        # 同样先归一化，再 MLP，再加残差
        out = h + self.feed_forward(self.ffn_norm(h))
        return out
```

**Pre-Norm 结构** = 先 `Norm` → 再 `子层` → 最后残差 `+`：
```
输入 x ─→ RMSNorm ─→ Attention/MLP ─── + ─→ 输出
                                         ↑
                                        x（原始输入直接加过来）
```

（可以补充 Decoder Layer 结构图）

> **通俗理解**：Pre-Norm 像"先洗手再吃饭"——先确保数据分布干净（归一化），再进行处理。残差连接像"外卖备用通道"——如果今天的菜不好吃，你还有原来的饭可以吃。

### 1.6. 完整 Transformer 模型

**数据全流程**（从输入到输出的每一步形状变化）：

```
输入："你好" → Tokenizer → [2, 48]  （两个 token，id 分别为 2 和 48）
  │
  ▼
Embedding:    (1, 2)     → 查表 → (1, 2, 768)    整数变成 768 维向量
  │
  ▼
Dropout:      (1, 2, 768) →       (1, 2, 768)    随机失活一部分神经元
  │
  ▼
DecoderLayer × 12:        →       (1, 2, 768)    每层"交流+思考"，形状不变
  │   └── 每层内部：
  │        RMSNorm → Attention(self-attn + RoPE) → +
  │        RMSNorm → SwiGLU_MLP                  → +
  │
  ▼
RMSNorm:      (1, 2, 768) →       (1, 2, 768)    最后的归一化
  │
  ▼
Linear:       (1, 2, 768) →       (1, 2, 6144)   映射回词表大小，每个 token 一个概率分布
  │
  ▼
训练模式：计算 cross-entropy loss（预测的 token 跟真实 token 对比）
推理模式：取最后一个位置的 logits → Softmax → 采样下一个 token
```

**权重共享**：Embedding 层和输出 Linear 层共享同一份权重矩阵。因为 Embedding 是把 token_id 变成向量，Linear 是把向量变回 token_id 的概率——本质上是互逆的操作，共享参数既省内存又帮助训练。

**训练 vs 推理的本质区别**：

```
训练：        [我, 喜, 欢, 你] → 模型 → [喜, 欢, 你, ?]  ← 跟真实标签对比算 loss
推理：        [我, 喜, 欢]     → 模型 → [你]  ← 只预测最后一个
  ↓
新输入：      [我, 喜, 欢, 你] → 模型 → [。]  ← 再把预测结果拼回去，继续预测下一个
```

### 1.7. 推理生成——逐 token 的"接龙"

```python
def generate(self, idx, stop_id=None, max_new_tokens=256, temperature=1.0, top_k=None):
    # idx: (1, seq_len) 初始输入的 token 序列
    for _ in range(max_new_tokens):
        # 前向传播，只取最后一个位置的 logits
        logits = self(idx_cond).logits[:, -1, :]  # (1, vocab_size)
        
        if temperature == 0.0:
            # 贪心：每次都选最可能的词
            idx_next = torch.topk(logits, k=1, dim=-1)[1]
        else:
            # 采样：按概率分布随机选，temperature 控制"锐利程度"
            probs = F.softmax(logits / temperature, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
        
        if idx_next == stop_id: break  # 遇到结束符就停止
        idx = torch.cat((idx, idx_next), dim=1)  # 把新 token 拼到序列末尾
    
    return idx[:, index:]  # 只返回新生成的 token
```

**Temperature 的作用**：想象你在玩"词语接龙"——

```
temperature=0.0：                                        永远选最常用的词，确定性输出，但可能单调
temperature=0.7：                 √    √   √      偶尔选冷门但更贴切的词，有创意但不离谱
temperature=1.5：          √     √ √  √ √ √ √ √  什么都可能选出来，可能胡言乱语
temperature=10：   √ √ √ √ √ √ √ √ √ √ √ √ √ √ √  几乎随机输出
```

**KV 缓存（为什么大模型推理需要它）**：

每次生成新 token 时，模型都要重新计算之前所有 token 的 Key 和 Value——但之前的结果其实没变！KV 缓存的做法是：把历史 Key 和 Value 存起来，每次只算新 token 的 Key/Value，直接拼接。

```
无 KV 缓存（当前实现）：
  Step 1: [我]                 → 计算 [我] 的 K,V   → 预测"喜"
  Step 2: [我, 喜]             → 重新计算 [我, 喜] 的 K,V → 预测"欢"  ⚠️ [我]被重复计算了
  Step 3: [我, 喜, 欢]         → 重新计算全部 K,V  → 预测"你"  ⚠️ [我][喜]又被重复计算

有 KV 缓存：
  Step 1: [我]                 → 计算 [我] 的 K,V   → 缓存 [我] 的 K,V
  Step 2: [喜]                 → 只算 [喜] 的 K,V   → 缓存 + [喜] 的 K,V
  Step 3: [欢]                 → 只算 [欢] 的 K,V   → 缓存 + [欢] 的 K,V ✓
```

**习题 1**：7B LLaMA2（dim=4096, n_layers=32, n_heads=32, n_kv_heads=8）。推理序列长 2048，head_dim=128，FP16（2 bytes）。KV 缓存要多少显存？

**解**：
- 每层缓存：Key(1,8,2048,128) + Value(1,8,2048,128) = 2 × 8 × 2048 × 128 × 2 = 8 MB
- 32 层总计：32 × 8 MB = **256 MB**
- 若用 MHA（n_kv_heads=32）：32 × 32 MB = **1 GB**，GQA 省了 75%

## 2. 训练 Tokenizer

### 2.1. 为什么需要 Tokenizer？

**原始问题**：神经网络只认识数字，不认识文字。Tokenizer 就是"翻译官"——把人类写的文字翻译成计算机能算的数字序列。

三种翻译策略：

| 策略 | 举例 | 特点 |
|:----|:-----|:-----|
| **按词切分（Word-based）** | "I love you" → [I, love, you] | 简单但遇到"loved""loving""lovely"就傻了 |
| **按字符切分（Character）** | "love" → [l, o, v, e] | 任何词都能处理，但序列太长（4个字符变4个token） |
| **按子词切分（Subword）** | "unhappiness" → [un, happi, ness] | 平衡前两者，不认识完整词也能拆解出词根+词缀 |

### 2.2. BPE（Byte Pair Encoding）——LLaMA 的选择

**核心思路**：从字符级别开始，反复合并最常见的"字符对"或"字节对"，直到词表达到预设大小。

举个例子，训练数据是 `["low", "lower", "new", "newest"]`：

```
初始词表：所有单个字符 [l, o, w, e, r, n, s, t]

第 1 轮合并：
  统计相邻字符对出现频率：
    "lo" 出现 2 次（low, lower）
    "ow" 出现 2 次（low, lower）
    "ew" 出现 2 次（new, newest）
    ...
  合并最高频对 "lo" → 新增子词 "lo"
  新词表：[l, o, w, e, r, n, s, t, lo]

第 2 轮合并：
  现在 "lo"+"w" 出现 2 次 → 合并为 "low"
  新词表：[l, o, w, e, r, n, s, t, lo, low]

重复...直到词表达到目标大小（如 8192）
```

训练完成后，"lower" 被切分成 `["low", "er"]`——模型虽然没见过"lower"这个词，但认识"low"和"er"这两个子词，就能猜出它的意思。

### 2.3. 训练 BPE 的代码流程

```python
from tokenizers import Tokenizer, models, pre_tokenizers, trainers

# 1. 初始化 BPE 模型
tokenizer = Tokenizer(models.BPE(unk_token="<unk>"))

# 2. 文本预处理
tokenizer.normalizer = NFKC()                       # Unicode 标准化（把"ｈｅｌｌｏ"变成"hello"）
tokenizer.pre_tokenizer = pre_tokenizers.ByteLevel() # 按字节划分（保证对所有字符都有解）

# 3. 定义特殊 token（占用前 5 个 id）
special_tokens = ["<unk>", "<s>", "</s>", "<|im_start|>", "<|im_end|>"]

# 4. 训练
trainer = trainers.BpeTrainer(vocab_size=8192, special_tokens=special_tokens, min_frequency=2)
tokenizer.train_from_iterator(texts, trainer=trainer)

# 5. 保存
tokenizer.save("tokenizer.json")
```

**特殊 token 的作用**：

| Token            | ID  | 含义   | 使用场景             |
| :--------------- | :-- | :--- | :--------------- |
| `<unk>`          | 0   | 未知词  | 遇到词表中没有的字时，用这个代替 |
| `<s>`            | 1   | 序列开始 | 标记一段文本的起点        |
| `</s>`           | 2   | 序列结束 | 标记一段文本的终点        |
| `<\|im_start\|>` | 3   | 对话开始 | 聊天模板中标记消息的起始     |
| `<\|im_end\|>`   | 4   | 对话结束 | 聊天模板中标记消息的结束     |

## 本讲核心要点

1. **搭建 LLaMA2 = 搭积木**：RMSNorm → Attention（含 RoPE + GQA）→ MLP(SwiGLU) → DecoderLayer → Transformer，每一块都有明确的输入/输出形状
2. **RMSNorm** 比 LayerNorm 简单——不做减均值只做除以 RMS，参数更少效果几乎不变
3. **RoPE** 给每个位置的 Q/K 向量"转角度"——位置差编码为角度差，比加位置编码更自然，还能处理比训练更长的序列
4. **GQA** 是 MHA 和 MQA 的折中——键值头少于查询头，用 `repeat_kv` 复制对齐，推理 KV 缓存减少 75%
5. **SwiGLU** 给 MLP 加了"门控"——一个分支做激活，另一个分支做"门"控制信息通过量，效果优于 ReLU
6. **Pre-Norm + 残差连接** = 先归一化再处理，处理完加回原始输入——训练更稳定
7. **训练 vs 推理**：训练时一次算完整序列的 loss；推理时逐 token 生成，每次只取最后一个位置的输出
8. **KV 缓存**把历史的 Key/Value 存起来避免重复计算，是大模型推理加速的核心技术
9. **BPE 分词**从字符开始不断合并最高频的字符对，直到词表达目标大小——不认识完整词就拆成词根+词缀
10. **Tokenizer 的工作流**：标准化(NFKC) → 预分词(ByteLevel) → 训练合并(BPE) → 保存配置
