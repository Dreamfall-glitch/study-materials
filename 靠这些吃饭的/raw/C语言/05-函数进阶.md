# 05-函数进阶

## 知识地图

```
return：结束函数并返回值（void 可提前退出）
    ↓
增量式开发：小步前进，每步编译验证 — Wall 零警告
    ↓
递归 = 边界条件 + 递归关系（层层展开→到达边界→层层返回）
├── 经典例子：阶乘、欧几里德算法
└── 尾递归可优化为循环 / 双递归导致指数级爆炸
```

**本讲回答的核心问题**：return 有哪些用法？什么是高效的编程方法论？递归为什么能解决复杂问题，有什么风险和代价？

## 1. return 语句

### 1.1. 有返回值的函数

```c
/* 求两个整数的最大值 */
int max(int a, int b)
{
    if (a > b)
        return a;
    else
        return b;
}
```

`return` 做了两件事：**结束函数**并把**返回值**交给调用方。

```c
int a = 5, b = 3;
int c = max(a, b) + 1;                   /* c = 6 */
printf("Max is %d\n", max(10, 20));       /* 输出 Max is 20 */
```

### 1.2. void 函数中的 return

`void` 函数也可以使用 `return` 提前退出（不带返回值）：

```c
void print_positive(int x)
{
    if (x <= 0)
        return;             /* 不打印，直接返回 */
    printf("%d is positive\n", x);
}
```

如果 `void` 函数执行到末尾没有 `return`，会自动返回——就像最后有 `return;` 一样。

### 1.3. main 函数的返回值

`main` 函数的返回值告诉操作系统程序的退出状态：

```c
int main(void)
{
    /* ... */
    return 0;    /* 0 表示正常退出 */
}
```

在 Shell 中可以查看：

```
$ ./a.out
$ echo $?
0
```

- `return 0` 或 `return EXIT_SUCCESS`：正常退出
- `return 非0` 或 `return EXIT_FAILURE`：异常退出

### 1.4. 函数返回值的使用场景

函数返回值就是对函数调用表达式"求值"的结果。**调用一个有返回值的函数但不使用它的返回值**是合法的（虽然编译器可能给warning）：

```c
max(3, 5);       /* 合法但无意义，结果被丢弃 */
printf("hello"); /* 也没用到 printf 的返回值（实际打印的字符数） */
```

## 2. 增量式开发

### 2.1. 方法论

**增量式开发**（Incremental Development）是最高效的编程方法论：

> 从一开始就写一个能正确运行的小程序，然后每次只做一个小的改动，立刻编译运行验证。如果出问题，一定是刚刚的小改动导致——错误范围被限缩到最小。

这比"一口气写完几百行再调试"的效率高得多：
- **问题定位快**：错误一定在最近一步中
- **始终有正确版本**：随时可以回退
- **信心递增**：每一步都验证通过，不会积累大量 Bug

Linux 内核就是从"一个交替打印 AAAA 和 BBBB 的小程序"逐步演化而来的上千万行代码。

### 2.2. 实践步骤

**第1步：用注释搭框架**

```c
int main(void)
{
    /* 1. 获取用户输入的两个数 */
    /* 2. 计算最大公约数 */
    /* 3. 打印结果 */
    return 0;
}
```

**第2步：逐步填充，每步验证**

```c
/* 第一步：只验证输入功能 */
int main(void)
{
    int a, b;
    printf("Enter two numbers: ");
    scanf("%d %d", &a, &b);
    printf("You entered: %d and %d\n", a, b);
    return 0;
}

/* 第二步：加入计算逻辑 */
/* 第三步：完善输出格式 */
```

**第3步：始终用 -Wall 编译**

```
$ gcc -Wall main.c -o main
```

零警告才是合格的代码。

## 3. 递归

### 3.1. 递归的本质

**递归**：函数直接或间接地调用自身。递归解决问题的思路是"大事化小"——将原问题分解为规模更小的同类型子问题。

递归必须包含两个要素：

1. **边界条件**（Base Case）：最简单的情形，直接返回结果，不再递归
2. **递归关系**（Recursive Case）：将问题分解，用递归解决更小的子问题

### 3.2. 阶乘——递归的经典例子

```c
int factorial(int n)
{
    if (n == 0)
        return 1;                       /* 边界条件：0! = 1 */
    else
        return n * factorial(n - 1);    /* 递归关系：n! = n × (n-1)! */
}
```

调用 `factorial(3)` 的执行过程：

```
factorial(3)
  = 3 * factorial(2)              ← 展开
  = 3 * (2 * factorial(1))        ← 再展开
  = 3 * (2 * (1 * factorial(0)))  ← 再展开
  = 3 * (2 * (1 * 1))             ← 到达边界 0!=1，开始返回
  = 3 * (2 * 1)                   ← 返回第2层
  = 3 * 2                         ← 返回第1层
  = 6                             ← 最终结果
```

**用纸笔追踪递归**：从目标参数开始，逐层展开，直到边界条件，然后逐层代回计算结果。

### 3.3. 欧几里德算法——尾递归的典范

```c
int gcd(int a, int b)
{
    if (b == 0)
        return a;               /* 边界条件 */
    else
        return gcd(b, a % b);   /* 递归关系：gcd(a,b) = gcd(b, a%b) */
}

gcd(12, 8) → gcd(8, 4) → gcd(4, 0) → 4
```

这个函数是**尾递归**：递归调用是函数的最后一步操作。编译器可以优化尾递归为循环（避免栈溢出）。

### 3.4. 递归 vs 迭代

| 维度 | 递归 | 迭代（循环） |
|------|------|------------|
| 思维模式 | 自顶向下，分而治之 | 自底向上，逐步累积 |
| 代码表达 | 接近数学定义 | 接近执行流程 |
| 效率 | 每次调用有函数开销 | 通常更高效 |
| 栈深度 | 每层占用栈空间，可能溢出 | 固定栈空间 |
| 适用场景 | 树/图遍历、分治算法 | 简单重复、线性处理 |

**选择原则**：
- 能用迭代就用迭代（效率优先）
- 递归结构的数据（树、图）用递归更自然
- 避免"双递归"产生指数级重复计算

### 3.5. 递归的反面教材——斐波那契

```c
/* 这个实现虽然"正确"，但效率灾难！ */
int fib(int n)
{
    if (n <= 1)
        return n;
    return fib(n - 1) + fib(n - 2);  /* 指数级 O(2ⁿ) 时间复杂度！ */
}
```

`fib(5)` 的计算会重复计算 `fib(3)` 两次、`fib(2)` 三次——随着 n 增大，重复计算呈爆炸式增长。

**改进方案**：

```c
int fib_iter(int n)         /* 迭代版：O(n) */
{
    int a = 0, b = 1;
    for (int i = 0; i < n; i++) {
        int tmp = a + b;
        a = b;  b = tmp;
    }
    return a;
}
```

## 本讲核心要点

1. **return 结束函数并返回一个值**到调用处；void 函数可用 `return;` 提前退出
2. **main 返回 0** 表示正常退出，非 0 表示错误，Shell 中用 `$?` 查看
3. **增量式开发**：从能运行的小版本开始，每改一步编译验证一次，出错窗口极小
4. **先写注释搭框架**，再逐步填充代码；始终加 `-Wall` 确保零警告
5. **递归 = 边界条件 + 递归关系**；执行过程是"层层展开 → 到达边界 → 层层返回"
6. **递归有函数调用开销和栈溢出风险**：每层占用栈空间，深度过大会崩溃
7. **尾递归**（递归在最后一步）可以被编译器优化为迭代
8. **斐波那契递归是反面教材**——双递归导致指数级重复计算，应改用迭代

## 习题

**1. 用递归实现计算 1+2+...+n。**

```c
int sum(int n)
{
    if (n == 1)
        return 1;               /* 边界条件 */
    return n + sum(n - 1);      /* 递归关系 */
}
```

**2. 用迭代重写上述递归。**

```c
int sum_iter(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}
```
