# 01-程序与C语言概述

## 知识地图

```
程序 = 指令的有序集合（输入→运算→输出→分支→循环）
    ↓
低级语言（机器/汇编）→ 高级语言（C/C++/Python）
    ↓
C语言：编译执行、可移植、贴近硬件
    ↓
源代码 → 编译 → 可执行文件 → 运行
    ↓
三类错误：编译时错误 → 运行时错误 → 逻辑错误
```

**本讲回答的核心问题**：什么是程序？编程语言如何分类？C语言处于什么位置？写第一个C程序需要了解哪些基本工具和概念？

---

## 1. 程序与编程语言

### 1.1. 什么是程序

程序（Program）告诉计算机应如何完成一个计算任务。这个"计算"可以是数学运算（如解方程），也可以是符号运算（如查找替换单词），还可以处理声音和图像——因为声音和图像在计算机内部也是用数字表示的。

程序由一系列**指令**（Instruction）组成，指令是指示计算机做某种运算的命令。所有程序都可以归纳为五类指令：

- **输入（Input）**：从键盘、文件或其它设备获取数据
- **输出（Output）**：把数据送到屏幕、文件或其它设备
- **基本运算**：数学运算（加减乘除）和数据存取
- **测试和分支**：根据条件判断，执行不同的后续指令
- **循环**：重复执行一系列操作

> 通俗理解：编写程序就是把复杂任务层层分解为子任务，直到每一步都简单到可以用这五类指令来完成。

### 1.2. 低级语言与高级语言

编程语言分为两大类：

| 类别 | 代表语言 | 特点 | 执行方式 |
|------|---------|------|---------|
| 低级语言 | 机器语言、汇编语言 | 直接用计算机指令编写，一条语句对应一条或多条指令 | 汇编→机器码→执行 |
| 高级语言 | C、C++、Java、Python | 用人类可读的语句编写，一条语句对应多条机器指令 | 编译或解释后执行 |

以 `a = b + 1` 为例，三种语言的对比：

| 编程语言 | 表示形式 |
|----------|---------|
| C语言 | `a = b + 1;` |
| 汇编语言 | `mov 0x804a01c, %eax` / `add $0x1, %eax` / `mov %eax, 0x804a018` |
| 机器语言 | `a1 1c a0 04 08` / `83 c0 01` / `a3 18 a0 04 08` |

**机器语言**完全由十六进制数字组成。最早的程序员直接用它编程，需要查大量表格来确定每个数字的含义，很不直观且容易出错。

**汇编语言**用助记符（Mnemonic）替代数字，比如 `mov` 表示移动数据，`add` 表示加法。汇编器（Assembler）负责把助记符替换成机器码——汇编语言和机器语言是一一对应的。

**C语言的一条语句可能对应多条汇编指令**。从C语言到机器指令的过程称为**编译**（Compile），由编译器（Compiler）完成。

### 1.3. 编译执行 vs 解释执行

**编译执行**（C语言方式）：
1. 用文本编辑器写源代码（`.c` 文件）
2. 编译器一次性将所有源代码翻译成机器指令
3. 生成可执行文件（如 `a.out`）
4. 操作系统加载可执行文件运行

**解释执行**（Shell/Python方式）：
1. 写脚本（如 `script.sh`）
2. 解释器逐行读取并执行，不生成独立的可执行文件
3. 每次运行都需要解释器参与

对比：

| 维度 | 编译执行 | 解释执行 |
|------|---------|---------|
| 执行效率 | 高（预翻译完成） | 低（边翻译边执行） |
| 开发效率 | 低（需编译等待） | 高（改完即运行） |
| 平台无关性 | 源代码可移植（重新编译） | 只要有解释器就能运行 |

### 1.4. C语言的可移植性

**可移植性（Portability）**是指同一份源代码能在不同平台编译运行。不同的计算机体系结构有不同的指令集，直接用汇编写的程序只能在该体系结构上运行。但各种体系结构都有各自的C编译器，可以把C程序编译成不同的机器指令——这意味着C程序只需稍加修改甚至不用修改，就能跨平台运行。

> 注意：即使在相同的体系结构和操作系统下，不同编译器对C语言某些未明确定义的语法特性也可能有不同的实现，应尽量避免使用不可移植的语法。

## 2. 自然语言与形式语言

### 2.1. 概念区分

**自然语言**（Natural Language）：人类日常交流的语言（汉语、英语等），自然进化而来，充满歧义和冗余。

**形式语言**（Formal Language）：为特定目的人为设计的语言（数学公式、化学分子式、编程语言），语法严格、无歧义。

### 2.2. 形式语言的三要素

编程语言作为一种形式语言，有三个层面：

- **词法（Lexical）**：Token的规则——哪些符号是合法的（如 `3+3=6` 合法，`3=+6$` 不合法，因为 `$` 不是合法运算符）
- **语法（Grammar）**：Token排列结构的规则（如 `3=+6` 的问题在于等号后面不能紧跟加号）
- **语义（Semantic）**：语句的含义——即使语法正确，程序是否做了你想要的事

### 2.3. 阅读程序的方法

形式语言远比自然语言紧凑，阅读时应注意：
1. 多花时间慢慢读
2. 不要从上到下逐行读，而要在大脑里解析结构
3. 细节很重要——拼写错误和标点错误在自然语言中可忽略，在形式语言中会使整段代码面目全非

## 3. 程序的调试

### 3.1. 三类错误

程序中的错误（Bug）分为三类，从易到难：

**（1）编译时错误（Compile-time Error）**
编译器检查出的语法错误，无法生成可执行文件。这是最初级的错误，熟悉后很容易定位和修复。

**（2）运行时错误（Run-time Error）**
编译通过但在运行时报错导致程序崩溃，如段错误（Segmentation Fault）、除零错误等。

**（3）逻辑错误和语义错误（Logic Error）**
程序编译运行一切正常，但输出结果不是预期的——程序没有做你想要的，而是做了你写的。这类错误最难排查，需要反向推断程序的实际行为。

### 3.2. 调试思想

调试就像侦探工作——根据线索推断原因，验证假设，逼近真相。核心方法：

**增量式开发**：始终从一个能正确运行的小程序开始，每次只做一小步改动就立刻编译调试。如果出错，一定是刚才的改动导致的。

### 3.3. 编译警告的重要性

编译器提示的信息分两种：

- **error**：致命错误，编译中止
- **warning**：警告信息，编译继续但程序可能有Bug

好的习惯是**始终加上 `-Wall` 选项**，让编译器提示所有警告：

```
gcc -Wall main.c
```

即使程序能编译运行，警告信息也可能暗示着潜在的运行时错误或逻辑错误。

## 4. 第一个C程序

### 4.1. Hello World

```c
#include <stdio.h>

/* main: generate some simple output */
int main(void)
{
    printf("Hello, world.\n");
    return 0;
}
```

保存为 `main.c`，编译运行：

```
$ gcc main.c -o main
$ ./main
Hello, world.
```

### 4.2. 逐行解读

| 代码行 | 含义 |
|-------|------|
| `#include <stdio.h>` | 包含标准输入输出头文件，使 `printf` 可用 |
| `/* ... */` | 注释，编译器忽略，写给人类看的 |
| `int main(void)` | 主函数，程序从这里开始执行 |
| `{` ... `}` | 函数体的边界，大括号内的语句属于 `main` |
| `printf("...\n");` | 向屏幕输出字符串，`\n` 是换行符 |
| `return 0;` | 向操作系统返回 0，表示程序正常结束 |
| 每行末尾的 `;` | C语言语句的结束符（分号） |

**缩进（Indentation）**：用空格或Tab表示代码的层级关系。`printf` 和 `return` 相对于 `main` 缩进一级，表明它们属于 `main` 函数体。缩进不是语法要求，但对可读性至关重要。

### 4.3. 编译器错误提示解读

如果写错了头文件名，编译器会报错：

```
$ gcc main.c
main.c:1:19: error: stdoi.h: No such file or directory
```

错误提示的格式为：`文件名:行号:列号: 错误类型: 错误描述`。即使提示不够友好，也应该学会从这些线索中推理出真正的问题。

## 本讲核心要点

1. **程序**由五类指令组成——输入、输出、基本运算、测试分支、循环，写程序就是层层分解复杂任务
2. **机器语言→汇编语言→高级语言**：从直接操作指令到用语句表达，一条C语句可能对应多条机器指令
3. **编译执行**（C）先生成可执行文件再运行，**解释执行**（Shell/Python）逐行解释运行
4. **C语言的可移植性**：同一份源代码可在不同体系结构的计算机上编译运行
5. **形式语言**无歧义、语法严格；阅读代码时要解析结构而非逐行读
6. **三类Bug**：编译时错误（语法）、运行时错误（崩溃）、逻辑错误（结果不对），难度递增
7. **增量式开发**：每次只改一小步立即调试，出问题一定是刚刚的改动导致的
8. **始终使用 `gcc -Wall`** 编译，把所有警告消灭在萌芽中
9. **第一个C程序**：`main` 函数是入口，`printf` 输出，`return 0` 表示正常退出
10. **缩进和分号**是C程序的基本书写规范，虽非语法必须但影响可读性

## 习题

**解释执行的语言相比编译执行的语言有什么优缺点？**

**答**：

| 维度 | 编译执行 | 解释执行 |
|------|---------|---------|
| 执行效率 | 高，运行前已完成全部翻译 | 低，运行中边翻译边执行 |
| 开发调试 | 慢，修改后需重新编译 | 快，改完即运行 |
| 平台无关性 | 源代码可移植，各平台重新编译 | 只要有对应解释器即可运行 |
| 发布部署 | 分发可执行文件即可 | 需要目标机器安装解释器 |
| 错误发现 | 编译阶段就能发现语法错误 | 跑到出错那行才会报错 |
