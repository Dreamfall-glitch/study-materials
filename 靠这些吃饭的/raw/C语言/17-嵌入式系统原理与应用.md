# 17-嵌入式系统原理与应用

## 知识地图

```
【内核与架构】
ARM Cortex-M3内核(STM32F103) → 总线矩阵(AHB/APB) → 存储器映射(Flash/SRAM/外设)
    ↓
【编程方法】
三种编程方式：寄存器编程 → 标准库(StdPeriph) → HAL库(抽象层次递增)
    ↓
【时钟与基础】
时钟树RCC(HSE→PLL→SYSCLK→AHB→APB1/APB2) → 外设时钟门控(逐个使能)
    ↓
【核心外设】
GPIO(8种模式) → 中断EXTI + NVIC(优先级分组/抢占/子优先级) → SysTick
    ↓
【高级外设】
定时器(基本/通用/高级) → PWM/输入捕获/编码器 → DMA(外设↔内存自动搬运)
    ↓
【通信接口】
通信：UART/USART/SPI/I2C → ADC/DAC(模拟接口) → 看门狗 + RTC + 低功耗模式
    ↓
【系统与调试】
FreeRTOS：任务调度 → 队列/信号量 → 中断保护 → 调试(SWD + HardFault追踪)
```

**本讲回答的核心问题**：STM32 的外设操作在寄存器级、标准库、HAL 库三个层次上各是怎样的？STM32F103 的时钟树和 APB 总线如何影响外设配置？DMA 如何将嵌入式程序的实时性带入新高度？

---

## 1. 内核与架构

### 1.1. 芯片定位与选型

STM32F103 基于 ARM Cortex-M3 内核，是 ST 最经典的 Cortex-M 系列芯片，也是学习嵌入式开发的理想入门平台。

**为什么选择 STM32F103C8T6 作为学习起点？**
- 内核简单清晰（Cortex-M3），没有 MMU 干扰
- 外设完整（定时器、ADC、DMA、各种通信接口齐全）
- 资料极其丰富，价格低廉
- 从 F103 学透后再迁移到 F4/H7/F0 都很容易

| 特性 | STM32F103C8T6 |
|:-----|:-------------|
| 内核 | ARM Cortex-M3, 72MHz |
| Flash | 64KB / 128KB |
| SRAM | 20KB |
| GPIO | 最多37个 |
| 定时器 | 2个高级TIM1/8 + 3个通用TIM2-4 + 1个基本TIM6 |
| ADC | 2个12位ADC(最多16通道) |
| 通信 | USART×3, SPI×2, I2C×2, CAN×1, USB×1 |
| 封装 | LQFP48 |

### 1.2. 总线架构：理解数据如何流动

总线架构决定了 CPU 如何访问 Flash、SRAM 和外设。理解总线矩阵是理解 STM32 性能瓶颈的第一步。

stm32总线结构图

**两条 APB 总线的区别**：

| 总线 | 最大频率 | 典型外设 | 为什么频率不同？ |
|:-----|:--------|:--------|:---------------|
| APB1（低速总线） | 36MHz | TIM2-7, USART2-3, I2C1-2, CAN, USB | 降低功耗，这些外设对速度要求不高 |
| APB2（高速总线） | 72MHz | GPIOA-G, TIM1/8, USART1, SPI1, ADC1-2 | 高速外设需要更高时钟（如 SPI 通信、ADC 采样） |

> **关键点**：当你配置一个外设时，必须先查手册确认它在哪条总线上——这决定了你能给它多高的时钟频率。

### 1.3. 存储器映射：软件如何看到硬件

Cortex-M3 使用统一编址——外设寄存器和内存都在同一个 4GB 地址空间中。

| 地址区间 | 映射对象 | 说明 |
|:--------|:--------|:-----|
| 0x0000_0000 | 根据BOOT引脚映射 | 启动时的别名区，实际指向 0x0800_0000 或 0x2000_0000 |
| 0x0800_0000 | 片内 Flash | 主程序存储，64KB/128KB，只读（除非进行 Flash 编程） |
| 0x1FFF_F000 | System Memory | ST 自举程序，出厂烧录，串口 ISP 下载用 |
| 0x2000_0000 | SRAM | 20KB，可读可写，存放全局变量、栈、堆 |
| 0x4000_0000 | APB1 外设寄存器 | 低速外设的控制寄存器 |
| 0x4001_0000 | APB2 外设寄存器 | 高速外设的控制寄存器 |
| 0xE000_E000 | Cortex-M3 系统控制块 | NVIC、SysTick、SCB（内核自己） |

> **为什么理解存储器映射很重要？**
> 
> 当你写 `*(volatile uint32_t*)0x40021018 |= (1 << 3)` 时，你是在直接操作物理地址 0x40021018——这个地址就是 RCC_APB2ENR 寄存器。不理解映射，寄存器编程就无从谈起。

## 2. 三种编程范式

STM32 开发经历了三个层次的抽象，从直接操作寄存器到 HAL 库的自动化。理解这三层，你就理解了嵌入式软件工程的发展脉络。

### 2.1. 第一层：寄存器级编程（完全控制）

直接操作外设的物理地址，零中间层开销，代码读起来最接近参考手册。

```c
// 寄存器级：点亮 PB5 上的 LED
*(volatile uint32_t*)0x40021018 |= (1 << 3);  // RCC_APB2ENR 打开 GPIOB 时钟
*(volatile uint32_t*)0x40010C00 &= ~(3 << 10);  // GPIOB_CRL 清零PB5配置位
*(volatile uint32_t*)0x40010C00 |=  (2 << 20);  // GPIOB_CRL PB5=推挽输出2MHz
*(volatile uint32_t*)0x40010C10 |=  (1 << 5);   // GPIOB_BSRR 置位PB5(输出高)
```

**优点**：
- 执行效率最高（编译为单条 STR/LDR 指令）
- 代码体积最小（无函数调用开销）
- 让你真正理解硬件工作原理

**缺点**：
- 可读性极差（0x40021018 是什么？1<<3 又是什么？）
- 移植性极差（STM32F1 和 F4 的寄存器地址不同）
- 开发效率低（每个外设都要查手册）

**寄存器映射的本质**：ST 在头文件 `stm32f10x.h` 中以宏和结构体指针将外设寄存器映射到存储器地址：

```c
#define PERIPH_BASE    0x40000000U
#define APB1PERIPH_BASE (PERIPH_BASE)
#define APB2PERIPH_BASE (PERIPH_BASE + 0x10000)
#define GPIOB_BASE      (APB2PERIPH_BASE + 0x0C00)
#define GPIOB           ((GPIO_TypeDef *)GPIOB_BASE)

typedef struct {
    volatile uint32_t CRL;   // 偏移 0x00
    volatile uint32_t CRH;   // 偏移 0x04
    volatile uint32_t IDR;   // 偏移 0x08
    volatile uint32_t ODR;   // 偏移 0x0C
    volatile uint32_t BSRR;  // 偏移 0x10
    volatile uint32_t BRR;   // 偏移 0x14
    volatile uint32_t LCKR;  // 偏移 0x18
} GPIO_TypeDef;
// GPIOB->ODR = 0x0001; 等同于 *(0x40010C00+0x0C) = 0x0001
```

### 2.2. 第二层：标准外设库（StdPeriph_Lib，平衡）

标准库是对寄存器的一层封装——用函数名替代寄存器名，用宏替代魔数。

**标准库命名规则**：`<外设缩写>_<操作>`（如 `GPIO_Init`, `USART_SendData`）

```c
// 标准库：与寄存器相同功能 — 点亮 PB5 LED
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);  // 打开 GPIOB 时钟

GPIO_InitTypeDef GPIO_InitStructure;
GPIO_InitStructure.GPIO_Pin  = GPIO_Pin_5;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;        // 推挽输出
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOB, &GPIO_InitStructure);
GPIO_SetBits(GPIOB, GPIO_Pin_5);                        // 输出高
```

**核心外设标准库 API 速查**：

```c
// GPIO —— 输入输出控制
GPIO_Init(GPIOB, &GPIO_InitStructure);              // 初始化引脚
uint8_t val = GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0); // 读单个输入引脚
uint16_t val = GPIO_ReadInputData(GPIOA);            // 读整个端口
GPIO_SetBits(GPIOB, GPIO_Pin_5);                     // 输出高电平
GPIO_ResetBits(GPIOB, GPIO_Pin_5);                   // 输出低电平
GPIO_WriteBit(GPIOB, GPIO_Pin_5, Bit_SET);           // 按位写入

// USART —— 串行通信
USART_Init(USART1, &USART_InitStructure);            // 初始化串口
USART_SendData(USART1, 0x55);                        // 发送一个字节
while (!USART_GetFlagStatus(USART1, USART_FLAG_TXE)); // 等待发送缓冲区空
uint8_t rx = USART_ReceiveData(USART1);              // 接收一个字节

// 定时器 —— 时间基准和 PWM
TIM_TimeBaseInit(TIM2, &TIM_TimeBaseStructure);      // 时基初始化
TIM_OC1Init(TIM2, &TIM_OCInitStructure);             // PWM 输出通道配置
TIM_Cmd(TIM2, ENABLE);                               // 使能定时器

// ADC —— 模数转换
ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5);
ADC_SoftwareStartConvCmd(ADC1, ENABLE);
while (!ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC));      // 等待转换完成
uint16_t val = ADC_GetConversionValue(ADC1);
```

**优点**：
- 代码可读性大幅提升（函数名告诉你它在做什么）
- 开发效率高（不用每个寄存器都查手册）
- STM32F1 时代的事实标准

**缺点**：
- 只能用于 F1/F2/F4 等老系列
- 代码体积比寄存器版略大
- 跨系列移植需要重写

### 2.3. 第三层：HAL 库（最高抽象）

HAL（Hardware Abstraction Layer）库是对标准库的进一步抽象——隐藏了具体的寄存器操作细节，提供统一的 API 风格。

```c
// HAL库：与标准库相同功能
__HAL_RCC_GPIOB_CLK_ENABLE();  // 打开GPIOB时钟

GPIO_InitTypeDef GPIO_Init = {0};
GPIO_Init.Pin   = GPIO_PIN_5;
GPIO_Init.Mode  = GPIO_MODE_OUTPUT_PP;
HAL_GPIO_Init(GPIOB, &GPIO_Init);
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_5, GPIO_PIN_SET);
```

**优点**：
- API 统一，STM32 全系列通用
- 提供了很多高级功能（如超时机制、中断回调）
- CubeMX 图形化配置，自动生成初始化代码

**缺点**：
- 代码体积大（多层调用和状态机）
- 执行效率低于标准库
- 调试时难以追踪到底层

### 2.4. 三种方式的对比与选择建议

| 维度 | 寄存器编程 | 标准库 StdPeriph | HAL 库 |
|:-----|:---------|:---------------|:------|
| 代码可读性 | 差（魔数遍布） | 中（函数名有意义） | 好（API 一致性强） |
| 代码体积 | 最小 | 中等 | 较大 |
| 执行速度 | 最快（直接 STR） | 快 | 中等 |
| 移植性 | 极差 | 弱（只支持 F1/F2/F4） | 好（全系列统一） |
| 学习价值 | 理解硬件本质 | 理解外设操作逻辑 | 学会抽象思维 |
| 入门门槛 | 高（需要手册） | 中 | 低（CubeMX 自动生成） |

**学习路线建议**：
1. **先用标准库**学习每个外设——理解 GPIO 怎么初始化、定时器怎么配
2. **再回看寄存器**理解底层——为什么 CRL 写 0x2 是推挽输出？
3. **工作中用 HAL + CubeMX**——提高生产力，需要优化时再改寄存器

## 3. 时钟树（RCC）

时钟是单片机的心脏。不理解时钟树，外设配置就是瞎猜。

时钟树图

### 3.1. F103 时钟源：四个振荡器

STM32F103 有四个时钟源，两个外部（需要晶振）、两个内部（RC 振荡器）：

| 时钟源 | 频率 | 精度 | 典型用途 |
|:-------|:-----|:-----|:---------|
| HSE（外部高速晶振） | 4-16MHz（典型8MHz） | ±50ppm | PLL 输入，产生系统时钟 |
| HSI（内部高速 RC） | 8MHz | ±1%（温漂大） | 启动时钟，低精度场景 |
| LSE（外部低速晶振） | 32.768KHz | ±10ppm | RTC 时钟 |
| LSI（内部低速 RC） | 40KHz | ±5% | 独立看门狗 IWDG |

### 3.2. 系统时钟路径：从晶振到外设

系统时钟（SYSCLK）最高 72MHz，经过分频后分配给 AHB、APB1、APB2：

```
SYSCLK(72MHz)
    │
    ▼
┌───────────────────────────────────────────────────────────┐
│ AHB 预分频器 (HPRE)                                        │
│   可选分频：1, 2, 4, 8, 16, 64, 128, 256, 512             │
│   输出 HCLK = SYSCLK / HPRE                                │
└───────────────────────────────────────────────────────────┘
    │
    ├──→ HCLK ──→ Cortex-M3 内核、存储器、DMA
    │
    ├──→ SysTick 定时器 (可选择 HCLK/8 或 HCLK)
    │
    ├──→ APB1 预分频器 (PPRE1)
    │       可选分频：1, 2, 4, 8, 16
    │       输出 PCLK1 = HCLK / PPRE1  (最大 36MHz)
    │       连接到：TIM2-7, USART2-3, I2C1-2, CAN, USB
    │
    └──→ APB2 预分频器 (PPRE2)
            可选分频：1, 2, 4, 8, 16
            输出 PCLK2 = HCLK / PPRE2  (最大 72MHz)
            连接到：GPIOA-G, TIM1/8, USART1, SPI1, ADC1-2
```

### 3.3. 标准库时钟配置（完整示例）

```c
// F103 标准库时钟配置 — 将系统时钟配置到 72MHz
void RCC_Configuration(void) {
    // 1. 复位 RCC 配置到默认值
    RCC_DeInit();
    
    // 2. 开启外部高速晶振 HSE
    RCC_HSEConfig(RCC_HSE_ON);
    while (RCC_GetFlagStatus(RCC_FLAG_HSERDY) == RESET);  // 等待 HSE 就绪
    
    // 3. 配置 Flash 等待周期（72MHz 需要 2 个等待周期）
    //    ⚠️ 忘记这一行，程序会在 72MHz 下随机跑飞！
    FLASH_SetLatency(FLASH_Latency_2);
    FLASH_PrefetchBufferCmd(FLASH_PrefetchBuffer_Enable);
    
    // 4. 配置 PLL：HSE(8MHz) ÷1 ×9 = 72MHz
    RCC_PLLConfig(RCC_PLLSource_HSE_Div1, RCC_PLLMul_9);
    RCC_PLLCmd(ENABLE);
    while (RCC_GetFlagStatus(RCC_FLAG_PLLRDY) == RESET);
    
    // 5. 配置 AHB/APB 分频
    RCC_HCLKConfig(RCC_SYSCLK_Div1);    // AHB(HCLK) = 72MHz
    RCC_PCLK2Config(RCC_HCLK_Div1);     // APB2(PCLK2) = 72MHz (高速外设)
    RCC_PCLK1Config(RCC_HCLK_Div2);     // APB1(PCLK1) = 36MHz (低速外设)
    
    // 6. 切换系统时钟到 PLL
    RCC_SYSCLKConfig(RCC_SYSCLKSource_PLLCLK);
    while (RCC_GetSYSCLKSource() != 0x08);  // 0x08 表示 PLL 为系统时钟
}
```

> **FLASH 等待周期的原理**：
> 
> Flash 的读取速度比 CPU 慢。当 CPU 频率超过 Flash 的访问速度时，必须插入等待周期。STM32F103 的 Flash 访问时间为 1 等待周期 @ 24MHz、2 等待周期 @ 72MHz。
> 
> **忘记设置等待周期** → CPU 读取 Flash 得到错误数据 → 执行非法指令 → HardFault 或程序跑飞。

### 3.4. 外设时钟使能：新手杀手

在 STM32 中，**任何外设在被操作之前，它的时钟必须被显式地使能**。这是一个"新手杀手"级的设计特性——忘记使能时钟，外设寄存器写不进去、读出来全是 0。

```c
// 寄存器级 — 直接操作 RCC 寄存器
RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;    // 使能 GPIOB 时钟
RCC->APB2ENR |= RCC_APB2ENR_USART1EN;  // 使能 USART1 时钟

// 标准库 — 使用封装好的函数
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB | RCC_APB2Periph_USART1, ENABLE);

// HAL库 — 使用宏
__HAL_RCC_GPIOB_CLK_ENABLE();
__HAL_RCC_USART1_CLK_ENABLE();
```

**常见外设的总线归属速查表**：

| 总线 | 外设 | 常用 |
|:-----|:-----|:-----|
| APB2 (72MHz) | GPIOA, GPIOB, GPIOC, GPIOD, GPIOE, GPIOF, GPIOG | ⭐ 必须 |
| APB2 (72MHz) | TIM1, TIM8, USART1, SPI1, ADC1, ADC2, AFIO | ⭐ 常用 |
| APB1 (36MHz) | TIM2, TIM3, TIM4, USART2, USART3, UART4, UART5 | ⭐ 常用 |
| APB1 (36MHz) | SPI2, SPI3, I2C1, I2C2, CAN, USB, RTC, WWDG | |
| AHB | DMA1, DMA2, FSMC, SDIO, CRC, FLASH 接口 | |

> **调试技巧**：如果外设不工作，第一件事就是检查对应的时钟使能位是否置 1。

## 4. 启动过程与系统控制

### 4.1. 上电启动序列（硬件自动完成）

系统上电后，Cortex-M3 硬件自动执行以下序列：

1. 从地址 `0x0000_0000` 读取堆栈指针 MSP 的初始值
2. 从地址 `0x0000_0004` 读取复位向量（Reset_Handler 的地址）
3. 跳转到 Reset_Handler 执行

**启动文件（startup_stm32f10x_md.s）中的 Reset_Handler**：

```assembly
Reset_Handler:
    ; 1. 调用 SystemInit() 配置时钟
    LDR     R0, =SystemInit
    BLX     R0
    
    ; 2. 调用 __main（C 运行时初始化）
    ;    — 将 .data 段从 Flash 复制到 SRAM
    ;    — 将 .bss 段清零
    ;    — 初始化堆和栈
    LDR     R0, =__main
    BX      R0
    
    ; 3. 最后跳转到 main()
```

### 4.2. BOOT 引脚：决定从哪里启动

| BOOT1 | BOOT0 | 启动模式 | 含义 |
|:------|:------|:--------|:-----|
| x | 0 | Flash | 正常运行，从用户程序启动（0x0800_0000） |
| 0 | 1 | System Memory | ST 自举程序，通过 USART1 下载程序 |
| 1 | 1 | SRAM | 从 SRAM 启动（调试用，可以无限次烧录） |

> **串口 ISP 下载流程**：
> 1. 设 BOOT0=1，BOOT1=0（System Memory 模式）
> 2. 复位芯片，等待自举程序运行
> 3. 用串口工具（如 FlyMCU）通过 USART1 下载程序
> 4. 下载完成后恢复 BOOT0=0，复位运行用户程序

### 4.3. 中断向量表：中断是如何找到处理函数的

中断向量表位于 Flash 的起始地址（0x0800_0000），每个中断源对应一个 4 字节的函数地址。

```c
// stm32f10x_it.h 中的中断服务函数原型
// 系统异常（Cortex-M3 内核）
void NMI_Handler(void);           // 不可屏蔽中断
void HardFault_Handler(void);     // 硬故障（最常见的程序错误）
void MemManage_Handler(void);     // MPU 访问违例
void BusFault_Handler(void);      // 总线错误
void UsageFault_Handler(void);    // 用法错误（未定义指令等）
void SVC_Handler(void);           // 系统调用
void PendSV_Handler(void);        // 可挂起的系统调用（RTOS 上下文切换用）
void SysTick_Handler(void);       // 系统定时器

// 外设中断（STM32F103 共 43+ 个）
void USART1_IRQHandler(void);      // USART1 中断
void TIM2_IRQHandler(void);        // TIM2 中断
void EXTI0_IRQHandler(void);       // 外部中断线 0
void DMA1_Channel1_IRQHandler(void); // DMA 通道 1 中断
```

 **HardFault 调试技巧**：

当程序进入 HardFault，可以从栈帧中恢复出错的 PC 寄存器：
 
```c
 // 在 HardFault_Handler 中加断点，查看 MSP 指向的内存
void HardFault_Handler(void) {
	uint32_t *stack = (uint32_t*)__get_MSP();
    uint32_t pc = stack[6];  // 栈帧中的 PC 位置
    // pc 指向出错的指令地址，可以在 .map 文件中查找对应的函数
    while(1);
 }
```

## 5. 核心外设详解

### 5.1. GPIO：8 种模式的完整理解

STM32F103 的每个 GPIO 引脚由 4 个位（CNF[1:0] 和 MODE[1:0]）配置，通过 `GPIOx_CRL`（引脚 0-7）和 `GPIOx_CRH`（引脚 8-15）寄存器控制。

**8 种配置模式速查表**：

| CNF1 | CNF0 | MODE1 | MODE0 | 模式 | 典型应用 | 输出驱动器状态 |
|:----:|:----:|:-----:|:-----:|:-----|:---------|:--------------|
| 0 | 0 | 0 | 0 | 模拟输入 | ADC 输入 | 关闭（高阻） |
| 0 | 1 | 0 | 0 | 浮空输入 | 默认复位状态 | 关闭 |
| 1 | 0 | 0 | 0 | 上拉/下拉输入 | 按键输入（需外部或内部上拉） | 关闭 |
| 0 | 0 | 0 | 1 | 通用推挽输出 @10MHz | LED、继电器 | 推挽 MOS 管 |
| 0 | 0 | 1 | 0 | 通用推挽输出 @2MHz | 低速信号 | 推挽 MOS 管 |
| 0 | 0 | 1 | 1 | 通用推挽输出 @50MHz | 高速信号 | 推挽 MOS 管 |
| 0 | 1 | 0 | 1 | 通用开漏输出 @10MHz | I2C（需外接上拉） | NMOS 开漏 |
| 1 | 0 | 0 | 1 | 复用推挽输出 @10MHz | UART/SPI 外设引脚 | 推挽（由外设控制） |
| 1 | 1 | 0 | 1 | 复用开漏输出 @10MHz | I2C 外设引脚 | 开漏（由外设控制） |

**快速选择指南**：
- **输出一个信号给其他芯片**：推挽输出
- **I2C 通信**：开漏输出（硬件 I2C 用复用开漏，软件模拟用通用开漏）
- **读取外部电平**：输入模式（按键用上拉/下拉输入，无外部确定电平用浮空输入）
- **ADC 采样**：模拟输入
- **引脚给外设使用（UART/SPI/TIM 等）**：复用功能输出

> **注意**：输出速度（2/10/50MHz）只在输出模式下有意义。输入模式下输出驱动器是关闭的，速度配置无效。

### 5.2. NVIC 与 EXTI：中断系统完整理解

#### NVIC 优先级分组

Cortex-M3 的 NVIC 支持 **4-bit 优先级域**，由应用通过 `SCB->AIRCR` 决定如何将这 4 比特分配为抢占优先级和子优先级。

| 优先级分组 | AIRCR[10:8] | 抢占优先级位数 | 子优先级位数 | 抢占优先级取值范围 | 子优先级取值范围 |
|:----------|:-----------|:-------------:|:-----------:|:----------------:|:----------------:|
| NVIC_PriorityGroup_0 | 7 | 0 | 4 | 0 | 0-15 |
| NVIC_PriorityGroup_1 | 6 | 1 | 3 | 0-1 | 0-7 |
| NVIC_PriorityGroup_2 | 5 | 2 | 2 | 0-3 | 0-3 |
| NVIC_PriorityGroup_3 | 4 | 3 | 1 | 0-7 | 0-1 |
| NVIC_PriorityGroup_4 | 3 | 4 | 0 | 0-15 | 0 |

```c
// 标准库 NVIC 配置示例
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);  // 2bit 抢占 + 2bit 子优先级

NVIC_InitTypeDef NVIC_InitStructure;
NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 0;  // 抢占优先级 0（最高）
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;         // 子优先级 0
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
NVIC_Init(&NVIC_InitStructure);
```

**抢占与子优先级的区别**：
- **抢占优先级**：高抢占优先级的中断可以打断正在执行的低抢占优先级中断
- **子优先级**：当两个中断具有相同的抢占优先级时，子优先级决定谁先执行（不能互相打断）

#### EXTI 外部中断

EXTI 将 GPIO 引脚映射到 16 条中断线（EXTI0-EXTI15）。

```c
// 标准库配置 PA0 上升沿中断
// 1. 使能 AFIO 时钟（重映射和 EXTI 配置必需）
RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);

// 2. 将 GPIOA_Pin0 连接到 EXTI 线 0
GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0);

// 3. 配置 EXTI 线 0
EXTI_InitTypeDef EXTI_InitStructure;
EXTI_InitStructure.EXTI_Line = EXTI_Line0;
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;
EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Rising;  // 上升沿触发
EXTI_InitStructure.EXTI_LineCmd = ENABLE;
EXTI_Init(&EXTI_InitStructure);
```

> **重要：共享中断线**
> 
> F103 的中断线 5-9 和 10-15 是共享中断号的：
> - 线 5-9 共用 EXTI9_5_IRQn
> - 线 10-15 共用 EXTI15_10_IRQn
> 
> 多个引脚共用一个 ISR，需要在 ISR 中用 `EXTI_GetITStatus()` 判断是哪个引脚触发：
> ```c
> void EXTI9_5_IRQHandler(void) {
>     if (EXTI_GetITStatus(EXTI_Line5) != RESET) { /* PA5 触发 */ EXTI_ClearITPendingBit(EXTI_Line5); }
>     if (EXTI_GetITStatus(EXTI_Line6) != RESET) { /* PA6 触发 */ EXTI_ClearITPendingBit(EXTI_Line6); }
> }
> ```

### 5.3. 定时器分类与功能详解

F103 定时器按功能分为三个层级：

| 定时器 | 位数 | 预分频 | 数量 | 功能 | 典型应用 |
|:------|:-----|:------|:-----|:-----|:---------|
| 高级定时器 TIM1/8 | 16 | 1-65536 | 2 | PWM + 死区 + 互补 + 刹车 | 电机控制、逆变器 |
| 通用定时器 TIM2-4 | 16 | 1-65536 | 3 | PWM / 输入捕获 / 编码器 | 通用定时、PWM、测速 |
| 基本定时器 TIM6/7 | 16 | 1-65536 | 2 | 仅时基 | 定时中断、DAC 触发 |
| SysTick（内核） | 24 | /8 或 /1 | 1 | 系统心跳 | RTOS 心跳、延时函数 |

**PWM 频率与占空比计算**（F103, APB2=72MHz）：

$$
f_{PWM} = \frac{PCLK}{(PSC+1) \times (ARR+1)}
$$

$$
Duty = \frac{CCR}{ARR+1} \times 100\%
$$

```c
// 标准库 PWM 配置(TIM1_CH1, PA8, f=1kHz, Duty=50%)
TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
TIM_OCInitTypeDef       TIM_OCInitStructure;

// 时基配置：PSC=72-1, ARR=1000-1 → 72MHz/72/1000 = 1kHz
TIM_TimeBaseStructure.TIM_Prescaler = 72 - 1;
TIM_TimeBaseStructure.TIM_Period    = 1000 - 1;
TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
TIM_TimeBaseInit(TIM1, &TIM_TimeBaseStructure);

// 输出比较配置：PWM 模式 1，占空比 500/1000 = 50%
TIM_OCInitStructure.TIM_OCMode     = TIM_OCMode_PWM1;
TIM_OCInitStructure.TIM_Pulse      = 500;   // CCR 值
TIM_OCInitStructure.TIM_OCPolarity = TIM_OCPolarity_High;
TIM_OC1Init(TIM1, &TIM_OCInitStructure);

TIM_Cmd(TIM1, ENABLE);
TIM_CtrlPWMOutputs(TIM1, ENABLE);  // ⚠️ 高级定时器必须额外使能主输出
```

### 5.4. DMA：让数据自己飞

DMA（Direct Memory Access）允许外设与内存之间、内存与内存之间直接传输数据，**不需要 CPU 干预**。

**DMA 解决的问题**：
- 没有 DMA：CPU 每个字节都要参与搬运 → CPU 被大量占用
- 有 DMA：配置好源地址、目标地址、数据长度后，DMA 自动搬运 → CPU 可以去干别的事

**DMA 传输流程**：

```
1. CPU 配置 DMA：
   - 源地址（如 &USART1->DR）
   - 目标地址（如 tx_buffer）
   - 传输长度（如 100 字节）
   - 传输方向（外设→内存 或 内存→外设）

2. CPU 使能 DMA，然后去干其他事

3. DMA 自动搬运：
   ┌──────┐    ┌──────┐    ┌──────┐
   │外设DR│───→│DMA   │───→│内存  │
   └──────┘    └──────┘    └──────┘
   每个字节后，DMA 自动决定是否增加地址

4. 传输完成 → DMA 触发中断 → CPU 收到通知
```

```c
// 标准库 DMA 配置：USART1_TX 通过 DMA1_Channel4 发送
DMA_InitTypeDef DMA_InitStructure;
RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1, ENABLE);  // DMA 在 AHB 总线上

DMA_InitStructure.DMA_PeripheralBaseAddr = (uint32_t)&USART1->DR;  // 源：外设
DMA_InitStructure.DMA_MemoryBaseAddr     = (uint32_t)tx_buffer;     // 目标：内存
DMA_InitStructure.DMA_DIR  = DMA_DIR_PeripheralDST;  // 内存→外设
DMA_InitStructure.DMA_BufferSize = tx_len;            // 传输长度
DMA_InitStructure.DMA_PeripheralInc = DMA_PeripheralInc_Disable;  // 外设地址不变
DMA_InitStructure.DMA_MemoryInc     = DMA_MemoryInc_Enable;        // 内存地址递增
DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;
DMA_InitStructure.DMA_MemoryDataSize     = DMA_MemoryDataSize_Byte;
DMA_InitStructure.DMA_Mode = DMA_Mode_Normal;  // 单次传输（非循环）
DMA_Init(DMA1_Channel4, &DMA_InitStructure);

// 将 USART1 的发送请求连接到 DMA
USART_DMACmd(USART1, USART_DMAReq_Tx, ENABLE);
DMA_Cmd(DMA1_Channel4, ENABLE);  // 启动 DMA

// DMA 传输完成中断
void DMA1_Channel4_IRQHandler(void) {
    if (DMA_GetITStatus(DMA1_IT_TC4)) {
        DMA_ClearITPendingBit(DMA1_IT_TC4);
        // 传输完成：可以关闭 DMA 或开始下一次传输
    }
}
```

> **F103 的 DMA 通道映射限制**：
> 
> DMA1 共有 7 个通道，每个通道**固定映射**到特定外设请求。这与 F4 的 DMA 流（Stream）不同——F4 更加灵活，可以任意映射。

| 外设请求 | 必须使用 |
|:--------|:--------|
| USART1_TX | DMA1_Channel4 |
| USART1_RX | DMA1_Channel5 |
| ADC1 | DMA1_Channel1 |
| SPI1_RX | DMA1_Channel2 |
| SPI1_TX | DMA1_Channel3 |

**DMA 常见应用**：
1. **USART 收发**：串口大数据传输不阻塞 CPU
2. **ADC 连续采样**：ADC 连续转换，DMA 自动搬运到数组
3. **定时器触发 DAC**：生成任意波形
4. **内存到内存拷贝**：大块数据移动

## 6. 通信接口详解

### 6.1. UART/USART 异步串行通信

USART（Universal Synchronous/Asynchronous Receiver/Transmitter）是 F103 最常用的通信接口。

**引脚定义**：
- TX：发送引脚
- RX：接收引脚
- CK：同步时钟（同步模式使用）
- CTS/RTS：硬件流控（可选）

```c
// 标准库 USART1 配置（PA9=TX, PA10=RX, 115200-8N1）
USART_InitTypeDef USART_InitStructure;
USART_InitStructure.USART_BaudRate            = 115200;
USART_InitStructure.USART_WordLength          = USART_WordLength_8b;  // 8 位数据
USART_InitStructure.USART_StopBits            = USART_StopBits_1;      // 1 位停止位
USART_InitStructure.USART_Parity              = USART_Parity_No;       // 无校验
USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
USART_InitStructure.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
USART_Init(USART1, &USART_InitStructure);
USART_Cmd(USART1, ENABLE);

// 中断接收
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);

void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uint8_t rx_byte = USART_ReceiveData(USART1);
        // 存入环形缓冲区
    }
}
```

**波特率计算公式**（F103, USART1 on APB2=72MHz）：

$$ Baud = \frac{f_{PCLK}}{16 \times USARTDIV} $$

例如 115200 bps：$USARTDIV = 72000000 / (16 \times 115200) = 39.0625$  
写入 BRR 寄存器：DIV_Mantissa = 39, DIV_Fraction = 1（0.0625 × 16 = 1）

### 6.2. SPI 同步串行通信

SPI（Serial Peripheral Interface）是一种四线全双工同步串行协议，常用于传感器、Flash、显示屏等。

**引脚定义**：

| 信号 | 全称 | 方向（主→从） | 含义 |
|:-----|:-----|:------------|:-----|
| SCK | Serial Clock | 主→从 | 时钟信号（由主机产生） |
| MOSI | Master Out Slave In | 主→从 | 主机发送，从机接收 |
| MISO | Master In Slave Out | 从→主 | 从机发送，主机接收 |
| NSS/CS | Slave Select | 主→从（低有效） | 片选信号 |

**SPI 四种模式（由 CPOL 和 CPHA 决定）**：

| 模式  | CPOL(时钟极性) | CPHA(时钟相位) | SCK 空闲电平 | 数据采样沿      | 典型设备      |
| :-- | :--------- | :--------- | :------- | :--------- | :-------- |
| 0   | 0          | 0          | 低        | 第一个边沿（上升沿） | 多数 SPI 设备 |
| 1   | 0          | 1          | 低        | 第二个边沿（下降沿） |           |
| 2   | 1          | 0          | 高        | 第一个边沿（下降沿） |           |
| 3   | 1          | 1          | 高        | 第二个边沿（上升沿） |           |

```c
// 标准库 SPI1 初始化（PA5=SCK, PA6=MISO, PA7=MOSI，模式 0）
SPI_InitTypeDef SPI_InitStructure;
SPI_InitStructure.SPI_Direction = SPI_Direction_2Lines_FullDuplex;
SPI_InitStructure.SPI_Mode      = SPI_Mode_Master;      // 主机模式
SPI_InitStructure.SPI_DataSize  = SPI_DataSize_8b;
SPI_InitStructure.SPI_CPOL      = SPI_CPOL_Low;         // CPOL=0
SPI_InitStructure.SPI_CPHA      = SPI_CPHA_1Edge;       // CPHA=0
SPI_InitStructure.SPI_NSS       = SPI_NSS_Soft;         // 软件控制片选
SPI_InitStructure.SPI_BaudRatePrescaler = SPI_BaudRatePrescaler_256;
SPI_InitStructure.SPI_FirstBit  = SPI_FirstBit_MSB;     // MSB 先发
SPI_Init(SPI1, &SPI_InitStructure);
SPI_Cmd(SPI1, ENABLE);

// 收发一个字节（全双工）
uint8_t SPI_TransferByte(uint8_t tx_byte) {
    while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_TXE) == RESET);  // 等待 TX 空
    SPI_I2S_SendData(SPI1, tx_byte);
    while (SPI_I2S_GetFlagStatus(SPI1, SPI_I2S_FLAG_RXNE) == RESET);  // 等待 RX 非空
    return SPI_I2S_ReceiveData(SPI1);
}
```

### 6.3. I2C 总线

I2C 是一种两线半双工同步串行协议，只需 SDA（数据）和 SCL（时钟）两条线，支持多主多从。

```c
// 标准库 I2C1 初始化（PB6=SCL, PB7=SDA, 100kHz）
I2C_InitTypeDef I2C_InitStructure;
I2C_InitStructure.I2C_Mode = I2C_Mode_I2C;
I2C_InitStructure.I2C_ClockSpeed = 100000;
I2C_InitStructure.I2C_DutyCycle = I2C_DutyCycle_2;
I2C_InitStructure.I2C_Ack = I2C_Ack_Enable;
I2C_Init(I2C1, &I2C_InitStructure);
I2C_Cmd(I2C1, ENABLE);
```

> **F103 I2C 硬件勘误**：
> 
> STM32F103 的 I2C 硬件有若干已知问题（EV5/EV6/EV7 事件序列较难调试），实际项目中很多人倾向于用 **GPIO 模拟 I2C**（bit-banging）替代硬件 I2C。
> 
> 如果必须使用硬件 I2C，建议用 HAL 库——`HAL_I2C_Mem_Read()` 和 `HAL_I2C_Mem_Write()` 已经处理好了复杂的事件序列。

### 6.4. CAN 总线

CAN（Controller Area Network）是一种面向实时控制的高可靠差分总线，广泛应用于汽车和工业控制。F103 的 bxCAN 支持 CAN 2.0A（标准帧 11-bit ID）和 2.0B（扩展帧 29-bit ID）。

**CAN 位时序**（决定波特率的四个时段）：

```
Sync_Seg | Prop_Seg | Phase_Seg1 | Phase_Seg2
   1Tq       1~8Tq      1~8Tq       1~8Tq
```

一个比特时间 = Sync_Seg + Prop_Seg + Phase_Seg1 + Phase_Seg2

**波特率计算公式**：$Baud = \frac{PCLK1}{(1 + BS1 + BS2) \times Prescaler}$

```c
// 标准库 CAN1 初始化（1Mbps, APB1=36MHz）
CAN_InitTypeDef CAN_InitStructure;
CAN_InitStructure.CAN_TTCM = DISABLE;
CAN_InitStructure.CAN_ABOM = ENABLE;      // 自动离线管理
CAN_InitStructure.CAN_AWUM = ENABLE;      // 自动唤醒
CAN_InitStructure.CAN_NART = DISABLE;     // 自动重传
CAN_InitStructure.CAN_RFLM = DISABLE;
CAN_InitStructure.CAN_TXFP = DISABLE;
CAN_InitStructure.CAN_Mode = CAN_Mode_Normal;
CAN_InitStructure.CAN_SJW = CAN_SJW_1tq;
CAN_InitStructure.CAN_BS1 = CAN_BS1_3tq;  // 3 Tq
CAN_InitStructure.CAN_BS2 = CAN_BS2_2tq;  // 2 Tq
CAN_InitStructure.CAN_Prescaler = 6;      // 36M / (1+3+2) / 6 = 1Mbps
CAN_Init(CAN1, &CAN_InitStructure);

// 发送
CanTxMsg TxMessage;
TxMessage.StdId = 0x321;
TxMessage.IDE   = CAN_Id_Standard;
TxMessage.RTR   = CAN_RTR_Data;
TxMessage.DLC   = 8;
TxMessage.Data[0] = 0x01;
CAN_Transmit(CAN1, &TxMessage);
```

> **CAN 硬件要求**：F103 的 CAN_TX/CAN_RX 是 TTL 电平，必须外接 CAN 收发器（如 TJA1050、SN65HVD230）转换为 CANH/CANL 差分信号才能连接到 CAN 总线。

## 7. 模拟外设与低功耗

### 7.1. ADC：模数转换器

F103 的 ADC 是 12 位逐次逼近型（SAR），最高采样率 1MHz。

```c
// 寄存器级 ADC1 单通道（PA0, 通道0）
RCC->APB2ENR |= RCC_APB2ENR_ADC1EN;
RCC->CFGR    |= RCC_CFGR_ADCPRE_Div6;   // ADC 预分频 72MHz/6=12MHz（不超过14MHz）
GPIOA->CRL   &= ~0xF;                    // PA0 模拟输入

ADC1->SQR1   = 0x00000000;              // 1 个转换
ADC1->SQR3   = 0x00000000;              // 第1个转换 = 通道0
ADC1->SMPR2  = 0x00000007;              // 通道0 采样时间 = 239.5 周期
ADC1->CR1    = 0x00000000;
ADC1->CR2    = ADC_CR2_ADON | ADC_CR2_CAL;  // 开启并校准
while (ADC1->CR2 & ADC_CR2_CAL);

ADC1->CR2 |= ADC_CR2_ADON;              // 开始转换
while (!(ADC1->SR & ADC_SR_EOC));
uint16_t adc_val = ADC1->DR;
```

**规则通道 vs 注入通道**：

| 通道类型 | 特点 | 典型用途 |
|:--------|:-----|:--------|
| 规则通道 | 至多 16 个，按 SQR 序列依次转换 | 常规多通道数据采集 |
| 注入通道 | 至多 4 个，可以插入规则转换序列中 | 紧急采样（如过流保护） |

### 7.2. DAC：数模转换器

F103 集成 2 个 12 位 DAC 通道（通道1=PA4, 通道2=PA5）。

```c
// 标准库 DAC 输出
DAC_InitTypeDef DAC_InitStructure;
DAC_InitStructure.DAC_Trigger = DAC_Trigger_None;
DAC_InitStructure.DAC_WaveGeneration = DAC_WaveGeneration_None;
DAC_InitStructure.DAC_OutputBuffer = DAC_OutputBuffer_Enable;
DAC_Init(DAC_Channel_1, &DAC_InitStructure);
DAC_Cmd(DAC_Channel_1, ENABLE);

DAC_SetChannel1Data(DAC_Align_12b_R, dac_val);  // 输出电压 = dac_val/4096 × Vref
```

> **DAC 高级应用：DDS 波形发生器**
> 
> DAC + 定时器 + DMA 可生成任意波形。将预计算的波形表存入内存，定时器触发 DMA 传输到 DAC 数据寄存器，即可在 PA4/PA5 引脚输出指定波形。

### 7.3. RTC 与备份域

F103 的 RTC 是一个独立的 32 位计数器（不是完整的日历时钟模块），由 LSE(32.768KHz) 驱动，通过软件换算为时间。

```c
// 标准库 RTC 初始化（LSE=32.768KHz）
RCC_LSEConfig(RCC_LSE_ON);
while (RCC_GetFlagStatus(RCC_FLAG_LSERDY) == RESET);
RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE);
RCC_RTCCLKCmd(ENABLE);
RTC_WaitForSynchro();

// 32.768KHz / (32767+1) = 1Hz
RTC_SetPrescaler(32767);
RTC_WaitForLastTask();

uint32_t cnt = RTC_GetCounter();  // 读取当前秒数
```

**备份寄存器（BKP）**：备份域由独立的 VBAT 引脚供电——即使主电源切断，只要 VBAT（纽扣电池）保持供电，RTC 和备份寄存器内容就不会丢失。

```c
PWR_BackupAccessCmd(ENABLE);
BKP_WriteBackupRegister(BKP_DR1, 0xABCD);  // 断电后该值仍保持
uint16_t val = BKP_ReadBackupRegister(BKP_DR1);
```

### 7.4. 看门狗

| 看门狗 | 时钟源 | 精度 | 特点 | 典型超时范围 |
|:------|:------|:-----|:-----|:------------|
| IWDG（独立看门狗） | LSI 40KHz | ±5% | 一旦使能无法软件关闭，主时钟停摆仍运行 | 0.1ms - 26.2s |
| WWDG（窗口看门狗） | PCLK1 | 高 | 必须在特定时间窗口内喂狗 | 10μs - 38ms |

```c
// IWDG 配置（1秒超时）
IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);
IWDG_SetPrescaler(IWDG_Prescaler_64);   // 40kHz / 64 = 625Hz
IWDG_SetReload(625);                     // 1秒超时
IWDG_ReloadCounter();
IWDG_Enable();

// 主循环中喂狗
IWDG_ReloadCounter();
```

### 7.5. 低功耗模式

| 模式 | CPU | 外设时钟 | HSI/HSE | 唤醒源 | 典型功耗 |
|:-----|:----|:--------|:-------|:------|:--------:|
| Sleep | 停 | 运行 | 运行 | 任意中断 | ~5mA |
| Stop | 停 | 停 | 停（可保持 LSE/LSI） | EXTI 线 | ~20μA |
| Standby | 停 | 停 | 停 | WKUP 引脚 / RTC / IWDG | ~2μA |

```c
// 进入 Stop 模式
RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);
PWR_EnterSTOPMode(PWR_Regulator_LowPower, PWR_STOPEntry_WFI);
// 被 EXTI 唤醒后系统时钟自动切换到 HSI，需要重新配置
SystemInit();
```

## 8. 调试与工具链

### 8.1. SWD vs JTAG

| 接口 | 信号线 | 特点 |
|:-----|:-------|:-----|
| SWD（串行调试） | SWDIO + SWCLK + GND | 只需 2 根信号线，推荐 |
| JTAG | TDI + TDO + TMS + TCK + TRST + GND | 5 根信号线，功能更全 |

> **SWD 是 F103 调试的首选**——只用 2 根线，不占用额外 GPIO，且大部分调试器（ST-Link、J-Link）都支持。

### 8.2. DWT 周期计数器（精确测量代码执行时间）

```c
// 使能 DWT 周期计数器
DWT->CYCCNT = 0;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;

uint32_t start = DWT->CYCCNT;
// ... 被测代码段 ...
uint32_t elapsed = DWT->CYCCNT - start;  // 执行了 elapsed 个 CPU 周期
// 72MHz 下，elapsed=72000000 表示 1 秒
```

### 8.3. 调试技巧

**断点硬编码**：
```c
__BKPT(0);  // 在代码中插入断点（仅调试模式下有效）
```

**DBGMCU：调试时冻结外设**：
```c
// 调试模式下停止看门狗和定时器，防止断点时溢出
DBGMCU->CR |= DBGMCU_CR_DBG_IWDG_STOP  |
              DBGMCU_CR_DBG_WWDG_STOP  |
              DBGMCU_CR_DBG_TIM1_STOP  |
              DBGMCU_CR_DBG_TIM2_STOP;
```

### 8.4. 波形捕获工具

- **逻辑分析仪**：捕获 SPI/I2C/UART 数字波形，协议自动解码
- **示波器**：测量 PWM 频率/占空比、电源纹波、信号上升时间

## 本讲核心要点

1. **三层编程范式**：寄存器（理解硬件）→ 标准库（F103 经典做法）→ HAL（现代开发）。建议从标准库入手，工作中用 HAL，关键路径改寄存器。
2. **时钟树是第一关**：APB1 ≤36MHz，APB2 ≤72MHz。外设时钟必须显式使能——忘记使能是 HardFault 最常见原因。
3. **GPIO 8 种模式**：推挽输出（驱动）→ 开漏输出（I2C）→ 复用功能（外设引脚）→ 输入（按键/ADC）。理解 CRL/CRH 配置位。
4. **NVIC 优先级**：抢占优先级决定嵌套，子优先级决定同优先级下的顺序。中断服务函数应尽量短——只设标志位或入队列。
5. **定时器是万能模块**：PWM、输入捕获、编码器模式、死区控制——全由一个硬件实现。高级定时器需额外 `TIM_CtrlPWMOutputs()`。
6. **DMA 解放 CPU**：外设与内存自动搬运。F103 的 DMA 通道固定映射，使用前查表。配合 USART IDLE 中断可实现高效不定长数据接收。
7. **通信接口**：SPI 四线全双工（4 种模式），CAN 差分高可靠性（需外接收发器），I2C 两线制（F103 硬件有勘误，可用 GPIO 模拟）。
8. **模拟外设**：ADC 注入通道可"插入"规则转换序列，DAC 配合定时器 + DMA 输出任意波形。
9. **低功耗**：Stop 模式（~20μA）被 EXTI 唤醒后时钟自动切到 HSI，需重新配置；Standby 模式（~2μA）唤醒相当于复位。
10. **调试**：SWD 是首选调试接口。DWT 周期计数器可精确测量代码执行时间。HardFault 可通过读取栈帧定位出错的 PC。
