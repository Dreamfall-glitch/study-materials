# 14-编译、链接与预处理

## 知识地图

```
多文件项目：声明（.h）与定义（.c）分离
    ↓
头文件保护 (#ifndef / #define / #endif)
    ↓
链接：目标文件 → 可执行文件
├── 静态库（.a）：编译时嵌入，体积大但独立
└── 共享库（.so）：运行时加载，节省空间
    ↓
预处理：#include / #define / 条件编译
    ↓
宏：无类型检查，带参须用括号保护
    ↓
Makefile：变量、规则、自动依赖
```

**本讲回答的核心问题**：多个 .c 文件如何协同工作？头文件怎么防止重复包含？宏和条件编译有什么实际用途？

## 1. 多文件编译

### 1.1. 声明与定义分离

头文件（`.h`）存放**声明**，源文件（`.c`）存放**定义**：

```c
/* stack.h —— 头文件：申明接口 */
#ifndef STACK_H
#define STACK_H

int push(int x);
int pop(int *val);
int is_empty(void);

#endif
```

```c
/* stack.c —— 源文件：实现 */
#include "stack.h"         /* 双引号：先搜索当前目录 */

static int data[100];
static int top = 0;         /* static：仅本文件可见 */

int push(int x) {
    if (top >= 100) return -1;
    data[top++] = x;
    return 0;
}

int pop(int *val) {
    if (top == 0) return -1;
    *val = data[--top];
    return 0;
}
```

```c
/* main.c —— 使用者 */
#include "stack.h"

int main(void) {
    push(10); push(20);
    int v; pop(&v);
    printf("%d\n", v);
    return 0;
}
```

编译：
```
$ gcc -c stack.c -o stack.o          # 编译成目标文件
$ gcc -c main.c -o main.o
$ gcc stack.o main.o -o program      # 链接
$ ./program
```

### 1.2. #include 的查找规则

- `#include "xxx.h"`：先找当前目录，再找系统路径
- `#include <xxx.h>`：只找系统路径（如 `/usr/include`）

### 1.3. 头文件保护

```c
#ifndef MATH_UTILS_H       /* 如果未定义才往下走 */
#define MATH_UTILS_H       /* 定义它，防止重复包含 */
int add(int, int);
int mul(int, int);
#endif                     /* 结束条件编译 */
```

**为什么需要？** 如果多个 `.c` 文件各自 `#include "header.h"`，链接时每个 `.c` 中的声明不会冲突（声明允许多次出现）。但如果一个 `.c` 文件间接包含同一个头文件两次，没保护会导致重复声明错误。

### 1.4. static 与 extern

```c
/* a.c */
static int hidden = 0;       /* 仅本文件可见，链接时不可见 */
int visible = 1;              /* 默认外部可见 */
static void helper(void) {}  /* 仅本文件可见（内部链接） */
void api(void) { helper(); } /* 外部可见 */

/* b.c */
extern int visible;           /* 声明 visible 是其他文件定义的 */
```

**static 对变量的含义**：
- 全局 static：限制为内部链接（其他文件不可见）
- 局部 static：生命周期变成全程（值会保持），但作用域不变（只有本函数内可用）

## 2. 链接

### 2.1. 链接过程

编译器把每个 `.c` 文件编译成目标文件（`.o`），链接器把多个 `.o` 和库文件合并为可执行文件。主要解决两种问题：
1. **符号解析**：把符号引用和符号定义关联起来
2. **重定位**：把相对地址调整为实际地址

### 2.2. 静态库 vs 共享库

| 特性 | 静态库（.a） | 共享库（.so） |
|------|:--:|:--:|
| 链接时机 | 编译时（ld） | 运行时（加载时动态链接） |
| 可执行文件大小 | 包含库代码——较大 | 仅包含引用——较小 |
| 发布 | 单文件即可运行 | 需要同时分发 .so 文件 |
| 更新 | 需重新链接整个程序 | 替换 .so 文件即可（接口兼容） |
| 典型位置 | `/usr/lib/` | `/usr/lib/` + 运行时需能找到 |

```bash
# 静态库
$ gcc -c stack.c -o stack.o
$ ar rcs libstack.a stack.o               # 创建静态库
$ gcc main.c -L. -lstack -o program       # -L 指定路径，-l 指定库名（去 lib 和 .a）

# 共享库
$ gcc -fPIC -c stack.c -o stack.o         # -fPIC: 位置无关代码
$ gcc -shared stack.o -o libstack.so      # 创建共享库
$ gcc main.c -L. -lstack -o program
$ LD_LIBRARY_PATH=. ./program             # 指定运行时搜索路径
```

## 3. 预处理

### 3.1. 预处理的本质

预处理是编译的第一步，本质是**文本替换**。可以用 `gcc -E` 查看预处理后的结果：

```
$ gcc -E main.c | head -20
...（展开后的代码）
```

### 3.2. \#define 宏

```c
/* 简单常量宏 */
#define PI 3.14159
#define MAX_SIZE 1024

/* 带参数的宏 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define SQUARE(x) ((x) * (x))
#define IS_EVEN(n) ((n) % 2 == 0)
```

**宏的陷阱——参数必须用括号保护**：

```c
#define BAD_SQUARE(x)  x * x

int a = BAD_SQUARE(3+1);       /* 展开为 3+1*3+1 = 7 —— 错误！ */
#define GOOD_SQUARE(x) ((x)*(x))
int b = GOOD_SQUARE(3+1);      /* 展开为 ((3+1)*(3+1)) = 16 */

#define BAD_MAX(a, b) a > b ? a : b
int c = BAD_MAX(3, 4) + 1;     /* 展开为 3 > 4 ? 3 : 4 + 1 = 5 —— 错误！ */
#define GOOD_MAX(a, b) ((a) > (b) ? (a) : (b))
```

| 对比 | 宏 | 函数 |
|------|:--:|:--:|
| 类型检查 | 无 | 有 |
| 调用开销 | 无（展开为内联代码） | 有（参数压栈、函数调用） |
| 代码体积 | 多次展开变大 | 只有一份代码 |
| 调试 | 难以单步跟踪 | 可设断点 |

### 3.3. 条件编译

```c
/* 调试开关 */
#define DEBUG
#ifdef DEBUG
    printf("x=%d, y=%d\n", x, y);
#endif

/* 跨平台兼容 */
#ifdef _WIN32
    #include <windows.h>
#elif defined(__linux__)
    #include <unistd.h>
#else
    #error "Unsupported platform"
#endif

/* 头文件保护（见 1.3 节） */

/* 断言调试 */
#ifndef NDEBUG
    assert(ptr != NULL);    /* 调试版本：检查 */
#endif
/* 编译时加 -DNDEBUG 可禁用 assert */
```

常用的预定义宏：

```c
printf("File: %s\n", __FILE__);      /* 当前文件名 */
printf("Line: %d\n", __LINE__);      /* 当前行号 */
printf("Date: %s\n", __DATE__);      /* 编译日期 */
printf("Time: %s\n", __TIME__);      /* 编译时间 */
printf("C std: %ld\n", __STDC_VERSION__);  /* C 标准版本 */
```

## 4. Makefile

### 4.1. 基本规则

```makefile
program: main.o stack.o          # 目标：依赖
    gcc main.o stack.o -o program   # 命令（必须以 Tab 开始）

main.o: main.c stack.h
    gcc -Wall -g -c main.c

stack.o: stack.c stack.h
    gcc -Wall -g -c stack.c

clean:
    rm -f *.o program
```

### 4.2. 变量与自动变量

```makefile
CC = gcc
CFLAGS = -Wall -g
OBJS = main.o stack.o

program: $(OBJS)
    $(CC) $^ -o $@         # $^=所有依赖 $@=目标

%.o: %.c
    $(CC) $(CFLAGS) -c $< -o $@   # $<=第一个依赖

clean:
    rm -f $(OBJS) program
```

### 4.3. 常用命令行

```
$ make              # 构建
$ make -j4          # 并行编译（4线程）
$ make clean        # 清理
$ make CFLAGS=-O2   # 覆盖变量定义
```

## 本讲核心要点

1. **头文件放声明**（函数原型、类型、宏），**源文件放定义**（实现）
2. **头文件保护**用 `#ifndef/#define/#endif` 防止重复包含
3. **static 限制作用域**（内部链接），**extern 声明其他文件定义的变量**
4. **静态库**编译时嵌入，发布简单但文件大；**共享库**运行时加载，需分发 .so
5. **宏是文本替换**，参数必须用括号 `((x))` 保护；调试时 `gcc -E` 查看展开
6. **条件编译**用于调试开关、跨平台、头文件保护、编译时断言
7. **\_\_FILE\_\_, \_\_LINE\_\_, \_\_DATE\_\_** 是常见预定义宏
8. **Makefile 用 Tab 缩进命令**，`$@` = 目标，`$^` = 全依赖，`$<` = 第一依赖
