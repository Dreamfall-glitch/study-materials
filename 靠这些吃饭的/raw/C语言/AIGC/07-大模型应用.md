# 07-大模型应用

## 知识地图

```
LLM 训练好之后，怎么用到实际场景中？
    │
    ├── 评测：怎么知道模型好不好？
    │     └── MMLU(通用) / GSM8K(数学) / HellaSwag(推理) / 垂直领域榜单
    │
    ├── RAG：怎么让模型"知道"它没学过的最新信息？
    │     └── 文档→切分→向量化→检索→LLM生成
    │         Tiny-RAG: Embedding + VectorStore + LLM
    │
    └── Agent：怎么让模型"会做事"（不仅会说话）？
          └── LLM(大脑) + 规划 + 记忆 + 工具调用
              Tiny-Agent: tool_calls + 函数定义 + 循环执行
```

**本讲回答的核心问题**：模型训练完了，怎么衡量它行不行（评测）？遇到模型不知道的信息怎么办（RAG）？怎么让模型不仅能回答问题，还能动手操作外部工具（Agent）？

## 1. LLM 评测——怎么知道模型好不好

### 1.1. 为什么需要评测

LLM 训练成本极高（百亿模型训练花费千万级），评测是判断模型是否"值这个价"的唯一标准。评测帮我们回答三个问题：
- 这个模型在哪些任务上强、哪些上弱？
- 和竞品比差距在哪里？
- 下一版迭代应该优化什么方向？

### 1.2. 主流评测集

| 类别 | 评测集 | 考察点 | 典型题目 |
|:----|:------|:------|:--------|
| **通用** | MMLU | 57 个学科的多任务理解 | 历史、物理、法律等知识问答 |
| **数学** | GSM8K | 小学数学推理 | "小明有5个苹果，吃了2个又买了3个，现在有几个？" |
| **数学** | MATH | 高中数学（代数/几何） | 解方程、几何证明 |
| **推理** | ARC Challenge | 科学常识推理 | "为什么冬天玻璃上会结霜？" |
| **推理** | HellaSwag | 情境下的最佳续写 | "他走进厨房，接下来最可能发生的是？" |
| **长文本** | InfiniteBench | 长文档阅读理解 | 读完论文回答问题 |
| **多语言** | MGSM | 跨语言数学 | 用中文/英文/法语解同一个数学题 |
| **工具使用** | BFCL V2 | 多步工具调用 | "查询A城市的天气，如果下雨则预订室内活动" |

- **安全榜**（Flames）：公平、安全、数据保护
- **法律榜**（LawBench）：法律问答、判例分析
- **医疗榜**（MedBench）：医学知识、安全伦理

> **通俗理解**：通用评测像"高考"——看综合能力。垂直榜单像"专业资格证考试"——看特定领域能不能用。

## 2. RAG——检索增强生成

### 2.1. 为什么需要 RAG

LLM 有三个固有缺陷，RAG 恰好弥补：

| 缺陷 | 现象 | RAG 怎么解决 |
|:----|:-----|:------------|
| **幻觉** | 编造不存在的知识 | 生成基于检索到的真实文档，答案可追溯 |
| **知识过时** | 训练数据截止后的事件不知道 | 检索最新的文档库 |
| **领域知识弱** | 对专业领域理解不深 | 检索领域特定文档补充上下文 |

### 2.2. RAG 核心流程

```
用户提问："RAG的原理是什么？"
    │
    ▼
① 向量化：把问题转为向量（Embedding 模型）
    │
    ▼
② 检索：在向量数据库中找最相似的文档片段（余弦相似度）
    │
    ▼
③ 生成：将检索到的文档 + 原始问题一起送入 LLM
    │
    ▼
回答："RAG 是一种检索增强生成技术，其原理是..."
```

**RAG 的三大步骤**——"索引 → 检索 → 生成"：

```
索引阶段：
  文档库 → 切分（chunk） → 每个chunk向量化 → 存入向量数据库

检索阶段：
  用户问题 → 向量化 → 在数据库里找最相似的 k 个chunk

生成阶段：
  Prompt = "根据以下上下文回答问题：\n{检索到的chunks}\n问题：{用户问题}"
  LLM 根据 Prompt 生成回答
```

### 2.3. Tiny-RAG 实现

一个极简 RAG 只需三个模块：

```python
# ① 文档加载与切分
docs = ReadFiles('./data').get_content(max_token_len=600, cover_content=150)

# ② 向量化与存储
vector = VectorStore(docs)
embedding = OpenAIEmbedding()   # 用 Embedding API 向量化
vector.get_vector(EmbeddingModel=embedding)
vector.persist(path='storage')  # 保存到本地

# ③ 检索 + 生成
question = 'RAG的原理是什么？'
content = vector.query(question, embedding, k=1)[0]  # 检索 top1 片段
chat = OpenAIChat(model='Qwen/Qwen2.5-32B-Instruct')
print(chat.chat(question, [], content))  # LLM 生成回答
```

**核心设计**：

```python
# 向量检索 —— 用余弦相似度找最相关的文档
def query(self, query, EmbeddingModel, k=1):
    query_vector = EmbeddingModel.get_embedding(query)
    result = np.array([cosine_similarity(query_vector, v) for v in self.vectors])
    return np.array(self.document)[result.argsort()[-k:][::-1]]

# RAG 提示词模板 —— 把检索结果拼到 Prompt 里
RAG_PROMPT = """使用以上下文来回答用户的问题。
如果不知道答案，就说不知道。
问题：{question}
可参考的上下文：
{context}
有用的回答："""
```

**关键参数**：
- `max_token_len=600`：每个 chunk 最大 600 tokens
- `cover_content=150`：chunk 之间重叠 150 tokens（避免切在关键句中间）
- `k=1`：检索返回 1 个最相关 chunk

> **通俗理解**：RAG 像给 LLM 配了一本"开卷考试参考书"——遇到不会的题（幻觉风险高的问题），先翻翻参考书找到相关段落，再基于找到的段落作答。答案有据可查，错误率大大降低。

## 3. Agent——智能体

### 3.1. 从 LLM 到 Agent

```
传统 LLM：你问 → 它答（单向、被动）
    ↓
LLM Agent：你给目标 → 它自己规划 → 调用工具 → 得到结果 → 继续下一步 → 完成目标
```

**Agent 的四大能力**：

| 能力 | 说明 | 类比 |
|:----|:-----|:-----|
| **规划（Planning）** | 把大目标拆成小步骤 | "帮我订机票"→先查日期→再查航班→再下单 |
| **记忆（Memory）** | 短期（当前对话）+ 长期（知识库） | 记住之前查过的航班号 |
| **工具使用（Tool Use）** | 调用 API、数据库、搜索引擎 | 查天气API、调用计算器、搜索维基百科 |
| **反思（Reflection）** | 从失败中学习，调整计划 | "刚才查询超时了，换个 API 试试" |

> **通俗理解**：LLM 像"纸上谈兵的谋士"——知识渊博但只会说不会做。Agent 像"全能的执行官"——把谋士的策略变成实际行动，还能根据执行结果调整下一步。

### 3.2. Agent 的类型

| 类型 | 特点 | 例子 |
|:----|:-----|:-----|
| **任务导向型** | 专注特定领域，预设流程 | 客服机器人、代码助手 |
| **规划推理型** | 自主分解任务，多步计划 | ReAct 框架（思考→行动→观察→再思考） |
| **多 Agent 系统** | 多个 Agent 协作 | 模拟团队：产品经理 + 程序员 + 测试 |
| **探索学习型** | 在交互中自主学习 | 游戏 Agent、新环境探索 |

### 3.3. Tiny-Agent 实现

核心机制：**OpenAI 的 tool_calls**——LLM 可以返回"我要调用某个工具"的指令，而不是直接返回文字。

```python
from openai import OpenAI

client = OpenAI(api_key="...", base_url="...")
model = "Qwen/Qwen2.5-32B-Instruct"

# ① 定义工具函数（每个函数要有清晰的 docstring）
def get_current_datetime() -> str:
    """获取当前日期和时间。"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

def count_letter_in_string(a: str, b: str) -> str:
    """统计字符串中某个字母的出现次数。"""
    return str(a.count(b))

# ② 将函数描述转化为 tools 参数（LLM 需要的 schema）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_current_datetime",
            "description": "获取当前日期和时间",
            "parameters": {"type": "object", "properties": {}}
        }
    },
    {
        "type": "function",
        "function": {
            "name": "count_letter_in_string",
            "description": "统计字符串中某个字母的出现次数",
            "parameters": {
                "type": "object",
                "properties": {
                    "a": {"type": "string", "description": "要搜索的字符串"},
                    "b": {"type": "string", "description": "要统计的字母"}
                },
                "required": ["a", "b"]
            }
        }
    }
]

# ③ 循环：LLM 决定是否调用工具
messages = [{"role": "user", "content": "现在几点？帮我统计'hello world'里有多少个l"}]

while True:
    response = client.chat.completions.create(
        model=model, messages=messages, tools=tools, tool_choice="auto"
    )
    msg = response.choices[0].message
    
    if msg.tool_calls:  # LLM 要求调用工具
        for tool_call in msg.tool_calls:
            func_name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            # 执行对应的 Python 函数
            result = globals()[func_name](**args)
            # 把工具返回结果加回对话
            messages.append({"role": "tool", "content": result, "tool_call_id": tool_call.id})
    else:  # LLM 直接返回文字——任务完成
        print(msg.content)
        break
```

**Agent 的工作循环**：

```
用户："现在几点？统计hello world里有多少个l"
    │
    ▼
LLM 思考 → 决定调用 get_current_datetime() 和 count_letter_in_string()
    │
    ▼
系统执行 → get_current_datetime() → "2026-06-17 00:15:00"
         → count_letter_in_string("hello world", "l") → "3"
    │
    ▼
LLM 看到工具返回结果 → 整合成自然语言回答
    │
    ▼
"现在是 2026年6月17日 0点15分。'hello world'中有 3 个字母 l。"
```

**关键设计**：`tool_choice="auto"` 让 LLM 自主决定是否需要调用工具及调用哪个。如果不需要，LLM 直接返回文字；如果需要，返回 `tool_calls` 结构，系统解析后执行对应函数。

## 本讲核心要点

1. **LLM 评测** 是衡量模型价值的标尺——MMLU（通用）、GSM8K/MATH（数学）、HellaSwag（推理）是三大核心评测集
2. **垂直评测榜单**（金融/法律/医疗）用于评估模型在特定行业的可用性，比通用评测更有业务参考价值
3. **RAG 解决三个问题**：幻觉（答案可追溯）、知识过时（检索最新文档）、领域知识弱（检索专业文档）
4. **RAG 三步骤**：索引（文档切分 + 向量化）→ 检索（余弦相似度找 top-k）→ 生成（LLM + 检索结果）
5. **chunk 重叠设计**通过保留前后 chunk 的部分重叠内容（如 150 tokens），避免关键信息被切在两段之间
6. **RAG 提示词模板**关键是让 LLM 基于检索到的内容作答，不知道就说不知道，减少幻觉
7. **Agent 的核心**是让 LLM 从"只会说"变成"会做事"——四要素：规划 + 记忆 + 工具 + 反思
8. **tool_calls 机制**是 Agent 的基础——LLM 返回函数调用指令，系统执行函数并返回结果
9. **Agent 的工作循环**是"LLM 思考→决定调工具→系统执行→LLM 继续思考→完成"
10. **多 Agent 系统**让不同角色的 Agent 协作（规划Agent + 执行Agent + 审查Agent），处理更复杂的任务
