## 1. 为什么需要并行

### 1.1. 单核性能的瓶颈

2000年代中期，CPU单核性能的提升遇到了三大障碍：

| 瓶颈 | 说明 |
|:----|:------|
| **功耗墙**（power wall） | 主频每提高约1GHz，功耗增加约$V_{DD}^2 \times f$——频率翻倍，功耗翻倍甚至更多。Pentium 4的3.8GHz已到风冷散热极限 |
| **指令级并行极限** | 流水线、超标量、乱序执行等ILP技术已接近天花板——再增加发射宽度收益递减 |
| **存储墙**（memory wall） | 处理器速度增长远快于内存速度——Cache命中率成为性能的关键瓶颈 |

**业界转向**：不再追求单核更高主频，而是将多个核心集成在同一个芯片上——**多核处理器**（multi-core processor）成为主流。

> **通俗理解**：单核性能提升就像把一辆赛车越改越快——但发动机越来越热（功耗墙）、赛道越来越挤（ILP极限）、加油站赶不上车速（存储墙）。多核就干脆多放几辆车一起跑——虽然单辆车没更快，但整体运力（吞吐量）翻倍了。

## 2. Flynn分类法

Flynn分类法根据**指令流**和**数据流**的数量将计算机分为四类：

| 类别 | 含义 | 例子 |
|:----|:-----|:------|
| **SISD** | 单指令流单数据流 | **传统单核CPU**——一条指令处理一个数据 |
| **SIMD** | 单指令流多数据流 | **GPU、向量处理器**——一条指令同时处理多个数据 |
| **MISD** | 多指令流单数据流 | 容错系统（少数应用） |
| **MIMD** | 多指令流多数据流 | **多核CPU、多处理器系统**——每个核心执行不同的指令处理不同的数据 |

**通俗理解**：

| 类型 | 比喻 |
|:----|:------|
| **SISD** | 一个人按一份菜谱做一道菜 |
| **SIMD** | 一个厨师长喊口令，10个帮厨同时切10堆土豆（一条指令操作多个数据） |
| **MISD** | 10个医生同时给一个病人会诊——每个医生给出不同诊断 |
| **MIMD** | 10个厨师各有各的菜谱，各自做自己的菜 |

> **SIMD与MIMD的实际关系**：现代CPU实际上是MIMD（多核），但每个核心内部集成了SIMD指令（如x86的SSE/AVX、ARM的NEON），用于多媒体和科学计算加速。GPU则是极大规模的SIMD/SIMT架构。

## 3. 多核处理器与并行架构

### 3.1. 多核结构

多核处理器将两个或更多的CPU核心集成在同一芯片上，共享最后一级Cache（通常是L3）和内存控制器。

**为什么多核有效**：
- 多个核心可以同时处理不同的任务（多任务并行）
- 一个任务可以拆分成多个子任务分配到不同核心（并行计算）
- 共享L3 Cache减少了核心间数据交换的开销

### 3.2. 对称多处理（SMP）vs 非一致内存访问（NUMA）

| 对比项 | SMP（对称多处理） | NUMA（非一致内存访问） |
|:------|:---------------:|:--------------------:|
| **内存访问** | 所有核心访问内存的时间**相等** | 核心访问"本地"内存比"远程"内存**更快** |
| **架构** | 共享总线/交叉开关 | 每个CPU有自己的本地内存，通过高速互连连接 |
| **扩展性** | 差（8核以上总线成为瓶颈） | **好**（可扩展到数十/数百核） |
| **编程难度** | 低——所有内存访问一致 | 高——需要考虑数据本地性 |
| **典型应用** | 中小型服务器、桌面PC | 大型服务器、HPC（高性能计算） |

> **通俗理解**：SMP就像一群人围坐在一张圆桌旁——每个人到桌子中心的距离相同，取东西时间一样。NUMA就像一个大图书馆分成几个区域——每个人离自己最近的书架最快，要去远处的书架就慢一些。NUMA的扩展性更好——图书馆再大，只需要增加新的区域，每个人仍然有自己的近处书架。

### 3.3. 多核处理器的技术挑战

| 挑战 | 说明 |
|:----|:------|
| **Cache一致性** | 各核心的私有Cache中同一数据可能产生不同副本——需要协议保证一致性 |
| **内存一致性** | 多核下数据写入的顺序如何被其他核心感知 |
| **同步与锁** | 竞争条件（race condition）——多个核心同时写同一变量 |
| **并行编程** | 将程序分解为并行任务——远串行执行困难得多 |

## 4. Cache一致性协议：MESI

### 4.1. 问题的产生

在多核CPU中，每个核心都有私有Cache（L1/L2）。如果两个核心同时缓存了主存中的同一数据，其中一个修改了它——另一个核心Cache中的旧副本就变得不正确了。**Cache一致性协议**（cache coherence protocol）就是用来解决这个问题的。

### 4.2. MESI协议的四种状态

**MESI**（Modified/Exclusive/Shared/Invalid）是最经典的Cache一致性协议。

| 状态 | 含义 | 该行数据是否与主存一致 | 其他核心中是否存在副本 |
|:----|:----|:----------------:|:-------------------:|
| **M** | Modified（已修改） | ❌ 不一致（被本核心修改了） | ❌ 独占 |
| **E** | Exclusive（独占） | ✅ 一致 | ❌ 独占（但未修改） |
| **S** | Shared（共享） | ✅ 一致 | ✅ 其他核心也有副本 |
| **I** | Invalid（失效） | — | —（该行数据无效） |

### 4.3. 状态转换

**核心转换规则**：
- **E → M**：本核心写该数据（独占→已修改，状态升级）
- **E → S**：其他核心读取该数据（独占→共享，因为产生了另一个副本）
- **M → I**：其他核心写该数据（已修改→失效，旧版本已作废）
- **S → I**：其他核心写该数据（共享→失效）
- **S → E**：所有其他核心的副本都失效后（需要通过总线嗅探确认）

> **通俗理解**：MESI协议就像几个人一起修改一份文档——
> - **M**：只有你手里有最新版，别人手里的都是旧的（你修改了但没提交到服务器）
> - **E**：你手里有唯一的一份，但还没改
> - **S**：几个人手里都有同一份，内容和服务器一致
> - **I**：你手里的已经过时了，需要重新从服务器获取

## 5. GPU架构简介

### 5.1. GPU vs CPU的设计哲学

| 对比项 | CPU | GPU |
|:------|:----|:----|
| **设计目标** | 低延迟——快速处理单个任务 | **高吞吐量**——同时处理海量任务 |
| **核心数** | 少（4~16）但每个核心功能强大 | **非常多**（数千个），但每个核心较小 |
| **Cache** | 大容量Cache（减少延迟） | 小Cache（面积匀给计算单元） |
| **控制单元** | 复杂——分支预测、乱序执行 | 简单——一个控制单元管多个计算单元 |
| **典型应用** | 通用计算、操作系统、单线程任务 | 图形渲染、**并行计算**（矩阵乘法、深度学习） |

**形象的对比**：

```
CPU：像一辆法拉利——跑得极快但只能坐2人
GPU：像一辆大巴车——跑得不如法拉利快，但一次能载50人
```

### 5.2. GPU的SIMT执行模型

GPU采用**SIMT**（Single Instruction, Multiple Threads，单指令多线程）模型——与SIMD类似但更灵活：

- 多个线程（thread）被组织成**线程束**（warp/wavefront，通常32个线程）
- 一个线程束中的所有线程**执行同一条指令**
- 每个线程可以处理不同的数据

**SIMT vs SIMD的区别**：

| 对比项 | SIMD（CPU） | SIMT（GPU） |
|:------|:----------|:-----------|
| 数据粒度 | 向量寄存器中的元素 | 独立的线程 |
| 分支处理 | 需显式处理 | 线程束内分支会序列化 |
| 灵活性 | 弱——数据必须对齐 | **强**——线程可独立寻址 |

### 5.3. GPU的典型应用

| 领域 | 应用 |
|:----|:------|
| **图形渲染** | 3D建模、游戏、视觉效果 |
| **深度学习** | 神经网络训练与推理——矩阵乘法正是GPU的强项 |
| **科学计算** | 气象模拟、分子动力学、有限元分析 |
| **加密货币挖矿** | SHA-256等哈希计算的并行加速 |
| **视频编解码** | 高清视频的编码与解码加速 |

## 6. 并行编程模型概要

### 6.1. 线程级并行

| 模型 | 说明 | 典型库/框架 |
|:----|:-----|:-----------|
| **共享内存** | 多线程共享同一地址空间（需处理竞争条件） | pthreads、OpenMP |
| **消息传递** | 每个进程有独立地址空间，通过消息通信 | MPI（Message Passing Interface） |
| **数据并行** | 将数据分片，每个处理单元处理一部分 | CUDA、OpenCL |

### 6.2. Amdahl定律的并行版本

**回顾Amdahl定律**：系统加速比受限于串行部分的比例。

$$
S_n = \frac{1}{(1 - f) + f/n}
$$

其中：
- $f$ = 可并行化部分的比例
- $n$ = 处理器核心数
- $S_n$ = 加速比

> **重要结论**：即使使用无限多的核心，加速比也无法超过 $1/(1-f)$。如果程序只有90%可并行，即使1000个核心，最大加速比也只有10倍。这提醒我们——**并行编程要重点关注串行瓶颈的消除**。

## 习题11：并行体系结构与多核处理器

### 11.1 概念题

1. **Flynn分类法将计算机分为哪四类？各举一例。**

> **答**：SISD（单核CPU）、SIMD（GPU/向量处理器）、MISD（容错系统）、MIMD（多核CPU）。现代CPU是MIMD+SIMD的结合。

2. **什么是Cache一致性问题？MESI协议的四种状态分别是什么？**

> **答**：多核处理器中，各核心的私有Cache可能持有同一数据的不同副本，一个核心修改后需要让其他核心知道。MESI四种状态：M（已修改，与主存不一致）、E（独占，与主存一致）、S（共享，其他核心也有副本）、I（失效）。

3. **SMP和NUMA有什么区别？**

> **答**：SMP中所有核心访问内存时间相同（通过共享总线/交叉开关），扩展性受限；NUMA中核心访问本地内存比远程内存更快，扩展性好但编程需考虑数据本地性。

4. **GPU和CPU的设计目标有何不同？**

> **答**：CPU面向低延迟（单线程性能优先），复杂控制单元+大Cache；GPU面向高吞吐量（并行处理优先），大量简单计算核心+小Cache。

### 11.2 计算题

5. **某程序可并行部分比例f=0.95，用100个核心执行，求加速比。若f=0.99呢？**

> **解**：$f=0.95$时，$S_n = 1/((1-0.95) + 0.95/100) = 1/(0.05+0.0095) \approx 16.8$。$f=0.99$时，$S_n = 1/(0.01+0.0099) \approx 50.3$。可见并行化比例对加速比影响极大——从95%到99%（仅4%的提升）加速比翻了3倍。

## 本讲核心要点

1. **单核性能三堵墙**：功耗墙（主频→散热极限）、ILP极限（超标量收益递减）、存储墙（内存跟不上CPU）
2. **Flynn四分类**：SISD（单核）、SIMD（GPU/向量）、MISD（容错）、MIMD（多核）——现代CPU多是MIMD+SIMD混合
3. **多核的核心优势**：不追求单核更快，而是通过并行提高吞吐量——多个"慢而多"的核心好过一个"快而少"的核心
4. **SMP vs NUMA**：SMP一致性访问好但扩展性差，NUMA扩展性好但需要数据本地性优化
5. **MESI四种状态**：M（已修改）、E（独占）、S（共享）、I（失效）——通过总线嗅探协议保持Cache一致性
6. **GPU设计哲学**：CPU追求**低延迟**（复杂控制+大Cache），GPU追求**高吞吐量**（大量计算核心+小Cache）
7. **SIMT模型**：GPU将32个线程组成线程束（warp），同一条指令在多个数据上并行执行
8. **并行Amdahl定律**：加速比受限于串行部分——$1/(1-f)$是不可逾越的天花板
9. **三种并行编程模型**：共享内存（pthreads/OpenMP）、消息传递（MPI）、数据并行（CUDA）
10. **多核的挑战**：Cache一致性、内存一致性、同步与锁、并行编程难度——"用更多核心"远不是一件简单的事
