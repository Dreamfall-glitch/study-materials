# 02-总线系统

```知识地图
总线基本概念（共享、分时）
    ↓
三组系统总线：数据总线(DB) / 地址总线(AB) / 控制总线(CB)
    ↓
总线结构：单总线 → 双总线 → 三总线
    ↓

    ↓

```

**本讲回答的核心问题**：总线是什么？计算机中各部件如何通过总线连接？多个设备争用总线时如何仲裁？总线的数据传输率如何计算？

## 1. 总线的基本概念

### 1.1. 为什么需要总线

计算机的五大部件（运算器、控制器、存储器、输入设备、输出设备）之间需要频繁地传输信息。如果每个部件之间都用独立的线路连接，连接数量将呈组合爆炸增长。**总线**（bus）的引入解决了这一问题——所有部件共享一组公共传输线。

### 1.2. 总线的定义与特点

**总线**：一组能为多个部件**分时共享**的公共信息传输线路。

> **通俗理解**：总线就像城市的"主干道"——所有车辆（数据）都在同一条道路上行驶，但同一时刻只能有一辆车通过某个路口（分时共享）。如果没有主干道，每两个建筑之间都要修一条专用路，城市将无法规划。

总线传输的两个基本特点：

| 特点 | 含义 |
|:----|:------|
| **共享**（share） | 总线上可以挂接多个部件，所有部件共用这组线路 |
| **分时**（time-sharing） | 同一时刻只允许一个部件向总线发送信息，多个部件需分时使用 |

### 1.3. 减轻总线负载的措施

总线上的部件都应具备以下特点，以减轻总线负载：
- **高输入阻抗**：对总线呈现高阻态，减少对总线信号的衰减
- **三态输出**：不占用总线时输出呈高阻态，与总线"断开"
- **驱动能力有限**：总线上挂接的部件数量不能过多

### 1.4. 总线分类

按连接部件不同：

| 分类 | 连接范围 | 特征 |
|:----|:---------|:------|
| **片内总线** | CPU芯片内部寄存器与ALU之间 | 芯片内部连线，速度最高 |
| **系统总线** | CPU、主存、I/O各部件之间 | 计算机系统的"主干道"（本章重点） |
| **通信总线** | 计算机与外部设备/网络之间 | 如USB、RS-232、以太网 |

### 1.5. 系统总线的三组分类

系统总线按传输内容分为三类：

| 总线类型 | 传输内容 | 方向 | 宽度决定因素 |
|:--------|:---------|:---:|:------------|
| **数据总线**（DB, Data Bus） | 数据信息（指令、操作数） | **双向** | 与机器字长、存储字长有关 |
| **地址总线**（AB, Address Bus） | 地址信息（内存地址、I/O地址） | **单向**（CPU发出） | 地址线根数决定寻址空间大小 |
| **控制总线**（CB, Control Bus） | 控制信号（读/写/中断/总线请求等） | **双向**（每根方向固定） | 每根传输一种控制信号 |

> **自己的话**：可以把系统总线想象成一个交通系统——数据总线是"双向车道"，数据可以来也可以去；地址总线是"单向车道"，CPU永远是司机，告诉存储器读哪个位置；控制总线是"交通信号灯"，每根信号灯控制一种操作。

**地址总线宽度与寻址空间的关系**：

$$
\text{可访问的存储单元数量} = 2^{\text{地址线根数}}
$$

例如：
- 20根地址线 → $2^{20} = 1\text{MB}$ 寻址空间
- 32根地址线 → $2^{32} = 4\text{GB}$ 寻址空间
- 64根地址线 → $2^{64}$（极大，几乎无限制）

## 2. 总线结构

随着计算机性能的发展，总线结构经历了从单总线到多总线的演进。

### 2.1. 单总线结构

```
CPU   主存    I/O设备1    I/O设备2    ...
 ┌────┐ ┌────┐ ┌────────┐ ┌────────┐
 │    │ │    │ │        │ │        │
 └──┬─┘ └──┬─┘ └───┬────┘ └───┬────┘
    └──────┴───────┴──────────┘   ← 系统总线
```

**特点**：所有部件都挂在同一组总线上，结构简单，成本低。

**缺点**：所有信息传输都经过这组总线，总线成为系统性能的**瓶颈**。

### 2.2. 双总线结构

在CPU和主存之间增加一组专用的**存储总线**（M总线），主存与CPU之间的数据不再经过系统总线：

```
CPU ─── 存储总线 ─── 主存
 │
 └── 系统总线 ─── I/O设备
```

**特点**：CPU访问主存和I/O设备使用不同的总线，减少了系统总线的竞争。

### 2.3. 三总线结构

进一步分离，增加DMA总线：

- **存储总线**：CPU ↔ 主存
- **系统总线**：CPU ↔ I/O
- **DMA总线**：高速I/O设备（磁盘、显卡） ↔ 主存（不经CPU）

```
CPU ─── 存储总线 ─── 主存
 │                    │
 │                    ├── DMA总线 ── 高速I/O
 │                    │
 └── 系统总线 ── I/O设备
```

> **通俗理解**：单总线就像一条窄巷子，所有人和车都挤在一起；双总线相当于给重要人物（CPU和主存）修了一条专用通道；三总线更进一步，给快递车（DMA高速设备）也修了专用通道，不再经过CPU中转。

## 3. 总线设备与总线仲裁

### 3.1. 主设备与从设备

总线上连接的各类设备，按其对总线有无控制功能可分为两类：

| 类型 | 定义 | 例子 |
|:----|:-----|:-----|
| **主设备**（master/主模块） | 对总线有**控制权**，能主动发起总线传输 | CPU、DMA控制器 |
| **从设备**（slave/从模块） | 只能**响应**主设备发来的总线命令，对总线没有控制权 | 主存、普通I/O设备 |

### 3.2. 为什么要总线仲裁

如果多个主设备同时要使用总线，必须由**总线仲裁机构**（bus arbiter）确定哪个主设备能获得总线使用权，该设备获得使用权后才能开始传输数据。

### 3.3. 三种集中式总线仲裁方式

| 仲裁方式 | 工作原理 | 优点 | 缺点 |
|:--------|:---------|:----|:-----|
| **链式查询**（daisy chain） | 总线授权信号BG串行通过每个设备，最先收到BG的设备获得控制权 | 电路简单，容易扩展 | 对电路故障**最敏感**（一个设备故障会导致链路中断），优先级低的设备可能很难获得请求 |
| **计数器定时查询** | 计数器从"0"开始计数，计数到某个设备号时该设备获得总线使用权 | 优先级可调整（计数可循环，初值可由程序设置） | 需要计数器和查询定时 |
| **独立请求**（independent request） | 每个主设备有独立的总线请求线和授权线，仲裁器统一裁决 | **响应时间最快**，优先级控制灵活（可通过程序改变） | 控制线数量多，硬件复杂 |

> **理解三种仲裁方式**：
> - **链式查询**：像排队吃饭——最前面的人吃完了才能轮到后面。如果有人赖着不走或结账太慢，后面的人只能干等（对电路故障敏感）。
> 
> - **计数器查询**：像抽号叫号——从"1号"开始叫，叫到谁谁去办。可以设置今天从"10号"开始叫（改变优先级），也可以叫完一轮重新循环。
> 
> - **独立请求**：像VIP通道——每个人都有专属的申请线和通知线，经理（仲裁器）根据优先级表快速决定谁先上。

## 4. 总线的通信控制

### 4.1. 同步通信

同步通信（synchronous communication）由统一的**时钟信号**控制，所有设备按固定的时间节拍进行数据传输。

**特点**：
- 有统一的时钟
- 传输速率高
- 所有设备必须在规定时间内完成操作
- 适用于速度相近的部件之间

### 4.2. 异步通信

异步通信（asynchronous communication）采用**应答方式**（handshaking），没有统一时钟，通信双方通过"请求-回答"信号协调。

异步通信中请求与回答有三种互锁关系：

| 互锁类型 | 描述 |
|:--------|:-----|
| **不互锁** | 主设备发出请求后，不必等待从设备的回答即可撤销请求；从设备发出回答后也无需等待请求撤销 |
| **半互锁** | 主设备发出请求后，必须等待从设备回答后才撤销请求；但从设备回答后不等待请求撤销 |
| **全互锁** | 主设备发出请求后，必须等待从设备回答才撤销请求；从设备也必须等到请求撤销后才撤销回答——最可靠 |

### 4.3. 同步 vs 异步对比

| 对比项 | 同步通信 | 异步通信 |
|:------|:--------|:---------|
| 时钟 | 统一时钟 | 无统一时钟 |
| 速度 | 快 | 慢 |
| 灵活性 | 要求设备速度匹配 | 可连接不同速度的设备 |
| 可靠性 | 高（时间确定） | 高（通过应答保证） |
| 复杂性 | 简单 | 较复杂 |

## 5. 总线性能指标与计算

### 5.1. 关键概念

| 概念 | 定义 |
|:----|:-----|
| **总线宽度** | 数据总线的根数，如32位、64位 |
| **总线带宽**（数据传输率） | 单位时间内总线上可传输的数据量 |
| **总线复用** | 同一组信号线在不同时间传输不同的信息（如地址和数据分时复用） |
| **总线周期** | 一次完整的总线操作（申请→寻址→传输→结束）所需时间 |

### 5.2. 总线带宽计算公式

总线带宽 = 总线宽度 × 总线频率

在实际中需要考虑传输周期：
$$
\text{总线带宽} = \frac{\text{总线宽度}}{\text{传输周期}} = \frac{\text{总线宽度} \times \text{时钟频率}}{\text{时钟周期数/传输}}
$$

**例题**（来自你的笔记例3.1）：假设总线的时钟频率为100MHz，总线的传输周期为4个时钟周期，总线的宽度为32位（4字节），试求总线的数据传输率。若想提高一倍数据传输率，可采取什么措施？

**解**：

时钟周期 $t = 1/100\text{MHz} = 10\text{ns}$

传输周期 $T = 4 \times 10\text{ns} = 40\text{ns}$

数据传输率 $= \frac{4\text{B}}{40\text{ns}} = 100\text{MB/s}$

**提高措施**：
- 提高总线时钟频率（如提高到200MHz）
- 减少传输周期所占的时钟周期数（如由4个减为2个）
- 增加数据总线宽度（如由32位增至64位）

### 5.3. 总线标准演进

常见标准总线的性能对比：

| 总线标准 | 宽度 | 频率 | 数据传输率 | 特点 |
|:--------|:----:|:----:|:----------:|:-----|
| **ISA**（工业标准结构） | 16位 | 8MHz | 16MB/s | 早期PC标准 |
| **EISA**（扩展ISA） | 32位 | 8.33MHz | 33MB/s | 兼容ISA |
| **PCI** | 32/64位 | 33MHz | 133/266MB/s | 即插即用，曾广泛使用 |
| **AGP**（加速图形端口） | 32位 | 66MHz | 266MB/s~2.1GB/s | 专用于显卡 |
| **PCIe**（PCI Express） | 串行 | 逐代提升 | 每通道~1GB/s(Gen3) | **现代主流** |

## 6. 现代总线技术（补充）

### 6.1. PCI Express（PCIe）

PCIe是当前最主流的计算机内部互连标准，与传统的并行总线（PCI、ISA）有本质区别：

| 对比项 | 传统PCI（并行） | PCIe（串行） |
|:------|:--------------|:------------|
| **传输方式** | 并行（32/64根数据线同时传输） | **串行**（差分对，一对发送一对接收） |
| **拓扑** | 共享总线（所有设备争用） | **点到点**（每个设备有专用通道） |
| **传输方式** | 基于信号线电平 | **基于数据包**（packet-based） |
| **全双工** | 半双工 | **全双工**（可同时收发） |
| **带宽扩展** | 增加位宽（困难） | **增加通道数**（×1/×4/×8/×16，灵活扩展） |

> **通俗理解**：传统PCI就像一条**多车道的老路**——看起来宽（并行），但所有车共享同一条路，一辆车堵住大家都动不了。PCIe像是把单车道变成了**高速列车系统**——虽然每列车只有一对轨道（串行），但每对设备都有专用轨道（点到点），而且可以双向同时发车（全双工），需要更大运力时只需增加轨道对数（×16）。

**PCIe的拓扑结构**：

```
CPU
  │
根联合体 (Root Complex)
  │
  ├── PCIe交换机 ─── PCIe端点（网卡）
  │
  ├── PCIe端点（显卡）
  │
  └── PCIe端点（SSD）
```

### 6.2. 片上互连（NoC）

**NoC**（Network on Chip，片上网络）是在单芯片上替代传统总线互连的技术。

随着多核处理器的发展，芯片内部集成的核心越来越多，传统的共享总线成为瓶颈——NoC将计算机网络的概念引入芯片内部：

| 对比项 | 传统总线（片上） | NoC |
|:------|:--------------|:----|
| **拓扑** | 共享总线 | 网格/环形/交叉开关 |
| **扩展性** | 差（核数增加→竞争加剧） | **好**（可扩展到数百核） |
| **带宽** | 共享，受限 | **随着核数增加而增加** |
| **功耗** | 全局连线长，功耗大 | 局部互连，功耗低 |
| **应用** | 少量CPU核 | 众核处理器（如GPU、网络处理器） |

> **通俗理解**：传统总线就像只有一个十字路口的老城区——车多了就堵死。NoC就像城市中规划了网格状的道路系统——每个路口只负责局部交通，整体可以支持更大的车流量。

## 习题2：总线系统

### 2.1 概念题

1. **什么是总线？总线传输有何特点？为了减轻总线的负载，总线上的部件都应具备什么特点？**

> **答**：总线是一组能为多个部件分时共享的公共信息传输线路。总线传输的特点是**共享**（多个部件共用）和**分时**（同一时刻只允许一个发送）。为减轻负载，部件应具备**高输入阻抗**和**三态输出**能力。

2. **总线如何分类？什么是系统总线？系统总线又分为几类？它们各有何作用？是单向的还是双向的？**

> **答**：总线按连接范围分为片内总线、系统总线和通信总线。**系统总线**是连接CPU、主存、I/O部件的总线，分为三类：**数据总线**（双向，传输数据/指令）、**地址总线**（单向，CPU发送地址，决定寻址空间）、**控制总线**（双向，每根方向固定，传输控制信号）。

3. **常用的总线结构有哪几种？不同的总线结构对计算机性能有什么影响？**

> **答**：主要有单总线结构、双总线结构和三总线结构。从单到多的发展，实质上是将CPU、主存、I/O之间的信息传输分开，减少总线竞争，提高系统吞吐率。单总线结构简单但瓶颈明显；双总线增加了存储总线；三总线增加了DMA总线，适合高速设备。

4. **为什么要设置总线判优控制？常见的集中式总线控制有几种？各有何特点？哪种方式响应时间最快？哪种对电路故障最敏感？**

> **答**：多个主设备同时请求使用总线时，需要仲裁决定哪个先获得使用权。三种方式：**链式查询**（电路简单，对故障最敏感）、**计数器查询**（优先级可调）、**独立请求**（响应最快，优先级控制灵活）。

5. **解释概念：总线宽度、总线带宽、总线复用、总线周期。**

> **答**：**总线宽度**=数据总线根数；**总线带宽**=单位时间传输的数据量；**总线复用**=同一组线在不同时间传输不同信息；**总线周期**=一次完整的总线操作时间。

6. **试比较同步通信和异步通信。**

> **答**：同步通信有统一时钟，速率高但要求设备速度匹配；异步通信无统一时钟，通过应答方式工作，可连接不同速设备，但速率较低。

### 2.2 计算题

7. 假设总线的时钟频率为100MHz，总线的传输周期为4个时钟周期，总线宽度为32位，求总线的数据传输率。若想提高一倍数据传输率，可采取什么措施？

> **解**：时钟周期=1/100MHz=10ns，传输周期=4×10ns=40ns，总线宽度=4B。数据传输率=4B/40ns=100MB/s。提高措施：频率加倍（200MHz）、减少传输周期（2个时钟周期）、增加宽度（64位）。

### 2.3 简答题

8. **简述PCIe与传统PCI的主要区别。**

> **答**：PCIe采用串行点对点传输（替代并行共享总线）、基于数据包传输（替代电平信号）、全双工可同时收发、通过增加通道数（×1/×4/×16）灵活扩展带宽。相比之下，传统PCI是并行共享总线，所有设备争用同一带宽。

## 本讲核心要点

1. **总线是计算机的"主干道"**——为多个部件提供分时共享的公共传输线路，核心特点是共享和分时
2. **系统总线三组线**：数据总线（双向、宽度决定吞吐率）、地址总线（单向、根数决定寻址空间）、控制总线（双向、每根控制一种操作）
3. **地址总线根数决定最大寻址空间**：$N$根地址线可寻址 $2^N$ 个存储单元
4. **总线结构演进**：单总线 → 双总线（存储总线分离）→ 三总线（DMA总线分离），逐步解决竞争问题
5. **三种总线仲裁方式**：链式查询（简单但故障敏感）、计数器查询（优先级可调）、独立请求（最快最灵活）
6. **异步通信三种互锁**：不互锁（最不可靠）→ 半互锁 → 全互锁（最可靠）
7. **总线带宽计算**：带宽 = 总线宽度/传输周期 = 总线宽度×时钟频率/每传输所需时钟数
8. **总线标准演进**：ISA(16MB/s) → PCI(133MB/s) → AGP(图形专用) → **PCIe**(串行点对点，Gen3单通道~1GB/s)
9. **PCIe核心优势**：串行差分传输、点对点拓扑、全双工、基于数据包、通过通道数（lanes）灵活扩展
10. **NoC片上网络**：替代传统总线用于多核/众核芯片内部互连——网格拓扑，可扩展到数百核
