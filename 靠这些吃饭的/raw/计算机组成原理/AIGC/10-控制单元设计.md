# 10-控制单元设计

```知识地图
控制单元(CU)的功能是什么？
    ↓
两种设计方式
    ├── 组合逻辑控制器（硬布线）—— 硬件实现，速度快
    └── 微程序控制器—— 存储逻辑，灵活
    ↓
微程序控制器的核心
    ├── 微指令格式：水平型 vs 垂直型
    ├── 微指令编码：直接编码 / 字段直接编码 / 混合编码
    └── 微地址形成：断定方式 / 增量计数 / 操作码映射 / 测试网络
```

**本讲回答的核心问题**：控制单元是如何发出各种控制信号的？组合逻辑和微程序两种设计方式有何本质区别？微指令的编码和地址如何设计？

## 1. 控制单元概述

### 1.1. 控制单元的功能

控制单元（CU，Control Unit）是CPU的"指挥中心"，其主要功能是**发出各种不同的控制信号**。

**CU的输入**（来自你的笔记P60 → P58）：

| 输入来源 | 作用 |
|:--------|:------|
| **时钟信号** | 提供时序基准——控制各种微操作出现的节拍 |
| **指令寄存器的操作码字段** | 决定当前执行什么指令——译码后产生相应的控制信号 |
| **标志位**（Flags） | 决定条件判断——如CF/ZF/SF/OF影响条件转移指令 |
| **来自系统总线的控制信号** | 如中断请求、总线请求等外部信号 |

### 1.2. 控制单元的内部工作

控制单元在时钟信号、指令操作码译码输出、标志位以及中断系统和时序电路的共同作用下，产生一系列控制信号，发至CPU内部及系统总线。

具体过程（来自你的笔记P60）：

```
指令 → IR → OP(IR) → CU译码器
                            ↓
时序信号 + 标志位 + 中断信号 → CU组合逻辑/微程序
                            ↓
          产生微操作控制信号 → 各执行部件
```

## 2. 两种设计方法：组合逻辑 vs 微程序

控制器有两种基本设计方法。

### 2.1. 组合逻辑控制器（硬布线控制器）

**设计思想**：用组合逻辑电路（门电路构成的复杂树形网络）直接产生每一个微操作的控制信号。

**设计步骤**（来自你的笔记P61）：

```
首先根据指令系统 → 列出所有指令的微操作序列
    ↓
列出操作时间表 → 写出每个微操作的逻辑表达式
    ↓
用门电路实现逻辑表达式 → 构成硬件控制器
```

**特点**：
- 控制信号直接由硬件产生，**执行速度最快**
- 一旦构成后，除非在物理上重新连线，否则无法增加新的控制功能
- 电路复杂，设计难度大
- **RISC处理器典型采用**——如ARM、MIPS、RISC-V

### 2.2. 微程序控制器

**设计思想**（来自你的笔记P61 → 10.9）：采用**存储逻辑**——将微操作控制信号以代码形式存储在ROM中，执行时依次读出。

**设计步骤**：

```
根据指令系统 → 写出所有机器指令的全部微操作及其节拍安排
    ↓
列出操作时间表
    ↓
根据微操作数目 → 确定微指令的控制方式、下地址形成方式、微指令格式
    ↓
编写全部微指令的代码
    ↓
将微指令代码写入ROM → 作为微操作的命令信号
```

**特点**：
- 微程序存放在ROM中，**修改微程序即可增加/修改指令**——极其灵活
- 执行速度比组合逻辑慢（需要从ROM中读取微指令）
- 设计规整、易于调试和修改
- **CISC处理器典型采用**——如x86系列

### 2.3. 两种方式的对比（来自你的笔记P61）

| 对比项 | 组合逻辑（硬布线） | 微程序 |
|:------|:---------------|:-------|
| **设计方式** | 硬件连线逻辑 | 存储逻辑（微程序存在ROM中） |
| **执行速度** | **更快**（硬件直接产生） | 较慢（需从ROM读取） |
| **灵活性** | 差——无法增加新功能 | **好**——修改微程序即可 |
| **设计复杂度** | 复杂（树形网络） | 规整（表格+编码） |
| **典型应用** | **RISC**（ARM、RISC-V） | **CISC**（x86） |
| **修改成本** | 需重新设计电路 | 只需更换ROM |

> **如何理解**：
> 1. 组合逻辑控制器就像用"硬件电路直接实现"——每条控制信号都是通过逻辑门直接从输入推导出来的，像一个定制的专用电路，效率高但死板。
> 
> 2. 微程序控制器像一个"微型计算机在计算机内部"——它有自己的程序（微程序）、存储器（ROM）和指令（微指令），通过执行微程序来产生控制信号，灵活但慢一些。
> 
> 3. 现代x86 CPU实际采用"组合逻辑+微程序"混合方式——常用简单指令用组合逻辑快速执行，复杂指令用微程序实现。

## 3. 微指令的格式

### 3.1. 基本概念

**微指令**（microinstruction）：存放在微程序存储器（ROM）中的、一组实现一个机器周期中全部微操作的二进制代码。

**微程序**（microprogram）：一系列微指令的序列。每一条机器指令对应一个微程序。

### 3.2. 水平型微指令 vs 垂直型微指令（来自你的笔记P61）

| 对比项 | 水平型微指令 | 垂直型微指令 |
|:------|:-----------|:-----------|
| **并行操作能力** | **强**——一次能执行多个微操作 | 弱——一次只执行一个微操作 |
| **效率** | 高 | 低 |
| **灵活性** | 强 | 弱 |
| **微指令字长** | **长**（用宽度换长度） | **短**（用长度换宽度） |
| **微程序长度** | **短**（一条机器指令所需微指令少） | **长**（需更多条微指令） |
| **与机器指令的关系** | 差别较大 | 相似 |
| **执行速度** | **快** | 慢 |
| **控制存储器容量要求** | 大 | 小 |

> **通俗理解**：水平型微指令像一张"总任务单"——一次告诉所有工人都做什么（每个bit控制一个动作），效率高但任务单长。垂直型微指令像"逐个命令"——每个命令只告诉一个人做什么，命令条数多但每条很短。

## 4. 微指令的编码方式

微指令中操作控制字段的编码有三种方式（来自你的笔记P62 → 10.10）：

### 4.1. 直接编码（直接控制）

**原理**：操作控制字段中的**每一位代表一个微命令**。

**特点**：
- **优点**：简单直观，输出直接用于控制，**执行速度最快**
- **缺点**：微指令字长很长，导致控制存储器容量较大

### 4.2. 字段直接编码控制

**原理**：将微指令操作控制字段分成若干段，每段经过译码后发出微命令。**每个字段中的微命令必须是互斥的**——即同一字段内的微命令不会在同一时刻出现。

**特点**：
- **优点**：用较少的二进制信息表示较多的微命令信号，缩短了微指令字长
- **缺点**：增加了译码电路，使微程序的执行速度降低
- 这种编码控制又称为**显式控制**

### 4.3. 混合编码

将直接控制和字段编码控制**混合使用**——部分字段直接控制，部分字段编码控制。

**三种方式速度排序**：**直接控制 > 混合编码 > 字段直接编码**

### 4.4. 例题10.4（来自你的笔记P61）

**题目**：某机的微指令格式中共有8个控制字段，每个字段可分别激活5、8、3、16、1、7、25、4种控制信号。分别采用**直接编码**和**字段直接编码**方式设计微指令的操作控制字段，并说明两种方式的操作控制字段各取几位。

**解**：

**(1) 直接编码方式**

操作控制字段的总位数等于控制信号数：

$$5 + 8 + 3 + 16 + 1 + 7 + 25 + 4 = 69\text{位}$$

**(2) 字段直接编码方式**

每个控制字段至少要留一个码字表示"不激活任何一条控制线"，因此各字段分别需给出：

| 字段 | 控制信号数 | 所需状态数 | 所需位数 |
|:----|:---------:|:---------:|:--------:|
| 字段1 | 5 | 6（5+1） | 3位（2³=8≥6） |
| 字段2 | 8 | 9 | 4位 |
| 字段3 | 3 | 4 | 2位 |
| 字段4 | 16 | 17 | **5位** |
| 字段5 | 1 | 2 | **1位**（2个状态：激活/不激活） |
| 字段6 | 7 | 8 | 3位 |
| 字段7 | 25 | 26 | **5位** |
| 字段8 | 4 | 5 | 3位 |

操作控制字段总位数：
$$3 + 4 + 2 + 5 + 1 + 3 + 5 + 3 = 26\text{位}$$

比直接编码的69位减少了超过一半！

## 5. 微指令地址的形成

微指令的地址有六种形成方式（来自你的笔记P62 → 10.13）：

| 方式 | 说明 | 特点 |
|:----|:-----|:------|
| **① 下地址字段（断定方式）** | 微指令中直接给出后续微指令的地址 | 最常用——大部分指令顺序执行 |
| **② 根据操作码形成** | 指令取至IR后，由操作码经微地址形成部件生成 | 适用于取指周期结束后进入执行周期 |
| **③ 增量计数器法** | $(CMAR) + 1 \rightarrow CMAR$ | 后续微指令地址连续时 |
| **④ 根据标志决定分支** | 根据条件标志（CF/ZF等）决定微地址转移 | 用于条件微程序分支 |
| **⑤ 测试网络形成** | 微地址分H段（非测试地址）和L段（测试地址），L段通过测试网络形成 | 地址格式更灵活 |
| **⑥ 硬件产生入口地址** | 上电、中断、间址时由硬件电路产生微程序入口地址 | 如加电后自动指向取指周期微程序 |

> **通俗理解**：微程序中的地址控制和机器指令中的地址控制非常相似——有顺序执行（增量）、有分支（标志判断）、有子程序调用（中断入口）。如果把机器指令看作"宏观程序"，微指令就是"微观程序"——这是"计算机中有计算机"的体现。

## 习题10：控制单元设计

### 10.1 概念题

1. **控制单元的功能是什么？其输入受什么控制？**

> **答**（来自你的笔记P58 → 9.2）：控制单元的主要功能是发出各种不同的控制信号。其输入受**时钟信号**、**指令寄存器的操作码字段**、**标志位**和**来自系统总线的控制信号**控制。

2. **试比较组合逻辑设计和微程序设计的步骤和硬件组成，说明哪一种控制速度更快，为什么？**

> **答**（来自你的笔记P61 → 10.9）：组合逻辑设计用门电路构成树形网络直接产生控制信号——速度快，因为完全由硬件完成；但一旦设计完成无法增加控制功能。微程序设计采用存储逻辑（微程序存储在ROM中）——灵活但慢（需读ROM）。组合逻辑控制速度更快。

3. **微指令的操作控制有几种编码方式？各有何特点？哪一种控制速度最快？**

> **答**（来自你的笔记P62 → 10.10）：三种——直接编码（每位代表一个微命令，速度快但字长）、字段直接编码（分组译码，字长短但速度慢）、混合编码（两者结合）。直接控制速度最快。

4. **微指令的地址有哪几种形成方式？**

> **答**（来自你的笔记P62 → 10.13）：六种——①下地址字段（断定方式）、②操作码映射、③增量计数法、④标志分支、⑤测试网络（H+L段）、⑥硬件产生入口地址。

### 10.2 计算题

5. **例题10.4**：同上文——直接编码69位，字段直接编码26位。

### 10.3 简答题

6. **水平型微指令和垂直型微指令各有什么特点？**

> **答**（来自你的笔记P61）：水平型——并行操作能力强、效率高、灵活性强、微指令字长较长、微程序结构短——用较短的微程序结构换取较长的微指令结构；垂直型——相反，用较长的微程序结构换取较短的微指令结构。水平型微指令与机器指令差别较大，垂直型微指令与机器指令相似。

## 本讲核心要点

1. **CU的四大输入**：时钟信号、指令操作码、标志位、总线控制信号——共同决定每个时刻发出的控制信号
2. **组合逻辑 vs 微程序**：组合逻辑（硬件实现，**更快**） vs 微程序（存储逻辑，**更灵活**）——RISC用组合逻辑，CISC用微程序
3. **微程序控制器的本质**："计算机中的计算机"——用存储在ROM中的微程序来解释执行机器指令
4. **水平型微指令**：宽字短程序，并行能力强，速度快；**垂直型微指令**：窄字长程序，与机器指令相似
5. **三种微指令编码方式**：直接编码（最快但最宽）→ 字段直接编码（较慢但最窄）→ 混合编码（折中）
6. **字段直接编码**：每个字段内微命令必须互斥——"同一时刻只能激活一个"，这样才能压缩编码
7. **例题10.4**：直接编码69位 vs 字段直接编码26位——编码效率相差2.65倍
8. **微地址六种形成方式**：断定方式（最常用）+ 操作码映射（指令→微程序入口）+ 增量（顺序）+ 分支（条件）+ 测试网络 + 硬件入口（中断）
9. **组合逻辑控制更快的本质**：控制信号直接从硬件逻辑产生，不需要从ROM读取微指令——少了一级"解释执行"的开销
10. **微程序与RISC/CISC的关系**：现代CPU往往混合使用——简单指令组合逻辑直接执行（如ADD/SUB），复杂指令由微程序辅助
