```知识地图
存储器分类（RAM/ROM、SRAM/DRAM、主存/辅存/Cache）
    ↓
存储器层次结构：CPU寄存器 → Cache → 主存 → 辅存
    ↓

```

**本讲回答的核心问题**：计算机的存储系统是如何分层的？SRAM和DRAM有何区别？如何用多个存储芯片组成更大容量的存储器？Cache如何工作？汉明码如何检错纠错？虚拟存储器如何实现大地址空间？

## 1. 存储器概述

### 1.1. 存储器的分类

#### 按存储介质分类

| 类型 | 介质 | 特点 |
|:----|:-----|:-----|
| **半导体存储器** | MOS管、双极型晶体管 | 速度快，用作主存和Cache |
| **磁表面存储器** | 磁化介质 | 容量大，用作辅存（磁盘） |
| **光盘存储器** | 激光读写介质 | 可移动存储 |
| **铁电/相变存储器** | 特殊材料 | 新型非易失存储器 |

#### 按存取方式分类

```
随机存储器（RAM）：可随机读写，速度高
    ├── SRAM（静态RAM）——用作Cache
    └── DRAM（动态RAM）——用作主存
只读存储器（ROM）：只能读出，不能写入
    ├── 掩膜ROM（出厂写入）
    ├── PROM（可编程一次）
    ├── EPROM（紫外线擦除可编程）
    ├── EEPROM（电擦写可编程，可字节擦写）
    └── Flash Memory（闪速存储器，块擦写）
```

#### 按在计算机中的作用分类

```
CPU内部：寄存器（最快）
    ↓
Cache（高速缓冲存储器）：SRAM
    ↓
主存（主存储器）：DRAM为主
    ↓
辅存（辅助存储器）：磁盘/SSD
```

### 1.2. 存储器层次结构

现代计算机采用**层次化存储体系**（memory hierarchy），其核心思想是利用**程序访问的局部性原理**：

> **程序访问的局部性**（locality of reference）：程序执行时对存储器的访问是不均匀的，指令和数据在主存的地址分布不是随机的，而是相对地**簇生**（clustered）。

两种局部性：

| 类型 | 含义 | 例子 |
|:----|:-----|:-----|
| **时间局部性**（temporal locality） | 刚刚访问过的数据很可能在不久后再次被访问 | 循环变量、堆栈顶 |
| **空间局部性**（spatial locality） | 访问某个地址后，附近的地址很可能也会被访问 | 数组遍历、顺序指令执行 |

层次结构的目标：让CPU访问存储系统的速度**接近最快的那一层**，而容量和价格**接近最便宜的那一层**。

```
层次     典型容量   速度(ns)    每GB价格      由谁管理
寄存器   ~1KB      0.3ns     极高        编译器
  ↓                                    
Cache    ~1MB      1ns       贵         硬件自动
  ↓                                    
主存     ~16GB     50-100ns  中等        操作系统
  ↓                                    
辅存     ~1TB      5-10ms    便宜        操作系统
```

**两个关键层次**：

| 层次对 | 目的 |
|:-------|:-----|
| **Cache-主存** | 从CPU角度**加速**——整体速度≈Cache，容量≈主存 |
| **主存-辅存** | 从程序员角度**扩容**——整体容量≈辅存，速度≈主存 |

### 1.3. 主存的基本技术指标

| 指标 | 定义 |
|:----|:-----|
| **存储容量** | 存储器可存放二进制代码的总量 = 存储单元数 × 存储字长 |
| **存取时间** | 从启动一次访存操作到完成操作所需的时间 |
| **存取周期** | 连续两次独立访存操作所需的最短时间间隔（= 存取时间 + 恢复时间） |
| **存储器带宽** | 单位时间内存储器能读/写的数据量 |

> 存取周期 > 存取时间，因为操作后需要线路恢复。

## 2. 半导体随机存储器

### 2.1. SRAM（静态RAM）

**基本存储单元**：由6个MOS管组成的触发器电路，利用双稳态触发器保存信息。

| 项目 | 说明 |
|:----|:------|
| **存储原理** | 双稳态触发器——只要电源不掉，信息就不会丢失 |
| **速度** | 快（存取周期~10ns） |
| **集成度** | 低（6管/位） |
| **功耗** | 高 |
| **用途** | Cache（高速缓存） |
| **典型芯片** | Intel 2144（1k × 4位，6管MOS） |

### 2.2. DRAM（动态RAM）

**基本存储单元**：用一个MOS管和一个电容（1T1C）组成，利用电容上存储的电荷表示"0"和"1"。

| 项目 | 说明 |
|:----|:------|
| **存储原理** | 电容存储电荷——但电容会**泄漏**，需要定期**刷新**（refresh） |
| **速度** | 慢（存取周期~50-100ns） |
| **集成度** | 高（1管/位） |
| **功耗** | 低 |
| **用途** | 主存 |
| **刷新周期** | 典型值~64ms内对所有行刷新一次 |

### 2.3. SRAM vs DRAM 对比

| 对比项 | SRAM | DRAM |
|:------|:----:|:----:|
| 存储机制 | 双稳态触发器 | 电容存储电荷 |
| 是否需要刷新 | **不需要** | **需要**（64ms内） |
| 存取速度 | 快 | 慢 |
| 集成度 | 低 | **高** |
| 功耗 | 高 | **低** |
| 价格 | 贵 | **便宜** |
| 用途 | Cache | 主存 |
| 破坏性读出 | 否 | **是**（读出后需要重写） |

### 2.4. DRAM技术的演进

| 类型 | 说明 |
|:----|:------|
| **SDRAM**（Synchronous DRAM） | 同步动态RAM——与CPU时钟同步，现代主存的基础 |
| **DDR SDRAM**（Double Data Rate） | 双倍数据率——时钟上升沿和下降沿都传输数据 |
| **RDRAM** | Rambus DRAM——高速但成本高，未广泛普及 |
| **CDRAM** | 带Cache的DRAM——集成小容量SRAM作为缓存 |

## 3. 只读存储器（ROM）与Flash

### 3.1. ROM类型对比

| 类型 | 全称 | 写入方式 | 擦除方式 | 特点 |
|:----|:-----|:---------|:---------|:-----|
| **掩膜ROM** | Mask ROM | 芯片制造时写入 | 不可擦除 | 大批量，固定程序 |
| **PROM** | Programmable ROM | 用户**一次性**写入 | 不可擦除 | 可编程一次 |
| **EPROM** | Erasable PROM | 用户多次写入 | **紫外线**擦除（20min） | 可重复擦写 |
| **EEPROM** | Electrically EPROM | 用户多次写入 | **电擦除**（字节） | 可字节擦写，可在线编程 |
| **Flash** | Flash Memory | 用户多次写入 | **电擦除（块）** | **块擦写**，速度快，密度高 |

> **Flash的特点**：Flash Memory（闪速存储器/快擦型存储器）结合了EPROM的高集成度和EEPROM的电擦除特性，采用**块擦除**（block erase）方式，擦写速度快，是目前最主流的非易失性存储技术（SSD、U盘、手机存储）。

### 3.2. ROM与RAM的对比

| 对比项 | RAM | ROM |
|:------|:----|:----|
| 易失性 | **易失**（断电丢失） | **非易失**（断电保持） |
| 读写 | 可读可写 | 主要读出（写入受限） |
| 用途 | 主存、Cache | 固件、启动程序 |

## 4. 主存容量的扩展（芯片连接）

实际的主存由多个存储芯片组合而成。扩展方式分为**位扩展**和**字扩展**两种。

### 4.1. 位扩展

当芯片的**字长**（每片的数据位数）不满足要求时，需要位扩展——将多片芯片的数据线并联。

**示例**：用1k×4位的芯片组成1k×8位的存储器

- 芯片数 = 8位/4位 = **2片**
- 连接方式：地址线、片选线、读写线全部**并联**，每片的数据线各贡献4位

### 4.2. 字扩展

当芯片的**容量**（字数）不满足要求时，需要字扩展——将多片芯片按地址范围串联。

**示例**：用1k×8位的芯片组成4k×8位的存储器

- 芯片数 = 4k/1k = **4片**
- 连接方式：地址线、数据线**并联**，片选线通过**译码器**连接，每个芯片对应不同的地址范围

### 4.3. 字位同时扩展

实际中往往需要同时进行字扩展和位扩展。

**示例**：用1k×4位的芯片组成4k×8位的存储器

- 字数扩展：4k/1k = 4组（字扩展）
- 位数扩展：8位/4位 = 2片/组（位扩展）
- 总共：4组 × 2片/组 = **8片**

### 4.4. 典型例题

**例**：假设CPU有16根地址线、8根数据线，现有ROM（2k×8位、4k×4位、8k×8位）、RAM（1k×4位、2k×8位、4k×8位）及74138译码器，要求6000H~67FFH为系统程序区（ROM），6800H~6BFFH为用户程序区（RAM），试选择芯片并画出连接图。

**解过程**：

1. **地址范围分析**：
   - ROM：6000H ~ 67FFH → 范围大小 = 67FFH - 6000H + 1 = 800H = 2×16² = 2×256 = 512 = 2k → **2k×8位 ROM** 或等价
   - RAM：6800H ~ 6BFFH → 范围大小 = 6BFFH - 6800H + 1 = 400H = 1k → **1k×8位 RAM** 或等价

2. **芯片选型**（结合可用芯片）：
   - ROM：选 2k×8位 ROM × **1片**
   - RAM：选 1k×4位 RAM × **2片**（位扩展）

3. **地址线分配**：
   - ROM（2k=2¹¹）：A₀~A₁₀地址线，片选由高几位地址通过译码器产生
   - RAM（1k=2¹⁰）：A₀~A₉地址线，片选由译码器产生

4. **片选逻辑**：利用74138译码器，根据A₁₅~A₁₁等高位地址线产生各芯片的片选信号

## 5. Cache（高速缓冲存储器）

### 5.1. Cache的工作原理

Cache位于CPU和主存之间，用于解决**CPU与主存速度不匹配**的问题。

**基本工作流程**：

```
CPU要访问数据
    → 先到Cache中查找（查找依据：地址映射关系）
        ├── 命中（hit）：直接从Cache读取，速度快
        └── 不命中（miss）：到主存中读取该数据，
             并将其所在的一整块（block）调入Cache
```

**块（block）**：Cache和主存之间以**块**为单位进行数据交换。一个块包含若干个连续的存储字。

### 5.2. 映射方式

Cache的三种映射方式决定了主存中的块如何放置到Cache中。下面的示意图和例题来自你的笔记。

#### (1). 直接映射（Direct Mapping）

**原理**：主存中的每个块只能映射到Cache中的**唯一一个位置**。

**主存地址格式**：

```
|  标记（Tag）  |  Cache块号（Index）  |  块内地址（Offset）  |
```

**映射关系**：`Cache块号 = 主存块号 mod Cache总块数`

> **通俗理解**：直接映射就像每个学生（主存块）只能坐在固定的座位号（Cache位置）上——座位号 = 学号 mod 教室座位总数。学生按学号顺序"对号入座"。

#### (2). 全相联映射（Fully Associative Mapping）

**原理**：主存中的任何一个块可以映射到Cache中的**任意一个位置**。

**主存地址格式**：

```
|  标记（Tag）  |  块内地址（Offset）  |
```

> **通俗理解**：全相联像自由入座——空座位都可以坐。灵活度最高，但每次查找时需要比较所有Cache块的标记（硬件开销大）。

#### (3). 组相联映射（Set-Associative Mapping）

**原理**：Cache被分为若干组（set），每个组包含$r$个块（称为$r$路组相联）。主存块映射到**固定的组**，但组内可以放在**任意一个块**中。

**主存地址格式**：

```
|  标记（Tag）  |  组号（Set Index）  |  块内地址（Offset）  |
```

**映射关系**：`Cache组号 = 主存块号 mod Cache总组数`

**特点**：直接映射和全相联映射的折中——既有一定灵活性，又控制了比较开销。

### 5.3. Cache地址格式例题

**例**（来自你的笔记）：设主存容量为512KB，Cache容量为4KB，每个字块16个字，每个字32位，存储器按字节寻址。

**(1) Cache地址有多少位？可容纳多少块？**

**解**：
- Cache容量 = 4KB = $2^{12}$B → 地址位数 = 12位
- 字块大小 = 16字 × 32位/字 = 16×4B = 64B
- Cache块数 = 4KB / 64B = 64块

**(2) 主存地址有多少位？可容纳多少块？**

**解**：
- 主存容量 = 512KB = $2^{19}$B → 地址位数 = 19位
- 主存块数 = 512KB / 64B = 8192块

**(3) 直接映射下主存地址格式**：
- 块内地址 = $\log_2(64)$ = 6位
- Cache块号 = $\log_2(64)$ = 6位
- 标记 = 19 - 6 - 6 = 7位

```
| 标记(7) | Cache块号(6) | 块内地址(6) |
```

**(4) 四路组相联下主存地址格式**：
- 块内地址 = $\log_2(64)$ = 6位
- 组数 = 64块 / 4路 = 16组，组号 = $\log_2(16)$ = 4位
- 标记 = 19 - 4 - 6 = 9位

```
| 标记(9) | 组号(4) | 块内地址(6) |
```

**(5) 全相联下主存地址格式**：
- 无Cache块号/组号字段
- 标记 = 19 - 6 = 13位

```
| 标记(13) | 块内地址(6) |
```

### 5.4. 三种映射方式对比

| 对比项 | 直接映射 | 全相联映射 | 组相联映射 |
|:------|:--------:|:---------:|:----------:|
| 映射灵活性 | 最低（固定位置） | 最高（任意位置） | 中等（组内任意） |
| 查找方式 | 直接索引 | 比较所有标记 | 索引组号+比较组内标记 |
| 比较器数量 | 1个 | Cache块数个 | 组内路数个 |
| 硬件复杂度 | 低 | **高** | 中等 |
| 冲突率 | 高 | 低 | 中（随路数增加而降低） |
| 典型应用 | 简单Cache | 小容量Cache（TLB） | **最常用**（2/4/8路） |

### 5.5. Cache命中率与平均访问时间

**命中率**：CPU访问Cache时命中（找到所需数据）的概率。

**Cache-主存系统的平均访问时间**：

$$
t_a = H \times t_c + (1-H) \times t_m
$$

其中：
- $H$ = Cache命中率
- $t_c$ = Cache存取周期
- $t_m$ = 主存存取周期

**例题**（来自你的笔记例4.29）：Cache命中4800次，访问主存200次，已知Cache存取周期30ns，主存存取周期150ns，求Cache命中率、平均访问时间和效率。

**解**：
- 总访问次数 = 4800 + 200 = 5000
- 命中率 $H = 4800/5000 = 0.96 = 96\%$
- 平均访问时间 $t_a = 0.96 \times 30 + 0.04 \times 150 = 28.8 + 6 = 34.8\text{ns}$
- 效率 $e = t_c / t_a = 30/34.8 \approx 86.2\%$
- 性能提升倍数 = $t_m / t_a = 150/34.8 \approx 4.31$倍

### 5.6. Cache的替换算法

当Cache已满且需要调入新块时，需要替换Cache中的某个块：

| 算法 | 说明 | 特点 |
|:----|:-----|:-----|
| **随机替换**（Random） | 随机选择一个块替换 | 实现简单，但效果不稳定 |
| **先进先出**（FIFO） | 替换最早调入的块 | 可能把频繁使用的块也替换掉 |
| **近期最少使用**（LRU） | 替换最长时间未被访问的块 | **效果最好**，硬件实现较复杂 |

> LRU是实际Cache中最常用的替换算法——利用局部性原理：过去未被访问的块，将来也不大可能被访问。

### 5.7. Cache的写策略

由于Cache中保留的是主存中数据的副本，当CPU修改了Cache中的数据时，必须确保主存中的数据也保持一致性：

| 写策略 | 操作方式 | 特点 |
|:-------|:---------|:-----|
| **写直达法**（write-through） | 每次写Cache时，**同时写入主存** | 主存始终为最新，但写操作慢 |
| **写回法**（write-back） | 每次只写Cache，当Cache块被替换时才写回主存 | 写操作快，但主存可能不是最新 |

> **自己的话**：写直达法像一手交钱一手交货——每次一手交（写Cache），一手也交给仓库（写主存），安全但费时。写回法像记账——先记在本子上（写Cache），到月底了再一次性结清（替换时写主存），效率高但要注意账本丢失。

### 5.8. 现代Cache结构（补充）

现代处理器通常采用**多级Cache**：

```
CPU → L1 Cache（几十KB，1~2个时钟周期，与CPU同频）
    → L2 Cache（几百KB，~10个时钟周期）
    → L3 Cache（几MB，~40个时钟周期，多核共享）
    → 主存（DDR）
```

- **L1 Cache**：通常分为指令Cache（L1i）和数据Cache（L1d）——哈佛结构
- **L2/L3 Cache**：统一Cache（指令和数据共用）

## 6. 汉明码（Hamming Code）

### 6.1. 基本原理

汉明码是**一种能够检测并自动纠正一位错误**的纠错码。

**检测位位置**：检测位（校验位）位于 $2^{i-1}$ 位置（$i=1,2,3,...$），即第1、2、4、8…位。

**检测位个数**：对于信息位长度为 $k$ 的编码，需添加的检测位位数 $r$ 应满足：

$$
2^r \geq k + r + 1
$$

### 6.2. 汉明码配置（以配偶原则为例）

**检测位的取值规则**（偶校验）：每个检测位负责检测一组特定的数据位，使该组中"1"的个数为偶数。

以7位汉明码（4数据位+3检测位）为例，位号分配：

```
位号： 7  6  5  4  3  2  1
      D3 D2 D1 C2 D0 C1 C0
```

各检测位负责的数据位：
- $C_1$（位1）：检测位号中包含"1"的位 → 1, 3, 5, 7
- $C_2$（位2）：检测位号中包含"2"的位 → 2, 3, 6, 7
- $C_3$（位4）：检测位号中包含"4"的位 → 4, 5, 6, 7

### 6.3. 检测与纠错过程

**检测**：接收端按相同的分组重新计算各检测位的值，与收到的检测位比较——得到**指误字**（syndrome）。

**纠错**：将指误字转换为十进制数，指出出错位置，取反即可纠正。

**例题**（来自你的笔记例4.4）：已知接收到的汉明码为0110101（按配偶原则配置），试问欲传送的信息是什么？

**解**：

收到的7位汉明码：`0 1 1 0 1 0 1`
位号：7654321

计算各检测组：

$$
P_1 = \text{位1} \oplus \text{位3} \oplus \text{位5} \oplus \text{位7} = 1 \oplus 0 \oplus 1 \oplus 1 = 1 \\
P_2 = \text{位2} \oplus \text{位3} \oplus \text{位6} \oplus \text{位7} = 0 \oplus 0 \oplus 1 \oplus 1 = 0 \\
P_3 = \text{位4} \oplus \text{位5} \oplus \text{位6} \oplus \text{位7} = 0 \oplus 1 \oplus 1 \oplus 1 = 1
$$

指误字 = $P_3P_2P_1$ = 101（二进制）= **5**（十进制）

**第5位出错！** 将第5位取反：原来的"1"变为"0"。

纠正后的代码：`0 1 0 0 1 0 1`

取出数据位（位3、5、6、7）：`0 1 0 1`

**欲传送的信息为 0101。**

### 6.4. 提高访存速度的措施

1. **采用高速器件**——使用存取周期短的芯片
2. **采用Cache**——CPU最近要使用的信息先调入Cache，缩短访存时间
3. **调整主存结构**——如采用**单体多字**或**多体结构存储器**
4. **多体交叉编址**——多个存储体轮流编址，可并行访问

## 7. 虚拟存储器与TLB（补充）

### 7.1. 为什么要虚拟存储器

虚拟存储器（virtual memory）解决两个问题：
1. **程序大小超过主存容量**——只将当前需要的部分调入主存
2. **多道程序隔离**——每个程序看到独立的地址空间

### 7.2. 基本概念

| 概念 | 定义 |
|:----|:-----|
| **虚拟地址**（VA, Virtual Address） | 程序使用的地址，也称逻辑地址 |
| **物理地址**（PA, Physical Address） | 实际访问主存的地址 |
| **地址转换** | 将虚拟地址转换为物理地址的过程 |
| **页**（page） | 虚拟地址空间和物理地址空间均划分为固定大小的块（通常4KB） |
| **页表**（page table） | 记录虚拟页到物理页的映射关系 |

> **通俗理解**：虚拟存储器就像一个"图书馆代借服务"——你（程序）只要告诉管理员（MMU，内存管理单元）想要哪本书（虚拟地址），管理员去书库（主存+磁盘）找到书，把书送到前台给你读。如果书暂时在书库的阁楼（磁盘），管理员会先去阁楼搬出来放到书架上（换入主存），再拿给你。你完全不需要关心书在书架的哪一层。

### 7.3. 地址转换过程（简化）

```
程序给出虚拟地址
    ↓
MMU将虚拟地址分为 虚拟页号 + 页内偏移
    ↓
MMU查找页表（页表存放在主存中）
    ├── 命中（页在主存中）→ 得到物理页号 + 页内偏移 → 物理地址
    └── 缺页（页不在主存中）→ **缺页中断** → OS从磁盘调入该页到主存 → 更新页表 → 重新执行
```

### 7.4. TLB（快表）

由于页表存放在主存中，每次地址转换都要访问一次主存（读取页表项），这将显著降低性能。

**TLB**（Translation Lookaside Buffer，快表/转译后备缓冲器）是位于CPU内部的一个**小容量、高速度**的Cache，专门用于缓存近期使用过的页表项。

```
CPU发虚拟地址
    ↓
MMU先查询TLB
    ├── TLB命中 → 快速获得物理地址（1个时钟周期）
    └── TLB不命中 → 访问主存中的页表 → 更新TLB
```

> **自己的话**：TLB就像管理员随身携带的"热门图书速查表"——大部分时候你要的书都在这个速查表上，一翻就知道位置。偶尔遇到不在表上的书，才需要去查总目录（主存中的页表）。

### 7.5. 存储保护

现代操作系统通过虚拟存储器机制实现存储保护：

| 保护机制 | 说明 |
|:---------|:-----|
| **特权级**（ring 0 ~ ring 3） | 内核运行在最高特权级（ring 0），用户程序运行在最低级（ring 3） |
| **页级保护** | 每页可设置读/写/执行权限 |
| **地址空间隔离** | 每个进程有独立的页表，不能访问其他进程的地址空间 |

## 习题3：存储系统

### 3.1 概念题

1. **解释概念：RAM、SRAM、DRAM、ROM、PROM、EPROM、EEPROM、CDROM、Flash Memory。**

> **答**：RAM=随机存取存储器（可读可写，易失）；SRAM=静态RAM（6管触发器，快但贵，用作Cache）；DRAM=动态RAM（电容存储，需要刷新，用作主存）；ROM=掩膜只读存储器（出厂写入）；PROM=可编程一次ROM；EPROM=紫外线擦除PROM；EEPROM=电擦写PROM；CDROM=只读光盘；Flash Memory=闪速存储器（块擦写非易失，主流存储技术）。

2. **什么是主存？什么是辅存？Cache的作用是什么？**

> **答**：**主存**（主存储器）用于存放正在执行的程序和数据，CPU可直接随机读写，访问速度较高。**辅存**（辅助存储器）用于存放当前暂不执行的程序和数据及需永久保存的信息。**Cache**（高速缓冲存储器）介于CPU和主存之间，用于解决CPU和主存之间的速度不匹配问题。

3. **存储器的层次结构主要体现在什么地方？为什么要分这些层次？计算机如何管理这些层次？**

> **答**：主要体现在**Cache-主存**和**主存-辅存**两个层次。Cache-主存层次从CPU角度加速访存（速度≈Cache，容量≈主存）；主存-辅存层次从程序员角度扩容（容量≈辅存，速度≈主存）。Cache-主存由**硬件**自动管理，主存-辅存由**操作系统**（硬件辅助）管理。

4. **说明存取周期和存取时间的区别。**

> **答**：**存取时间**仅为完成一次操作的时间；**存取周期**不仅包含操作时间，还包含操作后线路的**恢复时间**。即：存取周期 = 存取时间 + 恢复时间。

5. **计算机中设置Cache的作用是什么？能不能把Cache容量扩大、最后取代主存，为什么？**

> **答**：Cache解决CPU与主存速度不匹配问题。**不能**取代主存，原因：(1) Cache容量越大成本越高；(2) 若取消主存，Cache不命中时需从辅存调入，导致CPU等待时间太长。

6. **什么是程序访问的局部性？存储系统中哪一级采用了程序访问的局部性原理？**

> **答**：程序访问的局部性指程序执行时对存储器的访问在地址上相对**簇生**而非随机分布。Cache-主存级和主存-辅存级都用到了局部性原理——将近期访问过的信息放在较快的一级中。

### 3.2 计算题

7. **汉明码纠错**：已知接收到的汉明码为1100000（按偶性配置），试问欲传送的信息是什么？

> **解**：7位汉明码，位7654321=1100000。计算各检测组：$P_1=1\oplus0\oplus0\oplus0=1$，$P_2=1\oplus0\oplus0\oplus0=1$，$P_3=0\oplus0\oplus0\oplus0=0$。指误字=$011_2=3$，第3位出错。纠正为1110000。数据位（3、5、6、7）=1000。**信息为1000**。

8. **例4.28**：设主存容量256K字，Cache容量2K字，块长为4（主存和Cache之间的数据交换以块为单位）。设计Cache地址格式和三种映射方式下主存地址格式。

> **解**：块内地址=$\log_2 4=2$位。Cache块数=$2K/4=2^9$块。主存块数=$256K/4=2^{16}$块。
> - **直接映射**：标记(16-9-2=5) + Cache块号(9) + 块内(2)
> - **全相联**：标记(16-2=14) + 块内(2)
> - **四路组相联**：组数=$2^9/4=2^7$，组号(7)，标记(16-7-2=7)

### 3.3 设计题

9. **CPU与存储器连接**：CPU有16根地址线、8根数据线，MREQ（低电平有效）作访存控制信号，WR作读/写信号（高读低写）。选用适当芯片，要求最小4K地址为系统程序区（ROM），4K~16K为用户程序区（RAM）。

> **答**：ROM区=0000H~0FFFH（4k×8位ROM×1片），RAM区=1000H~3FFFH（共12k，可用1k×8位RAM（2片位扩）×3组或其他方案）。具体连接图需用74138译码器根据高位地址产生片选信号。

## 本讲核心要点

1. **存储器层次结构充分利用了程序访问的局部性**——Cache-主存级加速，主存-辅存级扩容
2. **SRAM vs DRAM**：SRAM（6管触发器，快但贵，用作Cache）vs DRAM（1T1C电容存储，需刷新，用作主存）
3. **ROM五大类型**：掩膜ROM→PROM→EPROM→EEPROM→Flash（块擦写非易失）
4. **存储芯片扩展**：位扩展（增加字长）、字扩展（增加字数）、字位同时扩展——用译码器管理片选
5. **Cache三种映射方式**：直接映射（固定位置，冲突率高）、全相联（任意位置，比较器多）、组相联（折中，最常用）
6. **Cache地址格式**：直接映射=标记+Cache块号+块内地址；组相联=标记+组号+块内地址；全相联=标记+块内地址
7. **Cache的替换和写策略**：LRU最常用；写回法（write-back）效率高，写直达法（write-through）安全性高
8. **汉明码可纠正一位错**：检测位在$2^{i-1}$位置，通过指误字定位出错位
9. **虚拟存储器**通过页表和缺页中断实现大地址空间，TLB加速地址转换
10. **提高访存速度三种措施**：高速器件、Cache、调整主存结构（多体交叉）
