## 1. I/O系统概述

### 1.1. I/O接口的功能

I/O接口（I/O interface）是CPU与外部设备之间的"桥梁"，其核心功能是解决CPU与外设在**速度、信号电平、数据格式、时序**上的差异。

| 功能 | 说明 |
|:----|:------|
| **地址译码** | 识别CPU发来的I/O地址，选择对应的外设 |
| **数据缓冲** | 在CPU和I/O设备之间暂存数据，匹配速度差异 |
| **信号转换** | 电平转换、串/并转换、模/数转换等 |
| **提供状态信息** | 向CPU报告设备的状态（忙/就绪/错误） |
| **传送控制命令** | 接收CPU发来的命令（启动/停止/读/写） |
| **时序控制** | 协调CPU与外设的时间配合 |

### 1.2. I/O接口的组成

一个典型的I/O接口内部包含：

| 组成部分 | 作用 |
|:--------|:-----|
| **数据缓冲寄存器** | 暂存CPU和外设之间交换的数据 |
| **状态寄存器** | 存放设备状态（如就绪/忙） |
| **控制寄存器** | 存放CPU发来的控制命令 |
| **地址译码器** | 识别I/O地址 |
| **数据总线和控制总线连接** | 与系统总线连接 |

### 1.3. I/O编址方式

| 编址方式 | 说明 | 特点 |
|:--------|:-----|:------|
| **统一编址**（memory-mapped I/O） | I/O端口和主存单元在同一地址空间中统一编址 | 可用访存指令操作I/O，无需专用I/O指令，但占用主存地址空间 |
| **独立编址**（isolated I/O） | I/O端口单独编址，与主存地址空间分开 | 需专用I/O指令（如IN/OUT），不占用主存地址，但需要额外的控制线 |

## 2. 三种数据传送控制方式

CPU控制I/O设备进行数据传送的方式有三种，从"CPU全程参与"到"CPU较少干预"，效率逐步提高。

### 2.1. 程序查询方式（轮询）

**工作原理**：CPU不断地查询I/O设备的状态寄存器，确认设备"就绪"后才进行数据传送。

```
CPU → 发出查询命令 → 读取设备状态
    ├── 未就绪 → 继续查询（CPU等待）
    └── 就绪 → 进行数据传送
```

**特点**：
- **优点**：控制简单，硬件实现容易
- **缺点**：CPU需要不断轮询，**浪费大量CPU时间**——在等待外设时CPU不能做其他工作
- 适用于：低速设备或CPU负担不重的场合

### 2.2. 中断方式

**原理**：当I/O设备准备好数据时，主动向CPU发出**中断请求**（interrupt request），CPU暂停当前程序，转去处理数据传送，处理完后再返回原程序。

**优点**：
- CPU不需要轮询等待，提高了CPU利用率
- 能处理突发事件（如电源掉电、硬件故障）

**缺点**：
- 每次中断都需要保护现场和恢复现场，有一定开销
- 不适合高速大批量的数据传送

### 2.3. DMA方式

**DMA**（Direct Memory Access，直接存储器访问）方式让I/O设备与主存之间直接传送数据，**不需要CPU的干预**，由专门的硬件——**DMA控制器**（DMAC）管理。

**工作原理**：

```
CPU → 向DMAC发命令（数据起始地址、长度、方向）
    ↓
CPU继续执行其他程序
    ↓
DMAC控制数据在 I/O设备 ↔ 主存 之间直接传送
    ↓
传送完成后，DMAC向CPU发中断信号（报告完成）
```

> **通俗理解**：程序查询方式像"你去超市买东西，每买一件就给老板打个电话问能不能拿"；中断方式像"你跟老板说好，东西到了让老板打电话通知你"；DMA方式像"你让一个助手（DMAC）专门负责收货，货到了直接搬进仓库（主存），完事再告诉你一声"。

**DMA与中断方式的主要区别**（来自你的笔记）：

| 对比项 | 中断方式 | DMA方式 |
|:------|:--------|:--------|
| **数据传送** | 靠**程序**传送（CPU执行指令） | 靠**硬件**传送（DMAC控制） |
| **CPU响应时间** | 在一条指令执行**结束时**响应 | 可在指令周期内**任一存取周期结束时**响应 |
| **异常事件处理** | 有处理能力 | 无，主要用于大批数据传送 |
| **保护现场** | 需要保护/恢复现场 | 不中断现行程序，无需保护现场 |
| **优先级** | 较低 | **比中断优先级高** |
| **典型应用** | 键盘、鼠标、打印机 | 硬盘、显卡、高速数据采集 |

### 2.4. 三种方式对比总表

| 方式 | CPU参与程度 | 速度 | 适用场景 |
|:----|:----------:|:---:|:---------|
| **程序查询** | 全程参与（轮询等待） | 最低 | 低速简单设备 |
| **中断** | 启动和结束时参与 | 中等 | 中速设备（键盘/鼠标/打印机） |
| **DMA** | 仅启动和结束时参与 | **最高** | 高速批量数据（磁盘/显卡） |

## 3. DMA控制器

### 3.1. DMA控制器的功能

| 功能 | 说明 |
|:----|:------|
| ① 向CPU申请总线控制权 | 当DMA准备传送时，通过HRQ（Hold Request）信号向CPU申请总线 |
| ② 接管总线控制权 | CPU响应后HLDA信号有效，DMAC获得总线控制权 |
| ③ 管理地址和长度 | 自动产生主存地址、计数传送字节数 |
| ④ 发读写命令 | 向主存和I/O设备发送读写控制信号 |
| ⑤ 传送结束处理 | 数据块传送结束时，向CPU发中断信号 |

### 3.2. DMA控制器的组成

| 部件 | 作用 |
|:----|:------|
| **AR（地址寄存器）** | 存储要访问的主存地址 |
| **WC（字计数器）** | 记录还需传送的字节数 |
| **控制/状态逻辑** | 管理DMA传送的控制信号和状态 |
| **数据缓冲** | 暂存数据 |

### 3.3. DMA的三种传送方式

| 方式 | 说明 |
|:----|:------|
| **周期挪用**（cycle stealing） | DMAC在CPU不访问总线时插入一个存取周期进行数据传送，不影响CPU程序 |
| **成组传送**（burst transfer） | DMAC获得总线控制权后连续传送一整块数据，传送完才释放总线 |
| **透明DMA** | DMAC仅在CPU不使用总线时（如执行内部运算）传送，对CPU完全透明 |

## 4. 中断系统

### 4.1. 中断的概念

**中断**（interrupt）：CPU在程序运行过程中，遇到异常情况或特殊请求，需**暂停现行程序**，转至对这些异常情况或特殊请求的处理，处理完后再**返回到原程序断点处**继续执行。

### 4.2. 设计中断系统需考虑的主要问题

1. 中断源如何向CPU提出请求
2. 当多个中断源同时提出请求时，CPU如何确定响应的优先次序
3. CPU在什么情况（时间、条件）下响应中断
4. 如何保护现场
5. 如何寻找中断服务程序的入口地址
6. 如何恢复现场
7. 当出现中断嵌套时如何处理

### 4.3. 中断系统中的关键触发器

| 触发器 | 全称 | 作用 |
|:-------|:-----|:------|
| **INTR** | 中断请求触发器（Interrupt Request） | 每个中断源对应一个，=1表示该中断源有请求 |
| **EINT** | 允许中断触发器（Enable Interrupt） | =1时CPU允许响应中断（开中断），=0时禁止响应（关中断）——**中断总开关** |
| **MASK** | 中断屏蔽触发器（Mask） | =1时该中断源的请求被屏蔽（分开关） |
| **INT** | 中断标记触发器（Interrupt） | =1时表示CPU已进入中断周期 |

**中断请求被响应的条件**：
- 设备状态为"完成"（D=1）
- 该中断未被屏蔽（MASK=0）
- CPU允许中断（EINT=1）
- 该中断源经排队被选中

### 4.4. 中断响应的条件与时机

**条件**：
- EINT = 1（开中断）
- 中断源有请求且未被屏蔽
- 经排队被选中

**时机**：在**每条指令执行周期结束时刻**，CPU向各中断源发查询信号。

### 4.5. 中断隐指令

**中断隐指令**（implicit interrupt instruction）是指令系统中**没有的指令**，由CPU在中断响应周期**自动完成**。

**三个功能**：
1. **保护程序断点**（将当前PC值压栈或保存到特殊寄存器）
2. **硬件关中断**（将EINT置0，禁止在中断响应期间再响应新的中断）
3. **将中断服务程序入口地址送PC**（硬件向量法/软件查询法）

### 4.6. 中断管理硬件

计算机管理中断所需的硬件（来自你的笔记）：

| 硬件 | 作用 |
|:----|:------|
| **中断请求触发器**（每个中断源一个） | 标志某个中断源向CPU提出中断请求 |
| **中断屏蔽触发器**（每个中断源一个） | =1时该中断请求被屏蔽，CPU不能响应 |
| **排队器** | 进行中断判优，选中优先级最高的中断 |
| **向量地址形成部件** | 产生中断源的向量地址→找到中断服务程序入口 |
| **允许中断触发器（EINT）** | =1时CPU允许处理中断 |
| **中断标志触发器（INT）** | 标志系统进入中断周期 |
| **堆栈** | 保护现场（断点地址和寄存器内容） |
| **中断查询信号电路** | 每条指令周期结束时刻发查询信号 |

**指令系统的支持**：应有**开中断**、**关中断**、**置屏蔽字**及**中断返回**等指令。

### 4.7. 中断判优

CPU在某一时刻只能响应一个中断源的请求。当多个中断源同时提供请求时，中断系统必须按其优先顺序予以响应——这称为**中断判优**。

**判优方式**：

| 方式 | 实现 | 特点 |
|:----|:-----|:------|
| **硬件排队** | 组合逻辑电路 | 速度快，优先级固定 |
| **软件排队** | 程序按优先级顺序查询 | 灵活但速度慢 |

**改变优先级的方法**：采用**屏蔽技术**，重新设置屏蔽字——封锁级别高的请求源，开放级别低的请求。

### 4.8. 中断响应优先级 vs 处理优先级

优先级包含两个不同概念（来自你的笔记）：

| 类型 | 定义 | 特点 |
|:----|:-----|:------|
| **响应优先级** | CPU响应各中断源请求的优先**次序** | 硬件线路已设好，一般不便于改动 |
| **处理优先级** | CPU实际对各中断源请求的处理**次序** | 可通过**屏蔽字**改变 |

如果不采用屏蔽技术，响应的优先次序就是处理的优先次序。

### 4.9. 中断处理流程

完整的中断处理过程：

```
① 中断源发出中断请求（INTR=1）
② CPU当前指令执行完毕，查询中断信号
③ 中断判优（排队器选中最高优先级的请求）
④ CPU进入中断周期（INT=1）
    中断隐指令自动完成：保护断点 + 关中断 + 送入口地址
⑤ 进入中断服务程序
    → 保护现场（保存通用寄存器+状态寄存器，用PUSH指令）
    → 开中断（EINT=1，允许更高级中断中断当前服务——中断嵌套）
    → 执行中断服务程序主体（数据传送等）
    → 关中断（EINT=0）
    → 恢复现场（POP指令）
    → 开中断
    → 中断返回（IRET指令，恢复断点PC）
```

### 4.10. 中断嵌套

当CPU正在执行中断服务程序时，如果有**优先级更高的中断源**发出请求，当前中断被暂时挂起，CPU转去响应更高优先级的中断。这种"中断中再中断"的现象就是**中断嵌套**。

**例题**（来自你的笔记）：优先级按1→2→3→4降序排列，现要求中断处理次序改为4→1→3→2。根据四个中断源的请求时刻，画出CPU执行程序的轨迹。

> **解**：通过设置屏蔽字，使优先级高的中断源在处理时开放比它更重要的中断。处理次序为4→1→3→2，则屏蔽字设置如下：
> - 中断源4处理时：屏蔽所有
> - 中断源1处理时：只开放4
> - 中断源3处理时：开放4和1
> - 中断源2处理时：开放4、1和3

## 5. 异常与中断的分类（补充）

在现代计算机体系结构中，"中断"（interrupt）和"异常"（exception）是两个不同但相关的概念。

### 5.1. 异常与中断的区别

| 对比项 | 异常（Exception） | 中断（Interrupt） |
|:------|:----------------|:-----------------|
| **来源** | **CPU内部**（指令执行时产生） | **CPU外部**（I/O设备等外部事件） |
| **产生时机** | 指令执行过程中检测到 | 指令执行结束后检测 |
| **是否同步** | **同步**（与指令执行相关） | **异步**（与指令执行无关） |
| **是否可屏蔽** | 通常不可屏蔽 | 部分可屏蔽（如关中断） |
| **例子** | 除零、缺页、非法指令 | 键盘按下、硬盘准备好 |

### 5.2. 异常的分类

| 异常类型 | 英文 | 定义 | 例子 | 处理后的恢复点 |
|:---------|:-----|:-----|:-----|:--------------|
| **故障** | Fault | 指令执行过程中检测到异常，可修复后**重新执行当前指令** | 缺页异常（page fault）、除零 | 当前指令（重新执行） |
| **自陷** | Trap | 有意安排的异常（通过特殊指令触发），用于系统调用 | syscall、int 0x80 | **下一条**指令 |
| **终止** | Abort | 硬件严重错误，无法恢复 | 内存校验错、总线错误 | 无法恢复，终止进程 |

> **通俗理解**：
> - **Fault**（故障）：你正在做饭，发现没盐了（缺页）——你停下来去买了盐（调入页面），然后**重新继续做这道菜**（重新执行当前指令）。
> - **Trap**（自陷）：你主动打内线电话给前台（系统调用）——前台帮了你之后，你**继续做下一道菜**。
> - **Abort**（终止）：厨房着火了（严重硬件错误）——什么都做不了，必须撤离。

## 习题4：输入输出系统

### 4.1 概念题

1. **什么是I/O接口？它有哪些功能？**

> **答**：I/O接口是CPU与外部设备之间的连接部件，功能包括地址译码、数据缓冲、信号转换、提供状态信息、传送控制命令、时序控制等。

2. **I/O编址方式有哪几种？各有何特点？**

> **答**：统一编址（memory-mapped I/O）和独立编址（isolated I/O）。统一编址用访存指令操作I/O，简单但占用主存地址空间；独立编址需专用I/O指令，不占主存地址空间，但需要额外控制线。

3. **什么是中断？设计中断系统需考虑哪些主要问题？**

> **答**：中断是CPU暂停现行程序转去处理异常或特殊请求的过程。需考虑：中断源如何提出请求、如何判优、CPU何时响应、如何保护/恢复现场、如何找入口地址、如何处理嵌套等7个问题。

4. **在中断系统中，INTR、INT、EINT三个触发器各有何作用？**

> **答**：INTR=中断请求触发器（标志中断源有请求）；EINT=允许中断触发器（中断总开关，1=允许）；INT=中断标记触发器（标志CPU进入中断周期）。

5. **中断响应的条件是什么？在什么时间响应？**

> **答**：条件：EINT=1、设备有请求且未被屏蔽、经排队被选中。时间：每条指令执行周期结束时刻。

6. **什么是中断隐指令？有哪些功能？**

> **答**：中断隐指令是指令系统中没有的指令，由CPU在中断响应周期自动完成。三个功能：保护程序断点、硬件关中断、将中断服务程序入口地址送PC。

7. **计算机为管理中断需设置哪些硬件？指令系统需提供哪些指令？**

> **答**：硬件：中断请求触发器、中断屏蔽触发器、排队器、向量地址形成部件、EINT、INT、堆栈、查询信号电路。指令：开中断、关中断、置屏蔽字、中断返回。

8. **中断判优有几种实现方法？若想改变原定的优先顺序，可采取什么措施？**

> **答**：两种——硬件排队（组合逻辑电路）和软件排队（程序查询）。欲改变优先顺序，可用**屏蔽技术**重新设置屏蔽字。

9. **简述中断处理过程中"保护现场"需要完成哪些任务？如何实现？**

> **答**：保护现场包括：(1) 保存程序断点（PC值）——由中断隐指令完成；(2) 保存通用寄存器及状态寄存器内容——在中断服务程序中用PUSH等机器指令编程完成。

### 4.2 简答题

10. **试比较程序查询、中断方式和DMA方式。**

> **答**：程序查询——CPU不断轮询设备状态，浪费CPU时间但控制简单；中断方式——设备主动通知CPU，提高CPU利用率但需保护现场；DMA方式——专用硬件DMAC控制数据直接在主存和I/O之间传送，不中断CPU程序，速度最快。DMA适用于高速批量数据传送，优先级高于中断。

11. **什么是响应优先级和处理优先级？有什么区别？**

> **答**：响应优先级是CPU响应各中断的硬件固定次序；处理优先级是CPU实际处理各中断的次序。不使用屏蔽时二者一致；使用屏蔽字可以改变处理优先级。

### 4.3 综合题

12. **已知优先级1>2>3>4降序排列，要求中断处理次序改为4→1→3→2，设计屏蔽字。**

> **答**：处理次序4→1→3→2意味着：处理4时屏蔽所有；处理1时只开放4；处理3时开放4和1；处理2时开放4、1和3。屏蔽字矩阵略（具体见笔记中例题）。

## 本讲核心要点

1. **I/O接口的六大功能**：地址译码、数据缓冲、信号转换、提供状态、传送命令、时序控制
2. **两种编址方式**：统一编址（memory-mapped，用访存指令）和独立编址（专用I/O指令，不占地址空间）
3. **三种数据传送方式**：程序查询（CPU轮询，简单低效）→ 中断（设备通知CPU，效率较高）→ DMA（硬件控制，最高效）
4. **DMA三大特点**：硬件传送、不中断现行程序、指令周期任一存取周期结束时响应
5. **中断三触发器**：INTR（请求）、EINT（总开关=CPU允许中断）、INT（标志位=已进入中断周期）
6. **中断响应三条件**：EINT=1、设备有请求且未被屏蔽、排队被选中
7. **中断隐指令三功能**：保护断点、硬件关中断、送入口地址至PC
8. **响应优先级 vs 处理优先级**：响应优先级硬件固定，处理优先级可通过**屏蔽字**改变
9. **异常三类**：Fault（可恢复，重新执行当前指令）、Trap（主动触发，执行下一条）、Abort（严重错误，无法恢复）
10. **中断嵌套**：在处理低优先级中断时，若更高优先级中断到达，可暂时挂起当前服务
